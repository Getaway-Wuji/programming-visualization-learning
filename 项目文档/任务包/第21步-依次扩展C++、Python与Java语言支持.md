## 本步骤目标

按顺序为 C++、Python、Java 建立受支持教学子集内的课程、练习、积木、代码工作台、真实执行与可视化复盘闭环，复用统一 Step DSL 和本地学习体系。每种语言必须通过本语言的门槛，再实施下一种语言。

“语言支持”按公布的教学子集验收，不承诺全部标准语法、任意标准库或任意第三方库。18.6的静态语法对照、语言下拉选项和示例文本均不能替代真实执行。

已有 C 课程和七个 C 案例继续使用 C。此后新增的算法可视化以 C++ 为基准，复杂算法只提供 C++ 版，不要求为 Python、Java 复制这些算法。各语言入门课程仍使用对应语言的语法示例与练习；不得用 C++ 程序的结果冒充 Python、Java 执行。

## 数量、语法与预算建议基线

以下为便于实施的规划建议，**不是用户指定数量，也不是本次已冻结的产品支持矩阵**。21.1须在实现前固定各语言的具体清单、版本、数值与理由；后续调整留痕并同步验收范围。

| 维度 | 建议基线与须冻结事项 |
|---|---|
| 各语言入门规模 | 每种语言至少3章、6小节、6道可判定练习，每题至少4组测试；覆盖正常、边界和常见错误，不以目录或重复换皮凑数量 |
| 共同教学主题 | 变量与输入输出、表达式与条件、循环、数组或序列、函数及综合练习；按语言特点组织，不把 C 语义强加给其他语言 |
| 语法支持矩阵 | 固定语言/方言版本、语法与库白名单、输入输出、类型/数值/溢出、作用域、字符串/索引、容器/引用/对象及错误语义；逐项给支持正例与拒绝反例 |
| 积木范围 | 至少覆盖该语言入门必需题；生成、反推和定位的范围分别登记，双向映射范围不得大于解释器范围；未映射源码保留原文并明确状态 |
| 资源预算 | 每语言固定代码/输入、语法深度、步数、栈深、虚拟对象与内存、输出、轨迹、Worker总内存及总耗时上限；组合运行另列预算 |
| 验收条件 | 固定设备、浏览器、生产构建、冷暖加载、输入规模和计时口径；沿原性能目标与已登记例外边界，不自动继承旧语言的实测结论或放宽原 C 预算 |
| 学习与兼容 | 课程、题目、语言及版本关系明确；语言间进度/草稿/解锁不串用，积分仍由统一幂等账本更新；新语言安装或切换不重算旧 C 学习历史 |

### 21.1 多语言范围、契约、数量与预算决议

**前置任务**：20.4。

**要做的事**：盘点12/17已验收的 C++ 算法执行子集与全部旧 C 能力，冻结三种语言本步骤的教学范围、上述数量及资源预算。分别确定语言版本、语法/库白名单和语言特有语义：C++的类型、引用与生命周期，Python的动态类型、整数/除法与序列行为，Java的数值、对象/数组引用与入口形式。未纳入者显式列为不支持，不以 C 的运算规则代替。

规划并登记 CONTENT、EXEC、STEP、DIAG、JUDGE、EDIT/积木、LEARN、SAVE及导出受影响字段和兼容组合。语言、方言/子集、源码版本、引擎版本与运行身份须可核对；统一 Step DSL 允许按登记扩展，但不能给每种语言另建互不兼容的播放器。规定切语言后的草稿保存/恢复、旧运行失效、断点映射、未知语言/版本拒绝和失败恢复规则。

**交付物**：三语言支持矩阵、课程/练习/积木清单、预算与验收决议、变更影响及兼容/迁移/回滚方案、正常与拒绝样例。只冻结范围及契约设计，不冒称实现已通过。

**验收条件**：每个承诺能力对应后续任务和可检查样例；三语言顺序及门槛明确；旧 C 与最小 C++ 算法子集的复用边界清楚；数量和预算在产品实现前有具体数值；共享变更的唯一负责人及新旧版本处置齐备。若无新增存档字段，也须明确兼容证据和不迁移理由。
