## 本步骤目标

在开工前统一一期边界、运行形态、教学子集和交付规模。

## 开工条件与文件归属

- 前置：无；本步骤先完成，再进入产品实现。
- 建议修改范围：项目文档/架构决策/、项目文档/契约/中的初始清单；不创建产品源码。
- 范围之外：不搭建工程、不安装产品依赖、不制作页面。
- 路径是未来工程建议，03.1 确认后以实际目录为准。每个子任务领取时进一步登记具体文件，不能把父步骤目录视为独占整模块的许可。
- 公共契约、根配置、路由、依赖/锁文件、本地模型、中央进度由指定负责人维护；本窗口通过独立交接提交共享修改。

## 子任务

### 01.1 建立需求基线与用户路径

**前置任务**：无。

**要做的事**：逐条核对原说明；确认第六章优先级为排期基准；定义初学者与课堂演示两条路径，确定小节和练习的完成判定。

**交付物**：一期范围清单、页面清单、需求差异记录。

**验收条件**：每项一期交付均有任务编号；账号、云存档、排行榜、多人房间无实现任务；冲突有明确默认。

### 01.2 确定执行位置与数据流

**前置任务**：01.1。

**要做的事**：区分本地保存、临时传输和离线运行；推荐先以浏览器 + 本机 Rust 服务验证一期。比较最终 Web 部署的 Rust 服务形态；若选择浏览器 Rust/WASM，记录其对原后端形态的调整。

**交付物**：运行形态决议、数据流图、日志和数据保留规则。

**验收条件**：明确代码、输入、轨迹、学习记录各在何处处理与保存；不把远程临时处理写成数据从未离开本机；不擅自承诺离线。

### 01.3 冻结一期 C 子集与教学规模

**前置任务**：01.1、01.2。

**要做的事**：按建议基线列出支持语法、课程、积木和算法；明确整数、作用域、错误语义与不支持项，后期扩展另列。

**交付物**：C 子集支持矩阵、课程与算法清单、正反样例清单。

**验收条件**：至少覆盖变量/运算/分支/循环/数组、有限输出和 main；课程及积木不会生成解释器不支持的语法。

### 01.4 确定技术版本与验收条件

**前置任务**：01.2、01.3。

**要做的事**：开工时核验 React 稳定版本及兼容生态，记录 Rust 工具链、编辑器和积木方案；确定设备、浏览器、网络、数据规模、资源预算及测量方式。

**交付物**：技术版本决议、性能基线、资源预算表。

**验收条件**：依赖版本可复现；2 秒首屏与 500 毫秒执行指标有测试条件；推荐数值被采纳或有理由替换。

1. 每项必需子任务的交付物、正常/边界/失败结果均可检查；未要求实现的设计任务以文档和可核对样例验收。

4. 不因任务包存在就标记开发完成。不满足验收条件时保持进行中/待验收/受阻并说明原因。
5. 如果本步骤含阶段门槛，必须核对该阶段所有必需任务，不能只验当前页面。
