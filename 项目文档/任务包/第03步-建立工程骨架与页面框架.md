## 本步骤目标

形成可复现的 React 与 Rust 开发环境及最小页面入口。

## 开工条件与文件归属

- 前置：第二步验收通过；这是最早允许建立产品工程的步骤。
- 建议修改范围：frontend/ 工程入口与全局样式、backend/ 启动入口、根级工程配置、依赖与锁文件；统一负责人。
- 范围之外：不实现后续完整业务，不制作登录页、空排行榜或管理后台。
- 路径是未来工程建议，03.1 确认后以实际目录为准。每个子任务领取时进一步登记具体文件，不能把父步骤目录视为独占整模块的许可。
- 公共契约、根配置、路由、依赖/锁文件、本地模型、中央进度由指定负责人维护；本窗口通过独立交接提交共享修改。

## 子任务

### 03.1 工程初始化与质量入口

**前置任务**：02.4。

**要做的事**：确定目录、构建、格式、类型检查、Rust 检查、运行说明和环境变量说明；只引入已确定的必要依赖。

**交付物**：工程骨架、运行文档、可复现依赖与质量检查入口。

**验收条件**：新环境按说明可启动；前后端检查可运行；密钥不进仓库；契约与源码职责分离。

### 03.2 页面导航与教学工作区布局

**前置任务**：03.1。

**要做的事**：建立首页、章节/小节、练习/积木、算法可视化和本地设置入口；PC 为主，确定中文界面、色彩、字体、键盘焦点和布局规则。

**交付物**：页面骨架、路由表、通用布局与交互规范。

**验收条件**：无登录可进入学习；训练页左积木右代码、可视化页左代码右动画；空态/加载/失败可区分。

### 03.3 Rust 执行适配与静态内容读取骨架

**前置任务**：03.1、02.1、01.2。

**要做的事**：按 01.2 决议实现静态课程/算法读取和执行适配入口。HTTP 形态提供服务健康状态、连接、跨源和取消；浏览器 Rust/WASM 形态提供模块加载、调用/取消和静态资源适配，不额外建设服务。

**交付物**：与运行形态匹配的 Rust 适配骨架、内容读取入口、调用联通说明。

**验收条件**：浏览器能够读取标准课程样例；HTTP 连接或 WASM 模块加载失败有可理解反馈；无用户表、用户会话和学习数据持久化。

### 03.4 早期集成检查

**前置任务**：03.2、03.3。

**要做的事**：验证启动、路由、内容加载和契约样例展示；确定后续任务的文件所有权与共享文件负责人。

**交付物**：骨架验收记录、目录归属表。

**验收条件**：浏览器到 Rust 执行核心的调用路径可走通；演示样例明确标注；不能据此将解释器或真实可视化任务标为完成。


## 本步骤验收与交接

1. 每项必需子任务的交付物、正常/边界/失败结果均可检查；未要求实现的设计任务以文档和可核对样例验收。
2. 采用已冻结契约；新契约与受影响模块已协调，不以本窗口单独运行代替集成通过。
3. 记录实际改动、验证证据、未测范围和遗留事项，写入独立交接文件；由协调窗口更新台账。
4. 不因任务包存在就标记开发完成。不满足验收条件时保持进行中/待验收/受阻并说明原因。
5. 如果本步骤含阶段门槛，必须核对该阶段所有必需任务，不能只验当前页面。
