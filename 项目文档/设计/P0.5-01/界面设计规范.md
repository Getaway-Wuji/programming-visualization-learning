## 1. 设计主张与适用范围

让代码与当前执行状态成为画面中心，让学习者一眼知道下一步做什么。保留“一步一懂”和“从代码，到理解。”；产品的识别来自括号/逐步执行符号、数组索引与完成清单，不依赖大面积绿色侧栏。

使用用户指定的ui-ux-pro-max与design-taste-frontend；后者按应用界面规则。主方向为Framed sheet，seed1414796492，沿用淡外框、实色工作面和克制层级。保留现有中文系统字体，不下载外部字体；使用`--keep type`，明确不采用抽取资料中的拉丁字体请求。调整为本产品的216px导航和16px面板间距，理由是长数组/代码工作台需要更多有效宽度；不机械复制示例开发者平台的228px/24px组合。

页面不是营销落地页：不用大字欢迎横幅、无意义指标、满屏动效、渐变、发光、毛玻璃或图标装饰卡片。可爱、炫酷通过明确的色板、圆角、密度和当前状态表达；不牺牲阅读和学习操作。完整应用只用一套组件与功能逻辑。

## 2. 固定设计变量

所有精确色值以`设计变量.json`为唯一设计数据源，`design-data.js`由该文件生成，供独立预览使用。正式产品在P0.5-02生成独立受控静态配置并显式登记，不直接把设计预览导入生产。

| 维度 | 冻结值 |
| --- | --- |
| 新档默认 | minimal简约、light浅色；旧档迁移保留原theme |
| 全局导航 | 展开216px、收起60px；图标有文字标签/可访问名称 |
| 应用框 | 顶栏48px；右/下外留8px；工作面圆角16px；不加静止阴影 |
| 内容留白 | 桌面24px，移动16px；面板横纵间距均16px |
| 阅读宽度 | 正文上限760px；可配完成清单/章节索引；不以阅读上限限制工具页 |
| 工具宽度 | 使用导航之外全部可用宽度，无1280px上限；初始可视化占约65% |
| 分栏 | practice 50:50；visualize/review 35:65；左侧比例允许30—70整数 |
| 重排 | 1100px以下导航折为顶部菜单、工作台区域标签；640px以下单区域/单栏、44px触控目标 |
| 字号 | 页面24、区域18、正文16、控件14、元信息12、代码15px；正文行高1.65、代码1.7 |
| 字体 | UI为系统中文无衬线；代码用Cascadia Code/Consolas等宽回退；其他数字用tabular-nums |
| 控件 | 桌面常规36px、同排同高；主/次/文字动作区分；键盘焦点3px且留3px间隙 |
| 动效 | 反馈/面板切换180ms，减少动态为0；无自动入场表演，算法动画不由主题控制 |

桌面网格算式：`视口宽度 = 导航216 + 右侧外留8 + 主工作面宽`；主工作面内部为`24左留 + 内容宽 + 24右留`。工作台内容宽再分`代码比例 × (内容宽−26) + 10分隔操作区 + 16间距 + 可视化比例 × (内容宽−26)`，边缘保持闭合。收起导航后将156px完整还给工作面。

## 3. 四套风格与八种明暗色板

| 预设ID | 名称 | 默认推荐模式/强调色 | 界面形态 |
| --- | --- | --- | --- |
| minimal | 简约·纸上推演 | light / `#1D5FBF`；dark / `#82B1FF` | 面板8px、控件6px，灰白工作面、舒适密度 |
| cute | 可爱·学习手帐 | light / `#BE185D`；dark / `#FFA9CB` | 面板20px、控件16px，淡粉外框、较宽松间距；正文和代码保持常规清晰字体 |
| cool | 炫酷·夜间演算 | dark / `#35D3E5`；light / `#006C80` | 中性黑与亮青、面板/控件4px、紧凑工具区；无持续光效 |
| tech | 科技·精密实验室 | light / `#0E7490`；dark / `#7CD8E8` | 灰白/中性炭黑、4px边角、精确索引与紧凑状态信息；不铺装饰网格 |

原规划的简约蓝`#2563EB`在本项正式冻结为`#1D5FBF`，减少框架默认色观感，并通过色彩检查；这是方案起点到正式设计值的调整，不改变主题数量或自选色要求。

选择预设会在设置草稿里同时预览其推荐明暗，明暗选择器同步显示；用户可另选light/dark/system。切换明暗不换preset，预设不能持久保存第二份明暗值；只有保存才生效。旧档首次载入默认minimal，但原settings.theme保留，不强制变浅。

颜色角色为ground/surface/raised/active/text/muted/border/control/accent/positive/negative/warning；代码背景和图表背景始终实色。普通文本/提示/占位文字至少4.5:1，焦点和必要图形/控件边界至少3:1；装饰分隔线不承担唯一状态信息。依据[W3C文字对比说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)和[非文字对比说明](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。

自选色持久保存用户原始规范大写`#RRGGBB`或null。派生算法固定：对当前色板的surface/raised/ground，原色若均达4.5则直接使用；否则按1%递增向浅色模式的黑/深色模式的白混合sRGB通道，取第一个全部达4.5的颜色作为可读强调色；0..100共101个有界候选。按钮字色取黑/白中对比更高者。色值格式无效不保存；界面展示“原色已适配为可读同色系”。切换明暗重新派生，不能把适配结果当用户原始选择覆盖。

主题色不重新定义比较/写入/错误语义。比较用位置括号/“比较”标签，写入用目标描边和“写入”，选择用焦点/索引，错误用明确文字；各状态的图形/颜色来自同一语义映射。只变色不得作为反馈唯一途径。

## 4. 关键页面布局

| 页面/原路由 | 首要问题 | 首屏结构与主要动作 |
| --- | --- | --- |
| 首页 `/` | 下一步学什么？ | 左主区为下一节/继续学习；右为真实今日目标；下为8章路径和案例入口；进度/积分来自同一持久投影，不造欢迎指标 |
| 课程 `/courses`及章节 | 知识按什么顺序学？ | 章节名称、目标、4节列表、已学/可继续状态；不把32节全部强挤首屏，也不以空目录计课程交付 |
| 小节 `/lessons/:lessonId` | 为什么这样写？ | 主区760px阅读正文，旁侧约280px完成清单；概念→完整代码→输入/状态表→常错/边界→独立练习；简单节默认无积木 |
| 练习 `/practice/:exerciseId` | 怎样提交自己的解答？ | 顶部题意可折叠，左解答/积木可选，右测试与教学目标反馈；底部就近运行/提交；辅助逐块区默认折叠 |
| 算法 `/visualize/:caseId` | 当前一步改变什么？ | 左35%代码，右65%大可视化；下方播放、变量/输出；题意和原理按需展开；可视化可单独展开 |
| 复盘 `/practice/:exerciseId/review` | 哪组、哪一步不满足？ | 与算法共享工作台；展示同题当前接受的caseKey/失败解释；禁止重跑输入或把旧题结果装进来 |
| 设置 `/settings` | 设置后是什么样？ | 左说明、右四预设/颜色/明暗/背景/积木/布局预览；显式“保存外观”；数据清除最后且有明确影响说明 |

正式应用仍只保留原四个全局目的地：首页、C课程、算法、设置。设计预览将小节/练习/复盘也列入导航，是为了评审7种页面；生产应用不得照搬为7个重复顶级目的地。章节/题目返回关系与公开ID继续沿原路由契约。

练习/算法标题行右侧保留专注、区域切换等必要动作，不能把常用提交埋到大画布之后。固定或吸附操作栏若实施，必须预留对应高度；不覆盖内容或占满手机视口。

## 5. 数组与宽屏规则

默认排序数组明确为`[7,3,5,3,9,1,6]`，长度7，兼含乱序/重复。随机默认长度7，生成器/seed解释仍沿07.2；上限30、普通元素−999..999、空/单项合法规则不变。默认输入更新须发布新内容版本，不能改旧样例/黄金资料。

7/15/30项均默认提供所有逻辑位置的概览，图表不能裁切、元素不能互盖，不以整页横向滚动补救。柱形按真实值/共同零基线绘制，负数向下、0有基线标记，重复值不赋予随机颜色；输入逻辑空时不画占位0。不能为了看起来饱满更改数值比例。

绘图区按实际可用宽度布局。数字/下标默认12—14px；空间足够时逐项列值，放不下完整4位带符号整数时保留全部位置及下标，并将当前比较/写入/选择值同步到清楚的详情区；“全部数值”表可用键盘打开，不依赖hover或把文字缩到11px以下。不得将横滑设为桌面默认遍历方式。窄屏允许概览＋当前值/索引详情、区域切换，仍提供所有数值的可访问文本。

分隔条可拖也可聚焦，用左右键每次5个百分点调整，Home/End可到30/70；必须显示可调范围和语义名称。达到最小宽度时优先收起次面板或切区域，不继续挤压代码/图表。专注模式退出恢复先前导航状态，不修改程序。

## 6. 积木、练习与状态文案

全局blockWorkspace=auto/show/hide；auto按课程独立展示配置（code/blocks）派生。练习内快捷切换仅改变当前题的呈现，“记为默认”才更新全局偏好；外观弹层在同题会话内，不因进入设置卸载草稿。显示设置不授予语法解锁权限。

独立练习默认只有必要main/受控输入源/无答案空位；示例与改错从主动入口进入。重置若覆盖草稿必须先说明影响，查看提示/答案不自动判通过。错误草稿、缺槽与暂未映射代码保留；不能执行上次有效稿来假装运行成功。源码/输入变化废弃当前运行，主题/显隐/拖动分栏只重排。

| 状态 | 用户看到的内容 | 可用操作 |
| --- | --- | --- |
| 尚未作答/缺槽 | “补充你的解答”，指出空位 | 编辑、分层提示；不静默补答案 |
| 分析进行中 | “正在检查当前代码”，保留草稿 | 继续编辑/取消；不提交旧源码 |
| 代码非法/未同步 | 具体位置/原因与“保留当前代码，积木尚未同步” | 修改；旧有效投影仅标对照 |
| 执行中/判题中 | 当前输入或第k/总组、可取消 | 取消；不能重复发同一提交 |
| 正常运行 | 结果和本次轨迹，“仅当前输入” | 复盘或提交全测；不能称整题通过 |
| 目标未满足 | 失败测试/教学原因/复盘入口 | 改稿、看提示；不发首次奖 |
| 全测通过待保存 | “练习通过，等待保存” | 等待；保留凭证，不伪报已保存 |
| 保存失败 | “已通过，但尚未保存”及原因 | 重试保存；不靠重跑/重复奖励恢复 |
| 保存完成 | “练习已通过并保存”，小节缺项清单 | 返回小节、满足条件后下一节 |
| 内容加载/存档失败 | 就近说明失败区域与恢复方式 | 重试/安全只读；不全页遮断无关内容 |

“确认已学习＋全部必修题有效通过”共同决定小节完成，没有可绕过判题的直接完成按钮。原六题真实判据/24测试保持，新增题据独立内容设计决议。

## 7. 外观保存与背景

设置页使用单一显式保存模型，所有控件先预览，保存后才显示已保存；取消/离开未保存草稿恢复已保存外观。工作台分栏在拖动结束/键盘确认后按统一服务保存，冲突显式保留布局草稿并提示；不在pointermove写DB。

背景只允许本地单张静态PNG/JPEG/WebP、原始文件1..5MiB、宽高1..4096；遮罩整数0..90默认75，fit=cover/contain/tile，position=center/top/bottom。按钮提供预览、替换、隐藏/显示、移除和恢复默认；页面内容面板保持实色。背景不随主题自动删除，不读取任意网络地址，也不传Rust。

详细存档、Blob校验、CAS/损坏/清除与迁移以[外观存储设计](../../契约/P0.5-01-外观偏好与图片存储设计.md)为准。图片损坏只禁外观写入，合法学习仍可保存；原meta/学习核心损坏则沿旧保护。

## 8. 设计预览与实施验收的区别

预览提供四风格、明暗、自选色、7/15/30固定数组、7种页面、侧栏/专注/可视化展开、分栏调整与草稿呈现。所有数据为明确标注的固定场景；运行/提交/保存仅解释未来行为，不产生结果、学习事实、积分或真实背景资源。`design-data.js`不含用户档案，预览不调用网络、WASM、IndexedDB、localStorage或产品模块。

P0.5-01检查设计变量、浏览器渲染、对比度、溢出、区域/主题切换和文档一致性。P0.5-02之后仍须逐项真实实现、三浏览器/迁移/判题与回归，不能用预览截图替代实际产品验收。
