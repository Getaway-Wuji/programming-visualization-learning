# 14.1 · 诊断使用说明与示例

错误面板把现有真实检查或执行结果显示为 `main.c:行:列: error: 摘要 [错误码]`，并给出源码片段、通俗解释和检查建议。这里的 GCC 风格只是教学排版，不调用 GCC；main.c / main.cpp 是当前单文件的教学名称。

在练习中选择“编辑 C 并同步积木”，修改代码后等待检查。词法、语法或语义错误会保留整份错误稿，同时禁用运行和提交。点击“定位问题”选中当前稿的对应位置；修复后错误消失并恢复可用操作。已保存的编辑历史可在刷新后显式恢复，未保存草稿仍遵守原历史提示。

运行错误位于提交与反馈区域。定位对应本组实际执行的源码，不拿另一个输入组的草稿偏移代替；积木有可靠映射时可直接定位节点。手机宽度会打开目标标签页。定位不修改代码、不重跑、不发奖励事件。普通错块也能通过“定位积木”选中当前未完成节点。

行列从 1 开始，列按 Unicode 字符计数，制表符算一列。中文与 emoji 不破坏字节范围和编辑器选区的对应。诊断位置是解释器发现问题的地方，遗漏的分号可能在上一行。没有可靠位置的错误不会虚构 1:1，也不会选中无关语句。

## 四类真实示例

下面均为浏览器实际发送给 Rust 的程序；原请求和结果在 `.artifacts/14.1/browser/candidate-final2/`，并随发布凭据保留。不是新增关卡，课程数量与奖励规则不变。

| 类型 | 实际结果 | 修复方向 |
| --- | --- | --- |
| 词法 | `main.c:5:1`，`E_LEX_INVALID`，阶段 lex | 删除不支持的 `@`，写合法语句 |
| 语法 | `main.c:6:1`，`E_PARSE_INVALID`，阶段 parse，expected 为 printf semicolon | 在上一行 printf 调用后补 `;` |
| 语义 | `main.c:5:16`，`E_NAME_INVALID`，阶段 semantic | 使用已声明的输入变量 x |
| 运行 | `main.c:6:16`，`E_DIV_ZERO`，阶段 execute | 使用有效除数；本题应输出 a / b 与 a % b |

前三个示例在“输出输入变量”中保留自动生成的 x 声明，分别使用以下完整源码。

```c
#include <stdio.h>
int main(void) {
    int x = 7;
    // 中文😀：保留原稿
@
}
```

```c
#include <stdio.h>
int main(void) {
    int x = 7;
    // 中文😀：保留原稿
printf("%d\n", x)
return 0;
}
```

```c
#include <stdio.h>
int main(void) {
    int x = 7;
    // 中文😀：保留原稿
printf("%d\n", missing); return 0;
}
```

将 main 中的末尾改为 `printf("%d\n", x); return 0;`，前三种错误会清除。不要删除原课程输入声明，否则会触发输入绑定检查。

“商和余数”的运行错误示例：

```c
#include <stdio.h>
int main(void) {
    int a = 7;
    int b = 3;
    // 中文😀：保留原稿
printf("%d\n", a / 0); return 0;
}
```

解释器返回 program-error 和已完成步骤前缀，失败动作不算成功步骤。改成 `printf("%d %d\n", a / b, a % b); return 0;` 后重新运行正常结束；本组运行本身不记录通过或积分，正式提交仍检查全部输入及教学目标。

内存观察中的 C++ 越界示例使用 main.cpp；其执行分支未单独提供阶段时明确显示“阶段未单独提供”，不伪造字段。回退后可继续查看错误前的完整状态。虚拟地址仍不是宿主真实地址。
