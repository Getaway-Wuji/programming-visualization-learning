# 14.3 · Bug修复关卡使用说明

从“C语言课程”目录点击“语法与逻辑 Bug 闯关”，或打开 `/#/bugs`。四关各有独立通过记录，修复并通过全部真实判题后首次各10分，重复0分；原课程必修题及其首次权益分别保留。

| 关卡 | 观察重点 | 四组输入 |
| --- | --- | --- |
| 输出语句少了什么？ | 语法诊断发现处不一定就是遗漏处，检查输出语句分号 | x=-9、0、7、999 |
| 输出调用没有闭合 | 分清算式和整个printf调用的括号 | x=-4、0、5、999 |
| 零走错了分支 | 正常结束与答案正确不同，零属于非负数 | x=-3、0、4、999 |
| 总和为什么总多一？ | 空数组与累加初值，真实遍历逻辑范围 | []、[4]、[-2,5]、[7,-3,0,5,-3,2,9] |

点击“修复：关卡名”后直接进入给定错误稿。前两关有真实Rust语法诊断，保持错误原文并禁用提交；修复结构后才可运行。后两关可实际运行，但给定版本无法通过全部判题。保留题目自动生成的输入声明，不要把某组输入写成固定输出。

“运行本组”只检查第一组，不保存通过或积分；“提交练习”检查全部四组和教学目标。判题会检查真实输入依赖、if/else覆盖或数组遍历等要求，不能靠固定答案、无关循环或源码文本相同蒙混。符合目标的不同正确写法也可通过，例如把负数判断放在前面，或用合法反向循环求和。

需要帮助时逐层打开三条提示。“查看修复解析与一种参考写法”是主动展开的讲解，不会替你修改答案。参考只显示main内的解答部分，输入声明仍需保留。

语法错误面板复用14.1的实际诊断、行列、源码标记和定位。逻辑失败显示对应测试与真实判题检查，不能把“程序正常结束”当作通关。提交后可逐步查看本次实际代码、变量与输出，或进入“查看本次复盘”；修改代码会清除旧运行。

编辑历史按关卡独立保存，保存状态就绪后，可在刷新或返回关卡时展开“编辑历史”，选定版本并点击“恢复所选版本”。错误稿和修复稿都保留原文，恢复会重新检查并清除旧执行；未保存的内容可能丢失。全站仍保留最近100条、合计8MiB。

“已保存通过”需要全部测试和教学目标通过，并且学习事务保存成功。若显示未保存，积分尚未入账；点击“重试未保存操作”重试同一次有效事实。刷新后已保存通过和积分保持，重复提交不重复奖励。明确清除本地档案则开始新世代，与原项目规则一致。

这四关是选做修复练习，不增加原32节的小节完成条件，也不凭关卡通过永久解锁原课程积木。临时积木权限沿关联小节，旧课、编辑历史和奖励规则兼容。野指针与死循环关卡属于14.4，本交付没有实现。

本页所有运行和诊断来自现有Rust/WASM解释器；不是14.2编译流程中的预编写示意，不调用GCC或运行原生用户程序。源码/输入/轨迹不进入学习档案，编辑历史仍按原规则单独保存。
