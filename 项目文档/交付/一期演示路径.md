# 一期演示路径

日期：2026-10-23。配套[一期使用说明](./一期使用说明.md)；[11.5一期验收](../验收/11.5-一期交付验收.md)已通过。以下是按实际按钮、公开内容ID及初始积木编写的默认目标手工演示路径。安装版Firefox本轮验证默认185→190分；三套新增自动化路径在首次学习前设置6/6/1目标，故为180→190分，两者分别记录，本文件不冒称每一个演示选项都在本轮另跑一次。

## 准备一个不会影响日常记录的演示环境

1. 按使用说明启动生产预览，统一打开[http://127.0.0.1:4173/](http://127.0.0.1:4173/)。本次全程保持这个浏览器配置、协议、主机名和端口。
2. 新建独立浏览器配置，作为全新本地状态；不清除已有日常档案，不导入数据或通过控制台制造学习记录。确认首页显示已完成0/6、已入账0分、待入账0，Lv.1及默认嫩叶形象。
3. 点击“设置每日目标”，确认推荐为“1道练习 · 1个小节 · 0个案例”，今日目标待开始。关闭面板。先不要修改目标或系统时间，确保以下学习在同一个档案学习日完成。
4. 等待本地保存、课程、目标、奖励和形象配置可用。若显示临时使用、只读、未保存或待入账，先按页面提示恢复；不能继续以正常保存路径记录结果。

预期：全新档案无需注册登录，网页资源从本机静态服务加载，执行位于浏览器Rust/WASM。URL只定位内容，不包含源码、输入或学习记录。

## 完成第一节，展示积木到真实执行

1. 首页点击“开始学习”，或从“浏览C语言课程”进入“变量与表达式”→“变量和输出”。公开定位为[变量和输出](http://127.0.0.1:4173/#/lessons/lesson.c.variables-output)。阅读目标、讲解、参考源码、常见错误和边界。
2. 点击“开始本节学习”，再点击“确认已学习”，等待本地保存完成。单独这一步只确认学习，必修练习尚未通过，小节未完成。
3. 点击“进入练习工作区”，到[输出输入变量](http://127.0.0.1:4173/#/practice/exercise.c.echo)。左侧为真实积木，右侧C只读。
4. 在“逐块编辑与键盘连接”的“积木列表”中选择“输出 · …”。“输出格式”当前为`%d`。把光标移到末尾，追加两个字符反斜杠和n，得到`%d\n`；不要先清空整个格式，以免改变输出参数槽并断开变量块，也不要输入实际换行。
5. 点击“准备代码”，检查右侧是包含当前输入声明的完整C程序。点击“提交练习”，等待“本次提交通过全部测试与教学目标”、已检查3/3组、通过记录已保存。页面实际测试含7、0、−9，严格要求每个输出值后有换行；只打印一个固定答案不能通过。
6. 展示播放器起点“步骤0”，点击“前进”两次，再“后退”两次；回到初态时变量、输出和源码位置应恢复。选择4×，点击“播放”，观察游标/画面/高亮变化，再“暂停”。保持播放工作区在前台；速度只改变观看节奏。
7. 点击“查看本次复盘”，应保持本题真实提交的反馈、源码及当前游标；再“返回练习工作区”，状态仍对应同一次提交。复盘不重跑程序，也不额外发奖励。
8. 点击“返回本节学习”，应显示“小节已完成”。回首页查看1/6、35分、待入账0、Lv.2；今日目标已打卡。35分为首次练习10＋小节20＋默认当日目标5，不是每节35分。

如要展示新增/删除积木，可在正式准备前从“添加积木类型”选择“整数”并点击“添加积木”，观察出现未连接块的提示，再用“删除选中积木”删除这个新块，恢复原程序后继续。不要删除课程输入块；它的名称和初值由测试绑定。可拖拽连接，也可用“连接到积木”→“连接位置”→“连接选中积木”完成合法连接。提示缺槽或未连接时先修复，不把旧生成代码当成当前程序。

## 按实际初始程序完成其余五节

每节都按“课程阅读→开始本节学习→确认已学习→进入练习工作区→修改积木→准备代码→提交练习→检查全部组通过且保存→返回本节学习”的顺序。只改表中指定的解答积木，保留输入来源块。积木列表前面的序号随工作区变化；以显示类型、值和右侧生成代码确认目标，不能把序号当固定ID。

| 小节/公开定位 | 必修题ID | 当前初始程序的最小修正 | 通过组数 |
| --- | --- | --- | ---: |
| [表达式](http://127.0.0.1:4173/#/lessons/lesson.c.expressions) | `exercise.c.two-x-plus-three` | “积木列表”第一个“整数 · 1”是乘数，把“整数值”改为2；生成式应为输入的两倍加三 | 3/3 |
| [条件](http://127.0.0.1:4173/#/lessons/lesson.c.conditions) | `exercise.c.nonnegative` | 选择唯一“比较”块，“运算符”由`>`改为`>=`，0也应输出1 | 3/3 |
| [while 与 for](http://127.0.0.1:4173/#/lessons/lesson.c.loops) | `exercise.c.two-loop-sums` | 两个“比较”块的运算符均由`<`改为`<=`，while/for两段各自有效累加1到n | 4/4 |
| [一维数组](http://127.0.0.1:4173/#/lessons/lesson.c.array-update) | `exercise.c.increment-at-index` | 选择解答中的“整数 · 0”，把增量改为1；应只更新并输出`values[k]` | 5/5 |

每题可重复展示单步/回退/复盘。当前练习只保留一个测试组的完整轨迹，反馈列出全部组摘要；完整结果不等于当前游标的输出。修改积木会立即使旧判定/轨迹失效，但不会删除合法历史通过；再次提交须重新检查全部测试。

预期：六题共24组真实测试通过，六节都显示完成。未额外观看案例、未跨日、未改变默认目标且奖励正常入账时，首页为6/6、185分、Lv.3、待入账0。计算为6×10练习＋6×20小节＋一次当日目标5。已打卡的同一学习日不会每完成一课再发5分。

## 用一个案例展示输入、完整观看和首次奖励

1. 从“浏览算法与演示”进入[变量赋值](http://127.0.0.1:4173/#/visualize/case.c.assignment)，保留示例输入。点击“准备运行样例”（输入面板中“应用输入并准备”也可），检查显示源码和本次输入，再点击“运行示例”。
2. 等待真实程序正常完成，播放器从步骤0开始。保持当前变量/数组画面实际可见，逐步“前进”到末尾，或在画面可见时自动播放至结束；不要切换后台、换输入或重新运行。观看覆盖未完成时“确认已观看”禁用。
3. 到末尾，页面显示“完整观看已就绪”后点击“确认已观看”。等待“本次观看已保存”；回首页应为190分、Lv.3、6/6、待入账0，积分明细新增该案例首次观看5分。
4. 刷新首页或重新进入案例，积分保持190。单纯运行、重播或重复确认不能再发该案例首次奖励；刷新丢弃临时轨迹和观看覆盖，不能只靠URL恢复观看。

如演示观看时页面向下滚动使当前画面不可见，请暂停并回到画面位置后继续。累计观看的是本次真实轨迹的有效呈现，不是只等待执行结束或停在底部按钮处。

七个实际案例入口如下；额外完成并确认其他首次案例会每个再加5分，不再符合“190分”这一单案例演示检查点。

| 显示名 | 公开案例ID |
| --- | --- |
| 变量赋值 | `case.c.assignment` |
| 分支判断 | `case.c.branch` |
| 循环 | `case.c.loops` |
| 数组遍历 | `case.c.array-traversal` |
| 冒泡排序 | `case.c.bubble-sort` |

若要附加展示数组输入，可选择冒泡排序，输入`3, -1, 3, 0`，“应用输入并准备”后运行，完整输出应为`-1 0 3 3`及换行；更改输入立即撤销旧源码/轨迹，必须重新准备。二分搜索可用有序`-1, 0, 3, 3`查找3，结果为2；改成乱序必须提示错误。此附加演示不必确认观看，以保持190分检查点。随机输入可选长度、填写种子，点击“生成随机数据”或“按种子复现”；同约束/版本/种子/长度须复现同值，刷新不保存种子。

## 保存每日目标与形象，再刷新核对

1. 回首页点击“设置每日目标”，检查今日已打卡及当前目标1/1/0。将“每日练习数”设6、“每日小节数”设6、“每日案例数”设7，点击“保存自定义目标”，等待“目标已保存”。当天已经固定的1/1/0保持，6/6/7用于后续尚未开始日期；这次设置不额外发分。刷新后再打开面板，已保存模板仍为6/6/7。
2. 点击“查看打卡历史”，应仅有本次学习日的已打卡记录及5分已入账；不修改系统时钟伪造跨日。关闭面板，点击“查看基础形象”进入[基础形象设置](http://127.0.0.1:4173/#/settings?panel=avatar)。
3. 从嫩叶、芽苗、方块、星光中选择“星光”，在“强调色十六进制”填写`#7C3AED`，点击“保存基础形象”，等待已保存。刷新，选择和颜色应仍在，首页形象也一致；仅看到更改预览不能算保存。
4. 再次核对首页6/6、190分、Lv.3、待入账0；积分明细有六笔练习首次通过、六笔小节首次完成、一笔日奖励和一笔案例首次观看，共14笔已入账。重新打开课程，六节仍完成，首次奖励不重复。
5. 刷新或直接打开本题`/review`时，没有当前页面内保留的真实提交应显示无可复盘运行；历史通过仍在。这是临时执行与持久学习记录的明确边界。

## 收尾与异常说明

日常档案保持原样。本演示不执行“清除本地数据”；若确需在专用演示档案清除，先阅读“本地设置”→“本地数据”的后果，再主动确认。清除后本平台无法恢复学习、账本、防重、目标、形象或设置，迟到的旧运行/保存不能恢复它们。关闭预览终端即可停止本机服务。

若运行失败，保留页面真实诊断，恢复模块/输入后重新运行；不把错误前缀、旧轨迹或保存失败当成通过。若积分为待入账，检查“积分明细”中的状态，按提示“重试奖励入账”，等实际入账后再核对总分。185/190分依赖全新档案、同学习日、默认目标、上述首次内容且全部成功保存/入账；重复使用旧档案或跨日应按实际账本解释，不强改为预期数。

原执行目标500毫秒未全部达到；11.4对131次轻微偏差按正式采样前固定的冷Module≤800毫秒、暖Module≤600毫秒带备注接受，安全截止1000毫秒和真实正确性要求保持。此次手工演示不是重测完整性能矩阵，也不证明物理持续60fps、长期零泄漏、自然配额耗尽、自然坏档、真实旧版升级、安装版Firefox产品50轮、全新电脑安装或公网部署；详见[11.4交接](../交接/11.4-交接.md)。
