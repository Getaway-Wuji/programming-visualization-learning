## 后继配置方式

配置仅由本机服务器侧读取，放用户批准的仓库外私有配置目录，示例enabled=false、程序/模型目录与实际exe SHA为null。它不包含API密钥；未来启用须填实际已验路径/可执行SHA、保持固定版本/manifest、指定原前端origin。程序哈希必须从已验证官方zip解出后取得，不能把zip SHA冒称exe SHA。tag相同但digest不同也拒绝，不能静默换模型。

用户主动运行可选AI适配，原前端origin/端口保持。服务器按需增加同源`/api/ai/v1/*`转发，两个本机服务分别只绑定127.0.0.1；随机服务器间通道凭据仅在服务器内存/受控子进程通道中，不给浏览器，不存任何`VITE_*`、localStorage、URL、HTML或日志。不会建立账号/云档案。纯静态或远程入口未具备受控同源转发时诚实显示不可用，不要求关闭浏览器安全策略。

生产本机入口用受控静态网关提供既有生产Web包与相对路由，用户不必安装Node/Vite；它只读包内公共资源并沿原CSP/指纹，不读用户目录或执行C。开发才使用现有开发服务器转发。端口占用时不得杀/替换已有用户服务，也不得静默改origin；安装与启动说明必须让用户能选择原origin的受控入口。这也是19.4同源集成和原档零副作用的实测门槛，不是本轮已提供的可执行程序。

Ollama子进程使用白名单环境，明确覆盖以下值；不继承未知debug/cloud/proxy设置，不修改用户全局环境：

| 环境项 | 固定值/规则 |
|---|---|
| OLLAMA_HOST | `127.0.0.1:47832`，只用本项目拥有的进程，不接用户11434服务 |
| OLLAMA_MODELS | 用户批准的仓库外公开权重目录，不读取其他模型/私人文件 |
| OLLAMA_NO_CLOUD | `1`；无远程模型、web search或云自动回退 |
| OLLAMA_DEBUG | `0` |
| OLLAMA_DEBUG_LOG_REQUESTS | `0`，与上一项不同，必须显式覆盖 |
| OLLAMA_NOPRUNE | `1`，禁启动时自动清理权重 |
| OLLAMA_NUM_PARALLEL / MAX_LOADED_MODELS / MAX_QUEUE | `1 / 1 / 1`；代理在此之前强制整个实例AI并发1、队列0 |
| OLLAMA_KEEP_ALIVE | `0`；请求同时传keep_alive=0 |
| OLLAMA_LOAD_TIMEOUT | `30s`，另有请求原起点60s总硬截止，不按加载进度延长 |

stdout/stderr不写文件；不使用带自动升级/请求历史的GUI，不注册常驻或开机服务，不用`ollama run`交互历史当产品API。固定版源码确认有正文debug落盘开关；关闭配置仍须后继用自有样例监测验证，不能凭env值推断已无日志。安全边界不承诺防御同用户恶意本机进程或物理擦除内存。

模型调用只允许`POST /api/chat`，profile固定model/format/options；无tools/history/images/传路径或任意URL。运行器/权重校验与读取状态可用本机`/api/version`、`/api/tags`、`/api/ps`等受控只读核对，不自动pull/run或触碰任何云端额度。取消由代理杀自身Windows Job Object子树，未确认退出则保持AI忙状态；不接管/终止其他用户进程。

实现时先以挂起状态创建自有子进程、加入禁止breakaway且KILL_ON_JOB_CLOSE的Job，再恢复，避免加入Job前子进程逃逸；退出/取消用Job终止并确认进程状态。Windows提供组级进程管理/终止机制，但Ollama的具体子树及驱动释放必须真实核对，不能凭API存在标取消已验。[Microsoft Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)、[TerminateJobObject](https://learn.microsoft.com/en-us/windows/win32/api/jobapi2/nf-jobapi2-terminatejobobject)。

## 19.4 必须实际完成的工作

1. 先取得准备授权并验证官方程序/模型digest，测实际CPU/GPU、模型内存、磁盘、冷启动与实际token计数。记录版本/所用权重，不以本文或官方能力说明替代本机运行证据。
2. 领取新增独立AI代理、C工作台可选AI面板和必要同源服务器适配/根配置归属；原64源变动时追加新的不可变发布。原浏览器执行位置、1000ms/fuel/单Worker/缓存和SAVE9保持，AI延迟单列。
3. 从当前严格接受的真实advanced结果选择片段与事实，绑定原运行/源码/输入修订/游标/页面lease和本地清除epoch。每次预览后确认才发送；选择变化必须重新确认，不传学习summary/档案。
4. 真实本机模型至少三例：空/失效指针引用真实诊断和虚拟对象；循环边界或更新错误引用实际条件/写入步和同游标值；语法错误没有轨迹时只定位实际诊断。逐条人工/程序核对事实与建议和跳转，保留实际请求/响应及原Rust证据，使用自有教学代码。
5. 正常成功须匹配版本、digest、当前身份、事实列表与原60s；任何不存在的引用、截断、过期或额外动作字段整包拒绝。文本按文字显示，不能执行工具、网络或代码，不能自动替换/运行建议。配置缺失、入口不支持或模型失败时原运行/单步/断点/保存/复习均可用。
6. 实测加载/推理/解码期间取消和改码/换输入/换游标/清档/卸载、两个标签忙竞争、原执行抢先取消AI、模型子树退出与无迟到覆盖。若60s内无法稳定完成或需要扩大上下文/资源，先提范围决议，不静默调大。
7. 记录原生全部17store行键及localStorage/sessionStorage前后，确认AI没有新增学习/奖励/弱点/草稿写入；核浏览器请求、代理/Ollama磁盘/日志与域外网络无上下文泄漏。公共资源/明确下载的连接与推理上下文传输分开记录。
