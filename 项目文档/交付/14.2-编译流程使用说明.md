# 14.2 · 编译流程使用说明

从主导航选择“编译流程”，或打开本地运行页面的 `/#/compilation`。这是独立的教学模拟，不计入课程完成或积分。

## 四步走完一个示例

默认情景为“正常流程”。main.c 引用教学头文件 values.h，头文件把 BASE 定义为 2。示例只用于解释编译概念，不能直接当作本站支持的宏程序执行。

1. 在“预处理”点击“演示此阶段”，对照原始源码与展开后的概念源码；BASE 变为 2。再点“下一步”。
2. 在“编译”观察架构无关伪汇编，理解语法/语义检查和翻译的职责。伪汇编不是某个真实处理器的指令，不能交给真实汇编器。
3. 在“汇编”观察目标文件的符号、指令区与重定位概念。这里只显示结构说明，没有机器字节或真实 .o 文件。
4. 在“链接”观察目标文件与必要启动支持的组合。完成后仍未运行 main；本页不会生成可下载或可执行的程序文件。

每一阶段的产物在演示后才出现。可以用“上一步”或已开放的阶段卡片回看，也可用“下一步”继续；键盘 Tab / Enter 可操作。切换阶段会把焦点带到阶段标题。首尾按钮有明确禁用状态，不能越过尚未演示的阶段。

## 看懂为什么会停下

“演示情景”提供四个固定常见问题说明，不是可提交的 Bug 关卡，也不是实时诊断：

| 情景 | 停止阶段 | 应理解的区别 |
| --- | --- | --- |
| 找不到头文件 | 预处理 | 先核对文件名、路径与搜索位置 |
| 遗漏分号 | 编译 | 文本展开成功，不等于语法正确 |
| 汇编文本被手工改坏 | 汇编 | 指令写法、操作数或目标架构不匹配可能阻止汇编；本例故意改坏示意文本 |
| 函数缺少定义 | 链接 | 声明不等于实现，目标文件中可能保留待解决的外部符号 |

选择情景会清空所有旧产物。依序演示到错误阶段后，会显示“常见错误说明 · 非真实诊断”，该阶段不产生结果，后续阶段不开放。点击“恢复正常示例”从第一步重走正常流程；“重新开始”则保留当前情景并清空进度。

刷新或离开页面后，演示从默认正常情景重新开始。此页没有持久学习记录、编辑草稿或奖励；它不会改动原课程、代码编辑历史及已保存的通过记录。

## 与本站真实执行对照

下方“本站怎样运行你的程序？”解释现有 Rust 解释器的词法、解析、语义检查、受限执行与真实 Step DSL 轨迹。这条路径不生成原生汇编、目标文件或可执行文件；支持约定头文件行，也不等于展开系统头文件。

“查看真实解释执行”进入已有变量赋值案例；在那里点击“运行示例”才会真实执行。“在练习中查看真实诊断”进入原有输出输入变量练习，可沿14.1已验收能力查看真实错误、定位与修复。四阶段的示意内容不会被送进解释器，也不会冒充真实诊断结果。

页面底部“概念依据与阅读边界”附有GCC、GNU CPP和binutils官方资料链接。真实工具的内部流程、优化、文件格式和动态加载会因环境不同而变化；本示例聚焦四阶段的基本职责。
