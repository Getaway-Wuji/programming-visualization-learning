浏览器/操作系统可能管理底层内存、HTTP/编译缓存和清理时机；平台要求的是不主动持久化或上传原始运行内容，不作进程退出后物理字节已擦除的承诺。应用“清除学习数据”与浏览器“清除网站数据/缓存”应分开说明。

## 2. 网络、日志与缓存的执行规则

1. 运行请求是主线程与 Worker 的本地消息，不建立 HTTP 执行端点。不得将用户内容放入路径、query、hash、cookie、请求头、资源命名、崩溃报告或状态查询。界面导航只携带必要公共内容 ID，不携带学习档案/程序。
2. 公共资源下载与用户数据分开。资源 URL 不由用户输入值拼接，源码/输入/轨迹不进入 HTTP 缓存或 Cache API；禁止把运行请求/响应包装成可缓存资源。模块编译缓存只含公共解释器，不含某次执行状态。
3. Worker 与 WASM 导入只开放受控绑定、预算/计时和虚拟输出所需能力；加载后不使用网络/存储 API。主线程网络能力用于同源公共资源读取；不引入第三方分析、广告、会话回放、远程错误上报或隐式云同步。
4. 正式构建和本机开发服务的调试日志同样禁记真实运行内容。调试需要真实对象时只能在本机主动查看临时内存，不能启用“打印所有请求”；提交验收证据使用合成数据。
5. 用户程序输出及诊断用安全文本展示，不插入可执行 HTML、脚本或动态 JavaScript。C 的输出写入受限轨迹，由播放器显示；宿主异常只映射技术类别，不原样持久化带正文的异常对象。
6. 本地存储保存学习结果摘要而非整次运行包；不得借“进度记录”自动保存源码、输入或轨迹。三期薄弱点记录仍需最少业务事件，不获取整条轨迹作为默认档案。

托管商仍会处理连接 IP 等网络元数据，资源路径也可能反映访问了哪份公开内容。KEEP-08 是部署选择/配置门槛，不是尚未选平台的事实保证：上线前核验源站、CDN、错误监控的实际策略和可关闭项。平台强制的持久原始元数据若不能满足本规则，需改托管设置/平台或记录明确决议后调整披露，不得照抄“零日志”。无论如何都不允许添加执行内容上传。

## 3. 清除、保存失败与后续历史

一期应用的清除入口由 04.3 实现：说明影响、终止正在运行的 Worker、使当前及其他标签页旧写入失效、清除本项目业务/偏好记录并重置临时状态。不得清空同源其他项目的数据，也不能让清除前的异步写入把旧档案重新写回；具体跨标签协调与清除事务由 02.3 冻结。

公共静态缓存可重新下载，不因“清除学习数据”承诺浏览器全部缓存消失；浏览器级清除网站数据可同时影响应用记录与资源缓存。没有外部学习存档可供恢复。保存失败可继续临时学习，显示未保存并允许幂等重试。

P1 编辑历史、执行恢复缓存、用户导出文件是三种独立数据。进入后续阶段时在相应契约中增加明确的数据范围/容量/删除方式，不能用一期“临时”说明掩盖已新增的持久历史；AI 也不能沿用本地执行的告知。
