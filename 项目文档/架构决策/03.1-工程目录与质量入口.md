# 03.1 工程目录与质量入口

日期：2026-10-14；负责人：Codex-03.1主窗口。本文是DEC-003/004 V1.0的工程落地记录，不升版既有决议或十二项契约。前置02.4已验收；本次只完成03.1。

## 1. 实际布局

正式采用`web/`、`engine/core/`、`engine/wasm/`、`content/`、`shared/fixtures/`、`tests/`、`scripts/`。这是DEC-003建议布局的实际落实；不使用较早守则中的frontend/backend建议名。根目录统一维护npm包/锁、Cargo workspace/锁、工具链、Vite/TS/ESLint/Prettier和环境配置。

React只有最小中文入口和建设状态。Rust核心是普通lib，WASM层为cdylib/rlib并调用同一核心；没有另建HTTP执行服务。公开课程发布目录目前只有职责说明。契约和黄金资料仍由`项目文档/契约/`提供唯一来源，shared入口只指向原索引，不复制Schema、改期望或更换fixtureId。

内部浏览器harness位于tests，生产工程产物是`web/dist/`，harness另输出`.artifacts/browser-dist/`，不进入产品发布目录。Rust探针只接收无用户内容的uint32 nonce，返回`kind=build-probe`和`interpreterReady=false`，不接受C、不产生EXEC结果/Step DSL/判题/学习事件。这不是03.3正式执行适配；引擎0.1.0是工程包版本，不声称P0-C解释能力。

## 2. 版本和安装

保留DEC-003的22个精确npm直接包、Node24.21.0/npm11.19.0、Rust/Cargo1.99.0、wasm-bindgen crate/CLI0.2.129、serde1.0.229，以及DEC-005补充serde_json1.0.154。依赖不用范围、latest、强装peer或ignore peer冲突。完整图由package-lock.json（257条含根）和Cargo.lock（19个registry包、2个本地成员）固定。

本轮官方源核对所有冻结版本均可获得；Node归档官方SHA256验证后解压到`.tools/`。Rustup安装精确工具链及rustfmt/clippy/WASM目标，不切换用户默认工具链。CLI使用`cargo +1.99.0 install ... --version 0.2.129 --locked --root .tools/wasm-bindgen`。首次npm ci成功安装231包，npm ls完整图合法；后续必须保持锁文件。

Windows运行入口使用PowerShell7和本机MSVC Build Tools/Windows SDK。详细步骤见[根README](../../README.md)。工具与生成文件均忽略；未初始化Git，也没有“已提交/已推送”结论。

正式Firefox158.0最小检查增加仅用于验收的geckodriver0.37.1及本地解压Firefox，未增任何npm/crate依赖或产品服务。Firefox归档匹配Mozilla SHA256；辅助工具来源/归档哈希见README和工程证据。Playwright157.0为补充自动化浏览器，独立于正式Firefox结果。

## 3. 质量入口

`scripts/task.ps1`只为单次命令设置固定工具PATH及本地Playwright目录；`env:check`核对精确Node、私有npm、rustc/Cargo和bindgen。`check`先构建所需胶水，再作独立类型检查，避免新环境缺生成声明；Vite构建不替代TypeScript。

| 入口 | 实际职责 |
| --- | --- |
| dev / preview | 127.0.0.1:5173开发 / 4173生产预览；端口占用失败 |
| build:wasm / build | locked Rust release→同版bindgen web胶水→最终WASM检查；产品和隔离harness构建及哈希/压缩体积记录 |
| typecheck / lint | strict TS（不跳过库检查）及ESLint/Hooks零警告 |
| format:check / format | 本次配置/脚本/测试/前端格式核对或修复；不触碰冻结资料 |
| check:rust | Rust fmt、native及WASM clippy零警告、workspace test，全用精确工具链/锁 |
| test:fixtures / test:schemas | 原02.4资料检查和27包Schema，保留document-model证据级别 |
| test | Vitest检查最终WASM内存声明/features/imports，不伪造C运行 |
| test:browser | Chrome/Edge及Playwright Firefox的3×3工程场景 |
| test:firefox-stable | 正式Firefox158.0同harness：页面、冷暖新实例、失败恢复；服务端口占用立即失败 |
| check | 上述构建、类型、lint、格式、Rust、资料、Schema、unit和Playwright统一退出码；正式Firefox额外独立运行 |

生成的WASM/glue、build报告和浏览器报告放在忽略目录；本次正式归档[工程证据](../验收/03.1-工程证据.json)。检查脚本不以失败或未测结果冒充passed。

## 4. 产物与数据边界

`.cargo/config.toml`仅对wasm32目标设置`--max-memory=134217728`。bindgen最终WASM实测minimum17/max2048页，非共享内存；8项features和2项胶水function imports已记录，无WASI/线程/进程/网络导入。三种正式浏览器均可编译Module、跨Worker克隆并实例化，超过上限grow拒绝；未真实耗尽128MiB，这留06.4。

产品首入口只加载React必要HTML/CSS/JS，不导入Blockly/CodeMirror/jsdom/Node runtime或引擎。引擎真实资源路径由隔离harness验证为hash资产，Module按需冷加载，暖检查保留1只读Module，每次新Worker/实例并最终终止。探针10秒是内部工具等待边界，不替代EXEC的一秒安全截止；正式请求/版本/取消/故障UI仍03.3/07.1。

运行不需要密钥。唯一示例变量VITE_BASE_PATH是公开静态部署路径，非法值明确失败；VITE_均浏览器可见，禁止秘密。`.env`和`.env.*`被忽略，只有.env.example例外。无外部执行、AI、账号、持久日志或学习数据库。

本机静态验收服务验证HTML no-cache、hash资产immutable、JS MIME与WASM application/wasm、/checks/ Worker路径及404。它不代表正式HTTPS/CDN压缩/缓存/托管日志验收或发布；静态资源仍需要网络，未实现离线缓存。
