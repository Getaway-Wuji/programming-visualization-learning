# DEC-P1-018：同数据双算法与统一回放

日期：2026-10-31；状态：16.2实施决议，验收结果另记。负责人：root / 完成16任务。

## 固定范围

仅配对原有 C 冒泡排序与选择排序，可互换左右；不新增算法、不翻译为 C++，不接入未验收案例。两者使用 input.c.int-sequence@1.0.0：0～30项、每项−999～999；空数组必须显式写[]。默认[7,-3,0,5,-3,2,9]。沿原输入随机协议，不要求预排序。

一份深冻结的规范输入形成两个相等但引用独立、各自深冻结的请求副本。两份源码分别由原 Rust 准备流程生成，各自具有独立上下文、源码修订、提交与运行身份；分别真实执行、解码校验和接收。全局引擎槽仍仅允许一个 Worker：顺序收集两次独立运行，绝不复用一次轨迹冒充两次执行。

## 预算与生命周期

“应用输入并准备”两侧共用一次触发时间；“运行两种算法”亦共用新的触发时间，各自执行仍受原1000ms墙钟截止、20,000步、1,000,000 fuel、请求64KiB、源码32KiB、结果16MiB和WASM128MiB约束，不延长第二侧截止。准备与执行为两个明确操作。首帧同步提交也计入执行截止。P1只增加双轨迹同时保留的上限：每侧最多一份16MiB结果，合计至多32MiB编码结果；状态恢复仍逐轨迹沿原检查点，不按步骤复制整条轨迹。保存、DB、引擎及EXEC/STEP版本均不变。

准备任一侧失败则整组未就绪，不自动运行。执行一侧失败时保留该侧真实有效前缀/诊断，另一侧仍在共同截止内独立尝试；不得把局部成功称为整组成功。取消使当前及未启动侧停止，保留已经最终接收的侧，丢弃未最终接收的暂呈状态；不伪造Rust终止。输入文字、随机种子、长度、生成、重置或算法变化立即使整组旧源码、结果、身份、回放计时器失效；离页、清档同样失效，晚到回调不可恢复。取消后须重新点击运行，无自动重试。视图开合不运行。

## 对齐与指标

统一游标k从0至max(L,R)，每拍各前进一个真实原子步骤，侧游标min(k,该侧长度)。短侧末态保持，长侧继续；回退完整恢复两侧状态，直到统一游标低于短侧长度才离开其末态。统一播放、暂停、步进、后退、跳转、重播和0.25/0.5/1/1.5/2/4倍速；调速只改变回放间隔，不影响执行或逻辑计数。不可暗示两侧同拍属于相同算法阶段。

计数直接取Rust轨迹当前state.counters；比较包含循环/下标/控制的关系与相等运算，标量写入含初始化、循环变量与临时变量，数组写入含初始化及同值写入；交换仅为Rust验证的交换观察，关联写入不重复计数。空逻辑数组仍有模板容量1占位初始化，不冒称零写入。不给出前端重算的排序、计数或性能排名。

复杂度按实际模板：冒泡无提前退出，最好/平均/最坏比较量均Θ(n²)，严格大于才相邻交换，稳定；选择固定扫描，均Θ(n²)，最多n−1次实际交换，不稳定。两者辅助空间O(1)（不含输入数组及教学轨迹）。动画时长不当算法效率。
