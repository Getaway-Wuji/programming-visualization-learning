## 1. 决议结论

**一期开发联调和正式 Web 交付统一采用：React 页面 + 浏览器 Dedicated Worker 中的 Rust/WASM 轻量 C 子集解释器 + 静态课程/算法资源。** Rust 编译目标为 `wasm32-unknown-unknown`；具体工具链、绑定方案和版本由 01.4 核验冻结。

学习者打开网页即可使用，不需要安装或启动 Rust 本机执行服务。开发者仍需构建工具链和本机静态开发服务器；后者只提供页面/脚本/WASM/内容文件，不接收学习者执行请求。正式部署使用 HTTPS 静态站点，托管平台尚未选定，本次不发布站点。

原始代码、积木结构、输入、随机种子、轨迹、输出和诊断在浏览器中生成/处理；执行适配不把这些内容上传到执行服务器。学习进度、积分和设置经统一本地存储接口保存，Rust 核心不读取或持久化学习档案。

本地执行是本产品需要实现并验证的数据规则，不是 WASM/Worker 自动提供的隐私保证。页面与公共资源首次加载仍需要网络；一期不承诺断网首次打开、刷新/重开后离线或完整离线安装。

## 2. 三种形态比较与取舍

| 维度 | 浏览器 + 本机 Rust HTTP | 浏览器 + 远程 Rust HTTP | 浏览器 Rust/WASM + Worker（采用） |
|---|---|---|---|
| 实际执行位置 | 用户设备的独立 Rust 进程 | 部署方服务器上的 Rust 进程 | 用户浏览器的 Worker 中，由 Rust 解释器执行 |
| 代码/输入路径 | 浏览器经回环 HTTP 临时到本机进程；离开浏览器 | HTTPS 临时到远端；即使不落盘也已经离开本机 | 主线程与 Worker 间本地消息；不上传执行服务 |
| 学习档案 | 仍须只在浏览器保存，不随请求发送 | 同左；服务端不得维护档案/会话 | 浏览器统一存储层；Worker 不访问档案 |
| 学习者启动成本 | 安装/启动本机服务，处理端口和连接问题 | 浏览器直接用 | 浏览器直接用，需成功加载模块 |
| 正式网页部署 | 在线网页依赖每台设备的本机服务；另有端口、跨源和服务分发工作 | 需要 Rust 服务容量、请求治理和隐私说明 | 静态资源托管；计算由各浏览器承担 |
| 取消与故障 | 客户端取消还需真正终止服务端运行 | 同左，并处理网络/排队/旧响应 | 主线程终止 Worker；处理模块/Worker/消息故障 |
| 主要代价 | 影响“无需环境配置”的学习路径，且不直接解决普通网页交付 | 增加运维和传输边界，不满足输入留在本浏览器的选择 | 冷加载、WASM 编译、消息复制和设备资源差异须实测 |
| 本次安排 | 不建设产品执行服务；原生核心可用于开发测试 | 不启用，也不作为自动降级 | 开发、联调、一期交付同一路径 |

守则推荐先用本机 Rust 服务是落地建议，并同时允许 01.2 改选浏览器 Rust/WASM。本次直接采用后者，理由是它同时保留纯网页入口、本地输入边界和 Rust 真执行，避免先实现再废弃一套本机 HTTP 适配。该取舍是对 SRS §2.3“Rust 后端形态”的显式调整，**保留 Rust 执行核心，取消独立执行服务的交付要求**。

远程 Rust 服务将来若重新启用，必须先升版本决议，重新确定临时传输、日志、保留、容量、取消及界面告知；不得静默回退或宣称代码从未离开本机。三期 AI 的外部调用只由 19.3 单独决策，本决议不授权其数据发送。

## 3. 核心、适配与内容职责

| 组件 | 责任 | 禁止混入的能力 |
|---|---|---|
| Rust 解释器核心 | 词法/解析/语义检查、受限执行、虚拟内存、轨迹和结构化诊断；输入与种子决定结果 | 运行原生用户 C、GCC、宿主命令；用户文件/进程/网络/任意库；读取学习档案 |
| WASM 绑定及 Worker | 调用同一 Rust 核心、验证调用边界、返回结果；每个实例仅拥有本次运行数据 | 第二套 C/算法实现；把用户 `printf` 输出写入宿主控制台；存档/网络上报 |
| React 执行适配 | 运行身份、源码/输入版本、Worker 生命周期、主线程截止监控、结果校验和错误呈现 | 用 JavaScript 动态执行用户程序；把宿主异常伪装成 C 语法错误或正常结束 |
| 播放器/视图 | 消费真实 Step DSL，恢复相同游标的变量/数组/输出等状态 | 在前端重新算算法；回退/重播重发首次奖励 |
| 内容读取/配置流程 | 版本化静态课程、题目、模板、解析、映射；构建/发布时校验引用；主线程读取必要公共资源 | 管理账号/后台、以静态样例冒充真实执行 |
| 本地学习层 | 接受最少学习结果事件，统一记录进度/账本/目标/设置 | 将整条轨迹、源码或输入自动作为学习档案上传或保存 |

Rust 官方说明 `wasm32-unknown-unknown` 是面向最少宿主假设的目标，部分操作系统相关标准库能力不可用。因此核心须与文件、线程等宿主依赖分离，计时通过受控适配提供，C 输出走虚拟输出/轨迹；不能依赖 Rust 宿主 `println!` 作为教学输出。[Rust 官方目标说明](https://doc.rust-lang.org/stable/rustc/platform-support/wasm32-unknown-unknown.html)

Worker 本身能使用网络和 IndexedDB，故“禁止上传/存档”必须由应用边界、WASM 导入清单和发布验证落实。加载完成后执行 Worker 不读取课程网络资源、不调用存储；必要题目配置由主线程传入，学习档案不传入。[MDN Worker 能力说明](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers)

## 4. Worker、取消与资源策略

1. 一期每个页面标签最多一个活动执行 Worker。每次运行使用隔离实例；更换源码/输入、切换案例、取消或退出当前题目/案例临时上下文时废弃旧运行，终止旧 Worker。完成结果被主线程接收后也释放该实例，播放器保留已验证轨迹供前后单步。同一题目的工作区→复盘→返回属于同一仅内存的临时上下文，保留版本绑定的提交快照、有效轨迹和工作区当前版本；内部页面切换不清空这些数据，不把已接受结果改为取消。内部切换若取消尚在计算的 Worker，也不得冒称已有完整复盘；具体上下文关联由 02.2/09.3 定义。
2. 取消不能只发送消息给忙于同步 WASM 的 Worker。主线程先将运行标记为取消/失效并停止等待，再直接终止 Worker；不等待 Worker 执行收尾或回传取消终态。下次运行重建实例，取消不产生通过/奖励。
3. 取消与完成竞争：主线程已经接受并验证的终态不能被后来的取消改写；尚未接受终态时取消生效，排队的旧结果被忽略。具体身份字段、状态枚举与首个终态处理由 02.2 冻结。
4. Rust 内部始终检查语法深度、执行步数、虚拟内存、输出和轨迹预算；适配层监控运行截止，必要时终止 Worker。具体数值由 01.4 冻结，不能用 Worker 替代解释器限制，也不能将虚拟内存配额当浏览器实际总内存上限。
5. 源码/输入体积在调用前检查，Rust 再校验；结果在序列化/跨线程传递前受限，主线程验版本、身份、大小和轨迹结构后再交播放器。预算还应计入绑定缓冲、消息复制和主线程状态投影，具体测法留 01.4/06.4。
6. 不要求 SharedArrayBuffer、WASM 多线程或共享 Worker；二期双算法用两个独立 Worker/运行实例，组合预算在 01.4 和 16.2 明确，不共享可变程序状态。
7. 可在页面内保留公共已编译模块，给新 Worker 实例复用；MDN 展示了向 Worker 发送 `WebAssembly.Module` 的方式。具体绑定是否支持该路径及冷/热开销由 01.4/03.3 验证，不能凭此宣称已达到 500 毫秒。[MDN 模块复用示例](https://developer.mozilla.org/en-US/docs/WebAssembly/Reference/JavaScript_interface/Module)

`Worker.terminate()` 会立即停止 Worker，不提供操作收尾机会；因此终态和失效标记由主线程管理，不能指望 Worker 的清理代码可靠执行。[MDN 终止行为](https://developer.mozilla.org/en-US/docs/Web/API/Worker/terminate)

浏览器调度/页面挂起会影响墙钟监控，不能宣称任何挂起场景都精确在一秒终止。暂停页面恢复时，已超期运行先失效/终止，再接受新操作；安全预算、冷加载和正常性能门槛分别定义，首屏 ≤ 2 秒与执行响应 ≤ 500 毫秒继续保留。

## 5. 失败、部署与离线边界

模块下载/编译/实例化失败、Worker 建立失败/异常、消息或版本不匹配属于执行基础设施故障；C 检查/运行错误属于程序诊断；预算耗尽、用户取消和正常完成各有独立结果。基础设施失败不得拼造成功 Step DSL，也不得自动转远程执行。界面提供可理解反馈、重试与返回入口。

所有页面、Worker、WASM、字体和课程资源采用受控同源静态资源；发布构建对齐内容、协议与执行核心版本。`application/wasm`、资源路径、页面及 Worker 的 CSP/加载限制和 SPA 导航回退由 03.1/03.3 实测。只允许受控 WASM 编译权限，不为此开放用户 JavaScript 动态执行；CSP 区分 `wasm-unsafe-eval` 与通用 `unsafe-eval`。[MDN CSP 指令说明](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/script-src)

模块与内容只作为公共静态文件缓存；不建设一期 Service Worker/PWA 离线功能。已加载模块/内容的当前页面有条件继续本地运行，不等于断网重开所有课程可用。也不以直接双击本地 HTML 作为交付方式；本机静态预览仍是服务器提供文件，区别于 Rust 执行服务。
