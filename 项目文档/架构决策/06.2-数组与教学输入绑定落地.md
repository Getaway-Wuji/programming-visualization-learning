## 数组运行

沿用同一CheckedProgram、ResolvedReference、整数/格式原语和迭代调度。execute取消06.1临时UnsupportedRuntimeFeature，直接返回Execution；唯一既有Rust测试消费者同步调整，没有新增WASM导出或公共协议。只有真实analyze产生且未被修改的CheckedProgram可调用，手工构造/反序列化AST不是边界输入。

RuntimeState新增arrays与live_bytes，保留标量variables；两表的对象共用单调id、所属scope和声明NodeId。RuntimeArray有length、default_value和按下标排序的稀疏cells；缺元素继承默认，None为未初始化。所有逻辑槽都占4字节，压缩表示不减虚拟活存储。对象数字身份不是宿主地址/STEP字符串ID；本轮不伪造完整allocator/frame/control。

| 动作 | 实际规则 |
| --- | --- |
| 声明 | 实际执行到声明才分配；用u64计算全部活字节+N×4，≤1048576后才能转usize和建立None数组；巨大声明不会先建立宿主大数组 |
| 初始化 | 无初值每元素独立None；非空列表整次成功才提交default=0与非零例外，余槽补0；按全部N槽扣基础工作量，失败保留已声明但未初始化对象 |
| 读取 | 使用索引base的真实声明绑定，先求下标并按0≤index<N检查，再读元素；实际None报E_UNINITIALIZED |
| 赋值 | 先计算并验证左侧位置，再完整求右值，成功才写；左索引错误优先于右值错误，赋值不读取目标旧元素 |
| 边界 | E_INDEX_BOUNDS定位实际失败Index节点；巨大/负int下标不会转无符号后绕回；逻辑n不代替声明N |
| 短路/输出 | 未选右侧不读取数组/不报越界；printf参数左到右全部成功才整次追加，沿用16KiB累计UTF-8限制 |
| 销毁 | scope退出、break/continue及return同时销毁其标量/数组并释放live_bytes；重新进入同一声明有新id和新初始化状态 |

MemoryLimit归ResourceLimit，stage=execute、dimension=liveBytes，分配前拒绝不会出现半个新对象。DiagnosticDetails.attempted内部改u64，精确表示wasm32上`2147483647×4`的候选字节；原JSON整数/字段/错误码不变。IndexBounds为ProgramError，与逻辑输入约定错误区分。完整初始化/销毁的原子提交继续为06.3真实轨迹提供基础。

## 教学输入实例

input模块只接已通过原CONTENT包校验的program/spec实体；它再次核输入相关字段、当前精确版本/Ref、配置关系和绑定，不代替全包引用/JSON重复键/发布审核。prepare校验实际输入后检查sourceExample与exampleInput一致，在主main受控输入前缀中按真实AST声明范围替换；不全局查找/替换名字，不把原始字符串直接拼入C。

PreparedProgram保存同一完整source、重新analyze所得checked、ResolvedBinding和SourceEdit，并通过只读getter提供。每个ResolvedBinding给binding_key、最终declaration_node、最终byte_range；每个SourceEdit给original_range/generated_range，编辑间所有原字节不变。范围按原始UTF-8字节计算，保留中文/补充字符与CRLF；最终nodeMap来自生成源码的AST，不沿用长度变化前的坐标或节点ID。当前未实现Blockly blockMap，不能把这份输入声明映射冒称10.2完整生成器。

verify_instance单独核对已显示/提交的source与BindingMapEntry，不修改源码：确认main前缀的原目标顺序、名字/类型、容量/逐项字面初值和精确声明范围；map必须完整且key唯一，不能指向同名内层对象或其他声明。派生n与循环计数输入n的写保护按ResolvedReference声明身份扫描全部赋值路径，含不执行分支/return后；同名内层变量不误禁。普通源x/k可后续赋值，数组元素可修改。真正的判题依赖/结构目标留09.3，不把输入绑定合法当题目通过。

输入仅接受配置字段集合、整数值及闭区间，序列长度0..30，更新题至少1项且合法k，loop n0..30。非整数/字符串/未知字段/缺失、域外/过长/非法下标拒绝；二分非递减要求明确报E_INPUT_ORDER，绝不排序。非空数组容量=逻辑长度且逐项等实际输入；空序列生成`int n = 0; int values[1] = {0};`。空输入读取values[0]在C层合法，但不因此满足教学逻辑范围；不存在隐藏stdin/scanf或前端结果算法。

正式case/exercise边界后续必须走相同输入/绑定复核，不能只调用裸execute并声称请求合法。prepare/verify是内部适配，不是正式EXEC封套：context/source/submission身份、接收/旧运行失效与浏览器Worker调用留07。
