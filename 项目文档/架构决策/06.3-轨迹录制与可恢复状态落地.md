# 06.3 轨迹录制与可恢复状态落地

日期：2026-10-16；范围：06.3；沿用 P0-C V1.0、STEP-01 / DIAG-01 / JSON-INT-01 1.0.0，不修改冻结契约。依据[任务包](../任务包/第06步-实现受限执行与真实轨迹.md)、[STEP 状态](../契约/02.2-StepDSL状态与源码映射.md)、[DEC-005](./02.2-StepDSL可逆与编码决议.md)及[06.2 交接](../交接/06.2-交接.md)。

## 一、执行与录制

`semantic::analyze` 的同一 `CheckedProgram` 可以交给 `runtime::execute` 或 `runtime::execute_traced`。两者共用一个 Rust Machine、求值器、整数原语和作用域调度；后者返回 `TracedExecution { execution, trace, node_map }`。轨迹在真实动作成功时提交，不再次运行 C，不由前端计算算法。输入适配的最终源码仍先经原静态检查；其节点映射就是本次轨迹的节点映射。

主帧和主作用域并入 `program.enter`；声明与初始化分成两个动作。每条赋值、完整条件、块进入/退出、完整 printf、break/continue、return 和真实空语句按 STEP-01 边界产生一步。for 的 init/update 复用原有声明/初始化/写入动作。隐式返回定位为闭括号锚点的 synthetic implicit-return。没有执行的分支与短路右侧不产生读取或比较。

录制先保存本次候选动作的临时状态、调度与观测元数据，执行和预检全部成功后才加入历史；错误或录制上限拒绝整个候选。之前成功的声明保留为未初始化对象，失败动作的输出、写入、销毁、观测和计数不进入成功历史。已消耗的工作费用不回退。失败返回可恢复的 prefix，正常返回为 complete；终止本身不增加步骤。

## 二、状态与增量

轨迹显式保留 frames/scopes/objects/control/allocator/output/counters 七项。ready 初态无帧/作用域/对象，nextNodeId 指向 main；逻辑地址从4096起、每槽4字节，动态 o/s/f 身份及地址在本次运行单调递增。销毁只释放 liveBytes，恢复时还原有序记录与完整 allocator。这些地址只作教学投影，与宿主真实地址无关。

标量和数组通过同一对象模型展示；数组 defaultValue=null 表示未初始化，初始化列表转换为 defaultValue=0 与有序稀疏例外。普通槽写使用 cell，包括写相同值；数组整次初始化使用同一对象的完整 record 变更并计所有逻辑槽的写数。scope 和 frame 引用保持闭合，为后续栈帧/内存语义保留字段，当前只支持 main。

Recorder 只保留必要的 record/cell/control/allocator/output/counters 差异，以及 cursor0 和每128步的完整检查点；不保存每一步完整状态。短暂候选快照用于原子回滚，提交后释放。output 变更记录 UTF-8 字节长度和完整追加文本，逆操作核对后缀后删除，不切断中文。

## 三、观测与计数

读取、运算、条件决定、短路观测来自实际求值顺序。comparisons 只统计六种关系/相等运算；初始化和赋值按实际 int 槽计 scalarWrites/arrayWrites，相同值写仍计数；swap 另计，不能重复增加元素写数。计数由增量精确恢复，播放器无需重算。

swap 标注识别同一数组两个不同下标的实际读值经标量临时量保存后，完成两次互换写入的情形。版本和来源关联防止被改写的旧临时量、跨对象、纯字面量巧合或自交换被误标；不同下标的等值互换仍可识别。标注附在第二次真实写入，引用两次真实 seq，不另造步骤。此识别范围不承诺任意等价 C 改写都被标注为 swap。

## 四、恢复与校验

`trace::apply_step` 前进按 changes 顺序，后退按逆序交换 before/after；候选在副本中完整校验，失败不会部分修改调用方状态。`validate_trace` 核对版本、封闭词汇、节点/对象关系、顺序、前置值、观测/计数与检查点投影；坏轨迹整体拒绝。`restore` 先验证轨迹，再从最近前置检查点应用至多127步，检查点不是未经验证的真相；当前内部 API 每次 restore 都验证，后续08可在已验证不可变轨迹上缓存验证结果。

## 五、预算与后续边界

本次录制基础保护包括20000步、轨迹 JSON 保留体积上限16MiB减65536字节、候选快照/状态投影的基础工作计费，以及既有输出/活内存保护。Recorder 增量计算新增步骤和检查点编码大小，不为每个候选重编码全部历史。该内部体积余量尚不是正式 EXEC 信封的完整编码验收；全阶段共享燃料、收尾、精确消息边界、取消和截止仍由06.4完成，不承诺本次端到端性能。

浏览器 WASM 入口仍为 build_probe、interpreterReady=false；本次不改导出或前端。07负责正式 EXEC 生命周期与身份校验，08负责播放器，09负责判题/学习事实，P1再扩展用户函数/指针/内存视图。Rust 不持久化用户源码、轨迹或学习档案；验收落盘仅包含开发者公开测试程序。

实际验证与限制见[验收](../验收/06.3-轨迹与恢复验收.md)和[交接](../交接/06.3-交接.md)。
