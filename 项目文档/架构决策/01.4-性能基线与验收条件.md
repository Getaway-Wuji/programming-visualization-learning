# 01.4 性能基线与验收条件

决议：**DEC-004 V1.0 / PERF-BASE-01 V1.0**；日期：2026-10-14。依赖DEC-001—003及P0-C V1.0。保留首屏≤2秒、完整结果/轨迹响应≤500毫秒；采纳60fps、连续30秒观察建议。本文冻结未来实测条件，**当前没有产品性能实测结果**。

## 2. 计时边界与通过条件

所有时间使用同一页面单调时钟关联run身份；Worker内细分时间单独计量，不能直接减去两个上下文的未对齐绝对时间。测量标记只含技术元数据，不记录原始代码/输入/输出/轨迹，遵循DEC-001保留规则。

| 指标 | 起点→终点 | 门槛/含义 |
|---|---|---|
| T首屏 | 导航开始→首屏真实必要内容已呈现、核心交互可响应并完成一次绘制 | ≤2000ms；只有骨架、空壳或仍在挡住操作的遮罩不算 |
| T工作区入口 | 直接导航工作区→内容/输入/生成源码已就绪，运行入口能接收有效点击或键盘提交 | ≤2000ms；这是工作区首屏检查；Module可尚未准备，但必须能接受提交并显示等待 |
| T复盘入口 | 已有真实提交会话中，有效“查看本次复盘”触发→同页路由的完整可操作复盘画面绘制 | ≤2000ms；保留原提交身份/轨迹，单列前置加载状态，不标全新上下文冷首屏 |
| T模块准备 | 本次Module准备开始→可供Worker实例化的编译Module就绪 | 单独报告；首次按需加载发生在提交之后，计入T执行，不增加免责区间 |
| T执行端到端 | **用户提交有效运行意图的点击/键盘触发**→完整真实结果/轨迹收到、身份/契约校验通过、初始状态投影已绘制且可播放 | ≤500ms；包括入口校验/绑定、新Worker、冷资源下载/编译/实例化、Rust、编码/传递、主线程校验和初始画面 |
| T Rust核心 | Rust解析入口→解析/语义检查、执行、完整轨迹及结果编码完成 | 同时报告各阶段及总值；包含在T执行内，不能替代500ms端到端门槛 |
| 安全截止 | 同一有效提交起点→1000ms截止 | 超限必须使run失效、终止已有Worker并禁止迟到成功；不把1秒安全限制当成正常性能达标 |

“接受请求”可以是状态名，不能把计时起点后移到输入绑定完、Module准备好或Worker启动后。预检发现无效输入/超限时报告拒绝响应，不把拒绝样本混入成功执行500ms统计。结果结束时不仅获得算法最终数字，还必须拥有契约要求的完整可逆轨迹；提前发一个完成信号不算通过。

入口检查覆盖01.1的7个逻辑页面。PAGE-06案例模式可直接导航作冷/暖首屏；真实练习复盘依赖内存提交，须先由真实Rust运行建立会话，再测T复盘入口，不能整页重载后注入假轨迹或持久化轨迹补上下文。其他可直接进入的页面测真正导航首屏，内容/本地学习档案状态固定。首页正常路由不得为首屏加载Blockly、CodeMirror或全部WASM；工作区按需加载相关模块。资源体积只是预算，真实入口时间仍需实测。

## 3. 冷/暖状态与重复方法

| 场景 | 必须控制的状态 | 重复及判定 |
|---|---|---|
| 页面冷启动 | 每次新隔离浏览器上下文，HTTP/磁盘/代码缓存清除，不使用Service Worker缓存，固定学习档案 | 各页面/浏览器5次；每次T首屏及工作区适用值≤2秒 |
| 页面暖加载 | 同版本资源已有HTTP缓存，新页面；固定同一档案，记录缓存命中和304/实际传输 | 同上各5次；冷暖分表，不把缓存值当冷值 |
| 真实提交复盘 | 每次通过真实工作区提交建立内存会话，再由查看复盘进入同页路由；记录已加载资源/缓存和run身份 | 每种受测复盘/浏览器5次，T复盘入口≤2秒；不算全新上下文冷启动 |
| 执行冷Module | 全新上下文/缓存，工作区就绪后的**首次有效运行**；点击前没有预编译或预实例化该Module | 每个受测工作负载/浏览器10次，T执行每次≤500ms |
| 执行暖Module | 页面已经保存同版本编译Module，但每run仍创建新Worker/实例，恢复相同输入和程序 | 同上各10次；不能保留可变旧Worker当加速结果 |

首次运行按需准备引擎，使冷Module测量是实际产品路径。若后续改为自动预编译或等Module才开放按钮，须登记影响：工作区等待全部纳入2秒；已有Module的500ms只能标暖，不能冒充冷Module通过。不得通过延迟“接受”提交隐藏等待。

保存每次测量值、样本数、min/中位数/p95/max、缓存状态、构建/内容哈希和失败详情。门槛以**每个有效样本及max**判定，不能用平均值或p95盖过超标。外部干扰样本只有具备明确记录才可剔除，并保留原记录和补测，不能自动丢弃慢样本。功能错误、异常退出或截断轨迹均不算成功样本。

随机数据使用公开固定种子夹具；自定义数据使用同样校验/执行路径。教学域内所有合法最大负载必须在本预算内完整执行，特别是30项排序。不为凑20,000步或500ms缩小既定n=30范围、删必要步骤或只返回终态；优化/版本化调整按[预算变更规则](./01.4-资源预算表.md)处理。

## 5. 动画、取消与内存观察

动画目标60fps，固定前台60Hz显示、连续30秒真实播放；P0测单视图30项，P1测两视图各30项。记录实际绘制帧/浏览器帧轨迹、视觉连续性、帧间隔和主线程长任务，rAF回调频率不能单独证明画面以60fps呈现。取30秒稳定段，另保存启动阶段。目标细化为：应用每帧“取轨迹→更新状态→提交画面”工作时长p95≤16.67ms，rAF间隔p95≤20ms，>33.3ms间隔占比≤1%；同时核查实际绘制帧、掉帧和界面响应。59.94Hz等实际刷新差异原样记录，不改名为已实现60fps。任一细化门槛失败或存在明显卡顿均登记缺陷，不以平均FPS通过。

取消、改码、切换题目或截止在处理事件时立即失效；前台非阻塞条件下，从有效取消事件处理开始≤100ms回到可重新运行的稳定状态。1000ms是主线程截止与Rust周期预算检查的合作约束；浏览器后台挂起/主线程暂停不保证恰好1秒触发，恢复后先检查过期再接受结果。若Worker尚未创建，仍使未完成下载/编译任务失效，可取消的下载同步取消；恢复/旧Promise不得再启动该run或提交迟到成功。

分别记录WASM线性内存峰值/最大页数、结果编码字节数、存活Worker/轨迹数量和可用的浏览器进程/JS堆峰值。128MiB线性内存不是整页或Worker总内存配额。执行/取消交替50次后，旧run、订阅和Worker不得存活；GC时间不确定，观察回收趋势并记录可用工具，不能仅凭一次GC后的堆值声称无泄漏。P0只有一个当前运行/轨迹；切换工作区与同题复盘共享该内存会话，不复制整条轨迹。
