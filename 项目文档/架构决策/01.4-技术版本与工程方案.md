## 1. 结论与取舍

采用 **React 19.3.0 + TypeScript 6.0.3 + Vite 8.3.4** 的静态单页应用；Blockly生成P0-C代码，CodeMirror 6展示源码；Rust 1.99.0编译为WASM，由每次运行新建的Dedicated Module Worker执行。声明式导航采用React Router，不启用其服务端/全栈框架模式。学习记录仍由浏览器本地保存。

开工日[React官方版本页](https://react.dev/versions)列出的稳定版是19.3.0；采用稳定发布通道，不用Canary/Experimental。[Node官方发布表](https://nodejs.org/en/about/previous-releases)及[发布清单](https://nodejs.org/dist/index.json)支持选择24.21.0 LTS（Krypton），而非本机现装的26.5.0。Rust选[2026-10-01发布的1.99.0](https://blog.rust-lang.org/2026/10/01/Rust-1.99.0/)。这些是选型依据，并不表示组合已经安装或构建成功。

TypeScript当日latest为7.0.2，但[typescript-eslint 8.71.2元数据](https://registry.npmjs.org/typescript-eslint/8.71.2)声明支持`>=4.8.4 <6.1.0`，故固定为已发布的6.0.3。保留可兼容的检查链，不用忽略peer冲突、强装或关闭类型检查解决版本问题。

## 3. 积木、源码与执行边界

Blockly负责20类P0积木及工作区。它的[内置生成器仅覆盖五种语言](https://docs.blockly.com/guides/create-custom-blocks/code-generation/overview/)，没有现成的C生成器。10.2须实现项目自己的C生成器，按DEC-002处理运算优先级、作用域、转义、main、有限printf及源码映射；不以改写JavaScript文本生成C。生成结果只能交Rust解释器。积木事件只能改变代码/输入并使旧运行失效，不能在前端算算法结果。

CodeMirror使用上述四个原生包，以薄React组件包装生命周期。一期源码只读：按[官方只读示例](https://codemirror.net/examples/readonly/)同时设置state的readOnly及view的editable，并保留可聚焦、选择、复制和源码定位能力。高亮语言包识别C/C++不代表解释器支持C++或完整C；诊断与可执行语法以P0-C/Rust为准。二期/三期的编辑开关及双向转换另按13.1、17.3契约实现。

Rust核心与WASM边界适配分离。按[wasm-bindgen部署说明](https://wasm-bindgen.github.io/wasm-bindgen/reference/deployment.html)使用`--target web`生成ES module胶水并显式初始化；不另装wasm-pack或WASM打包插件。WASM作为带版本/内容哈希的静态资源；Vite负责URL及发布路径，胶水负责所需imports，不能用Vite裸WASM的`?init`直接替代wasm-bindgen胶水。

Worker采用[Vite支持的静态构造形式](https://vite.dev/guide/features.html#web-workers)：主线程执行适配使用`new Worker(new URL('./…worker.ts', import.meta.url), {type: 'module'})`，new URL直接放在new Worker构造器内，options为静态值；不在Worker内部另建嵌套Worker。每run独立Worker和WASM实例；页面可保存一个只读编译Module供后续Worker使用，clone及胶水init路径须03.3真测。首次有效运行默认按需加载/编译；之后可复用Module，禁止复用可变执行状态。正常完成校验后或取消/失效时均释放Worker。主线程终止Worker，不依赖同步WASM能接收取消消息；截止期间尚未结束的加载也必须失效。

不启用SharedArrayBuffer、SharedWorker、WASM线程或原生用户程序。Rust版本固定其标准库及默认WASM特性；03.1记录实际产物features/imports，并在三种浏览器验证。不得用“当前Rust支持WASM”代替实测浏览器兼容。单实例线性内存最大128MiB，实施办法及其他预算见[资源预算](./01.4-资源预算表.md)。

React组件卸载及StrictMode重建须销毁Blockly工作区、CodeMirror视图、订阅和失效运行，符合[Effect清理机制](https://react.dev/reference/react/useEffect)。React Router采用[声明式模式](https://reactrouter.com/start/declarative/installation)；03.2固定实际路径并验证刷新/返回，BrowserRouter需静态站点回写index.html，不能回写时采用HashRouter并记录。均不引入执行HTTP服务。

## 4. 可复现落地要求与目录建议

03.1先确认工程布局，建议`web/`存React、`engine/`存Rust核心/适配、`content/`存公开课程数据、`tests/`存跨端验收样例；这四个目录现在不存在，本文不把建议视为已建目录。契约来源以02.1—02.4最终文件为准，不在前端、Rust和内容各自重新定义协议。

03.1须完成：

1. 固定Node 24.21.0/npm 11.19.0和Rust 1.99.0（minimal profile及所需target、rustfmt/clippy）；核对工具版本后再初始化。直接npm版本不用`^`/`~`，Rust直接crate用精确`=版本`；CLI安装同版且locked。
2. 生成并提交package-lock.json、Cargo.lock及实际工具链/构建配置；全传递依赖和integrity由锁文件固定。干净环境执行npm ci、Cargo locked构建；不使用create-vite@latest生成未经核对的依赖树。
3. 质量入口包括独立TypeScript检查、ESLint/格式检查、Rust fmt/clippy/test、Vitest以及生产构建和真实WASM最小流程。[Vite仅转换TypeScript、不作类型检查](https://vite.dev/guide/features.html#typescript)，构建成功不能代替类型检查。
4. 保存锁文件和产物哈希、工具/浏览器版本、WASM内存上限与features、静态MIME/缓存/Worker路径检查，以及冷/暖测试结果。先验证真实纵向调用，再据此验工程；具体正常/失败样例由02.4确定。
5. 更新依赖须登记DEC-003补充/新版本、影响任务与重新验证，不能以latest自动漂移。增删路由、协议库及根配置由指定负责人合入。
