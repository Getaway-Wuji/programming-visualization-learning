# 06.1 基本运行状态与控制流程落地

2026-10-16（Asia/Shanghai）；Codex-06.1主窗口协调。前置[05.3交接](../交接/05.3-交接.md)已验收；任务为[06.1](../任务包/第06步-实现受限执行与真实轨迹.md)。P0-C V1.0、DIAG/STEP/EXEC 1.0.0、原规模与资源上限不变。这里只落实Rust核心标量执行，不引入公共契约或新增浏览器导出。

## 接口和状态

先`semantic::analyze(&str)`得到当前源码的CheckedProgram，再`runtime::execute(&checked)`。CheckedProgram是内部受信结构，必须来自原静态检查且不被改写；公开Rust字段不等于允许导入外部AST，未来WASM边界仍须从源码做完整检查。语义错误仍在analyze阶段返回，未执行分支/短路右侧/return后也受静态检查。

execute成功启动返回Execution，含state、outcome、work_used。outcome为Completed {exit_code}、ProgramError {diagnostic}或ResourceLimit {diagnostic}；非零exit_code不误报C程序失败。execute外层Err为UnsupportedRuntimeFeature，给出首个数组声明的内部NodeId及原始byteRange。数组语法在05.3已支持，本轮统一在执行前检查全部声明并作内部能力拒绝，包括不可达数组；它不是E_UNSUPPORTED_SYNTAX、不是正式EXEC rejected包，也不能当作完整P0-C运行。

RuntimeState含有序scopes、按静态声明NodeId索引的活variables、output及单调next_scope_id/next_object_id。scope记录自己的声明节点；变量有动态id、声明节点、scope_id、name和Option<i32>。None表示尚未初始化，不能变成0。状态不持有宿主地址、文件/网络/进程或学习档案；动态数字ID不是公开STEP的o/s/f字符串，也不是教学虚拟地址。每次execute从空状态和ID=1开始，循环同一声明重入有新动态对象ID，退出scope删除对应变量。

## 求值与控制

| 行为 | 实施规则 |
| --- | --- |
| 声明 | 先提交未初始化变量，后求初值并成功写回；`int x=x`读新x，初始化失败仍保留该None对象 |
| 名字/遮蔽 | 使用05.3的ResolvedReference声明身份找活对象；不按字符串找最近同名替身，内层退出后外层对象仍原值 |
| int32 | 复用integer原语，不浮点/回绕；`-7/3=-2`、`-7%3=-1`、`7%-3=1`；MIN/-1的除及余均溢出 |
| 求值顺序 | 普通二元运算和printf参数左到右；`&&`左假/`||`左真先返回0/1，右侧不求值；比较/逻辑结果为0或1 |
| 失败写入 | 右值全部成功且基础工作量检查通过才写目标；未初始化、除零、溢出均在实际表达式范围诊断，失败时原值不变 |
| if/while | 0假、其他int为真；只执行选定块，每轮while重新检查条件和建立体scope |
| for | 自有scope贯穿init/cond/body/update；空cond是真，每轮仍计工作量；body每轮新scope；continue退出体后执行update再cond |
| break/continue | 找最内层活动loop marker；先预扣整批scope/object销毁工作再清理，break同时退出for自己的scope并跳过update |
| return | 先求值；失败保留当前活状态，成功一次性销毁全部scope/变量并撤销后续任务；main末尾默认0 |
| printf | 使用05.3编译格式和已解码文本，全部参数成功后生成有界候选文本，再检累计UTF-8长度≤16384，一次追加；不写宿主stdout/HTML |

语句调度采用迭代Work栈和每块一个语句游标，宽块不在每次循环复制整组语句。loop marker保留break/continue各自目标调度长度及scope深度；嵌套jump按最内marker执行。表达式递归受原解析器独立astDepth≤64约束，不按动态循环次数递归堆栈。

错误不触发成功清理：失败初值保留新声明，失败return保留当前scope，失败赋值/输出保留已完成的真实前缀。退出批量预扣避免因基本工作量耗尽只删除一半scope。这里还没有STEP changes/逆数据、计数器、控制/allocator、checkpoint或正式完整状态；state只是06.2/06.3的内部起点，不能直接充当协议trace。

## 诊断与资源责任

新增使用既有DIAG码E_UNINITIALIZED/E_DIV_ZERO/E_INT_OVERFLOW，stage=execute、origin=rust，location为失败AST原始UTF-8 byteRange，无源码片段或宿主栈。E_FUEL_LIMIT/E_OUTPUT_LIMIT区分为ResourceLimit，details给dimension/limit/used/attempted，候选超限动作不提交。首错服从实际左到右路径；未运行错误表达式不产生诊断。

本轮基础MAX_EXECUTION_WORK=1000000覆盖运行访问、读、算术/判断、写、跳转/销毁和输出片段/UTF-8块，防止空循环/空for失控。work_used仅此基础运行计数，**不是完整run的stats.fuelUsed**；前置lex/parse/semantic和引用索引构造等仍未接统一meter。完整1000000总燃料、失败/比较/观测/映射/编码及4096收尾储备、steps=20000、liveBytes=1MiB、resultBytes、取消及1秒截止均由06.4在06.3真实轨迹基础上统一实现，不能把本轮guard或静态成功计数当全阶段预算通过。

16KiB是实际累计输出限制，恰好可用；超限前候选文本可临时超过16KiB，但有32KiB源码/静态格式参数数量约束且不反复持久追加。标量活对象数量受源码/词法scope约束；本轮未开展数组分配或虚拟内存预算验收。没有时钟接口/Worker正式执行，故不声称取消/截止或500ms性能达标。
