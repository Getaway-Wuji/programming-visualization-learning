# 01.4 资源预算表

决议：**DEC-004 V1.0 / BUDGET-P0 V1.0**；日期：2026-10-14。与[性能基线](./01.4-性能基线与验收条件.md)共同生效；采用[需求裁决](../需求覆盖与范围裁决.md)的初始建议并明确计量口径。它们是待实现/实测的预算，不能据此声称已经限制资源或通过性能。

## 1. 输入、执行与结果预算

所有KiB=1024字节、MiB=1048576字节。文本按UTF-8字节数，不按字符数或JavaScript UTF-16长度。02.2须把预算值、规范编码、计数点、错误映射和边界样例落实到契约；不能把本表当成既有请求字段定义。

| ID | 对象 | 一期固定预算/计量 | 检查位置及超限处理 |
|---|---|---|---|
| RB-01 | 用户/生成源码 | ≤32KiB=32768字节，含注释/空白 | 主线程初检、Rust解析前复核；超限拒绝，不截断源码 |
| RB-02 | 单次完整请求 | ≤64KiB=65536规范编码字节；含源码、输入、seed及协议元数据 | 编码前可估算、发送前准确检查；Rust边界复核；不通过扩大或分批拼接绕过 |
| RB-03 | 课程普通整数/序列 | -999..999；逻辑n=0..30，数组更新题n≥1；循环教学n=0..30 | 输入绑定前校验；不把课程数值域当成C int32语义范围 |
| RB-04 | 单个实际数组分配 | 正声明长度；与其他存活对象合计受RB-08约束。没有其他对象时最多262144个int32槽 | 解析/静态语义沿用C-15正长度规则；执行到声明、实际分配前检查大小及剩余配额；不把N>30当语法非法 |
| RB-05 | 语法结构深度 | ≤64；括号/语法嵌套和表达式AST路径都须有界 | 解析及遍历检查；扁平长运算链也不能导致无界宿主递归；可采用迭代AST遍历，02.2固定计数定义 |
| RB-06 | 内部操作燃料 | ≤1,000,000单位/run，覆盖词法、解析、检查、求值、循环条件/空循环、初始化及轨迹/结果编码遍历 | Rust所有可增长循环/遍历扣减；不能只在可见DSL步骤处检查；耗尽终止 |
| RB-07 | 教学DSL轨迹 | ≤20,000个契约定义的原子教学步骤/run | 追加前检查；具体原子边界由02.2冻结，不能以多个消息/渲染帧/检查点替代该计数 |
| RB-08 | 虚拟教学内存 | ≤1MiB=1048576字节，累计所有存活作用域的标量/数组int槽，每槽4字节 | 大小乘加检查溢出，分配前检查；释放作用域后按契约计量；未初始化槽也占资源 |
| RB-09 | 文本输出 | ≤16KiB=16384 UTF-8字节/run | printf整次格式化输出提交前检查；超过剩余量整次失败，不留下半次输出/伪成功 |
| RB-10 | 完整编码结果 | ≤16MiB=16777216规范编码字节/run；含身份、轨迹、恢复资料、输出、诊断和统计 | 编码时有界追加，传递前和前端接收边界核对；不先无限构造大对象再测长度 |
| RB-11 | 运行安全截止 | 从有效运行触发起1000ms；涵盖加载/Worker/Rust/传递/校验 | Rust周期检查、主线程截止；终止并失效，不能接受迟到成功；挂起恢复规则见性能基线 |

**边界规则**：字节/容量/深度/步骤/燃料的上限值可用；任何会使计数超过上限的动作，在提交该动作前失败。时限按到达截止即过期，不保证真实系统能精确计时到1ms。所有失败须清楚显示发生阶段与可定位信息，取消和资源失败不得产生练习通过/奖励/完成事件。发生宿主OOM、WASM trap或Worker异常时，适配层呈现运行失败/可重试，不能承诺所有异常都能被Rust转成细粒度资源诊断。

有效前缀能否显示及其failure状态由02.2规定；不得把不完整轨迹标为成功，亦不得拿失败前缀冒充完整后退恢复。课程数组/逻辑输入最多30项；解释器实际声明容量可以更大，按剩余虚拟配额分配，二者分别校验。`int a[31];`本身不会因31而失败；超配额声明即使可解析，也只在执行到分配时触发资源失败，未执行分支不会因容量预算被静态拒绝。空逻辑序列保留一元素占位，越界仍按实际声明容量。P1特殊算法的数据域/规模须各任务另冻，不借本表提前开放。

虚拟配额只计算教学对象槽，不把源码/AST/轨迹/解释器元数据算作C对象；这些宿主开销受源码、燃料、结果和实际线性内存共同约束。虚拟地址是模拟地址，绝非宿主真实地址。作用域释放与轨迹恢复不能依赖已释放的宿主指针。

## 2. 实际WASM、前端持有与资源体积

| ID | 对象 | 固定上限/要求 | 实施与证明 |
|---|---|---|---|
| RB-12 | 单Worker WASM线性内存 | 最大128MiB=134217728字节=2048页（每页64KiB） | 03.1在WASM目标链接参数设置`--max-memory=134217728`，核对产物声明的最大页数，06.4真测分配/grow失败 |
| RB-13 | 当前运行Worker | P0最多1个；P1算法对比最多2个 | 新运行先失效/终止旧Worker；正常完成校验后终止；未完成加载任务同样受身份约束 |
| RB-14 | 编译Module与可变实例 | 页面最多保留1个当前引擎版本只读编译Module；每run新实例/Worker | 版本改变释放旧Module引用；复用路径03.3验，不保证浏览器免编译或免复制 |
| RB-15 | 当前有效轨迹 | P0最多1条、规范编码总量≤16MiB；P1对比最多2条、合计≤32MiB | 同题工作区/复盘共享会话；代码/输入变动立即失效；不在本地档案保存原始轨迹 |
| RB-16 | 页面首屏资源 | 首页必要响应体压缩后合计≤1MiB；工作区必要响应体合计≤2MiB（含HTML/CSS/JS/必要内容/图片） | 生产真实传输字节清单，不用模块源码大小；工作区首次提交才下载的引擎另按RB-17，禁止把首屏必要模块挪出统计 |
| RB-17 | 首次执行引擎资源 | 未缓存WASM及其必需胶水/Worker新增响应体压缩后合计≤512KiB=524288字节 | 20Mbps约210ms纯传输只是规划估算，仍有RTT/编译/实例化/执行；500ms必须测完整路径 |

[LLVM WebAssembly链接器文档](https://lld.llvm.org/WebAssembly.html)说明max-memory控制线性内存最大值，默认无该上限。此处128MiB是**显式最大值**而非initial-memory；03.1必须把参数限制于WASM目标并检查最终胶水处理后的产物，不用“Rust分配器会控制”代替上限证据。若产物声明不生效则工程未满足本决议，须修复或登记决议调整。

RB-12不限制Worker JS堆、编译Module、结构化克隆临时副本、解码后的轨迹对象、GPU或浏览器总进程内存；16MiB编码结果也不等于16MiB对象堆。传递优先采用有界编码缓冲、可转移资源及共享会话引用；具体结构与传递方式留02.2。浏览器总峰值必须观测并报告，不能冒称已有宿主硬配额。P1最多两实例意味着其线性内存合计上界256MiB，而非整页内存上界。

静态资源缓存仅保存公开课程/引擎资源，按DEC-001版本/保留规则；本预算不增加Service Worker/PWA或离线承诺。资源体积预算帮助2秒/500ms规划；体积通过不能代替耗时、功能或帧率通过。

## 3. 建议采纳与边界核验

| 原建议 | 本次决议 | 理由/承接 |
|---|---|---|
| 序列/数组30，普通输入-999..999 | 采纳为课程输入/生成数组规模；不将30作为解释器所有声明的硬上限，改按1MiB对象分配预算 | 保持DEC-002 C-15/C-16及§4允许声明容量大于教学n、分配时检查的语义；不是全部int32取值能力或全部可解析声明规模 |
| 源码32KiB、嵌套64、轨迹20,000步 | 采纳初始上限 | 02.2细化计数；06.4测合法最坏负载及深结构，不把数学比较数当DSL步数 |
| 输出16KiB、虚拟内存1MiB、结果16MiB | 采纳，按上述字节及对象口径执行 | 防输出/编码爆量，区分虚拟对象、线性内存、浏览器对象堆 |
| 安全时限1秒 | 采纳；500ms正常响应目标同时保留 | 涵盖整个有效提交，防迟到/挂起恢复旧结果 |
| 动画60fps、至少30秒 | 采纳；P0单30项、P1双视图各30项 | 真实帧/行为与细化测法见性能基线；P1待二期再测 |
| 二期递归32、编辑历史100 | 本次不提前冻结P1实现预算 | 当前main子集不开放递归/双向历史；分别由12.1、13.4正式冻结容量和淘汰规则 |
| 补充请求64KiB、内部燃料1百万、WASM128MiB、资源体积/持有数量 | 新增一期保护/规划预算 | 请求、空循环、宿主分配和重复运行具有不同增长途径；需多层约束，不能只数DSL步 |

02.4至少登记每个离散预算的“恰好上限/上限+1”夹具；01.4不执行产品边界测试。06.4还须覆盖32KiB多字节文本、64层/65层嵌套、扁平长运算链、空循环、31项声明合法、虚拟配额内最大数组/超配额声明及未执行分支、多作用域对象累计、printf跨字节边界、20,000/20,001步、编码膨胀、WASM最大页及分配失败、取消和截止迟到。无法由P0语法自然触及的线性内存等边界，允许在引擎/构建测试中设置受控小配额验证机制，再检查正式值；不能假称教学程序已耗尽128MiB。时限边界用可控时钟测试及真实前台超时恢复证据，避免偶然速度作为唯一判断。

01.3全部合法n≤30样例必须完整成功，不能因为触发预算就缩小题目范围。如果20,000步/16MiB与02.2真实可逆方案冲突，先优化必要状态的表示/检查点或处理开销；仍不能满足则写出真实最大步骤/字节/耗时、调整原因与新数值，提交DEC-004新版本并同步02.2/06.3/06.4/07/08/11.4。不能删必要信息、静默裁剪、只更新代码常量或自行降低性能门槛后宣称通过。
