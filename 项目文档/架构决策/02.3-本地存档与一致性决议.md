# 02.3 本地存档与一致性决议

决议：**DEC-006 V1.0**；契约：**SAVE-01 / SAVE-TX-01 / SAVE-MIGRATE-01 1.0.0**；2026-10-14，Codex-02.3主窗口。输入[学习事件](../契约/02.1-学习事件与奖励边界.md)、[内容版本](../契约/02.1-内容格式与引用契约.md)、[保留规则](./01.2-日志与数据保留规则.md)及[02.2交接](../交接/02.2-交接.md)。本次只冻结设计和合成资料，04步才实现浏览器存储。

## 1. 结论

P0使用原生IndexedDB，数据库名`c-viz-learning`，首个物理版本1、存档语义版本1.0.0；所有业务记录、头像和少量UI偏好均在该DB，**不使用localStorage/sessionStorage保存或镜像它们**。统一适配器是唯一写入口，不新增存储库或依赖。数据库包含meta、settings、avatar、progress、dailyFacts、goals、ledger、receipts、aliases九个store。所有写事务必须包含meta；学习事务包含全部九个store，以串行一致性换取小规模P0下的简单正确性，不把内存快照整档覆盖。

此选择对“IndexedDB业务+localStorage偏好”的推荐作显式取舍：两种API不能共同原子提交，清除和世代一致性更重要；本项目偏好很少，不需要独立同步缓存。冷启动只在内存使用默认外观，读取后应用已保存值，不冒称默认值已保存。

每个数据世代使用128位随机UUID `generation`（本地标记，不是账号/设备标识，绝不上传），清除时生成不同值；事务递增安全整数revision。原始运行、源码/积木、输入/seed、输出、诊断正文、轨迹、观测及其内容哈希均不进入存档。P1编辑历史和P2笔记没有提前建立store或任意扩展字段。

## 2. 保存与并发保证

业务事务内重读generation、语义版本、当前行和幂等键；receipt+进度+奖励权利+每日事实+目标/打卡作为一个原子提交。`request.onsuccess`不是“已保存”；仅transaction.complete后并确认当前世代仍一致才发布已保存状态。报错、quota、显式abort、中断均不得留下部分业务提交。使用`durability: "strict"`作为提示，目标浏览器能力在04/11.4核验，不把提示或complete当成永不丢失保证。[IndexedDB标准](https://www.w3.org/TR/IndexedDB-3/#transaction-lifecycle)规定事务生命周期、提交/回滚与durability提示。

BroadcastChannel `c-viz-learning.invalidate`只发送`{generation, revision}`失效提示，不传学习正文，也不作锁或事实来源。丢消息/后台挂起仍须在写入、页面恢复焦点和读刷新时核对meta。DB versionchange立即停止写入、关闭连接、提示重开；升级blocked不得强删DB。[事务调度标准](https://www.w3.org/TR/IndexedDB-3/#transaction-scheduling)是本设计让重叠meta写事务排序的依据，应用仍须正确选择scope。

清除使用同一DB事务清业务/偏好并rotate generation，保留新meta和默认singleton；不用deleteDatabase“重建同一世代”。存储缺失只能通过独立初始化入口创建随机新世代，旧命令入口绝不自动建库。清除前的写若先提交将被清除，后提交则世代不符拒绝；UI迟到成功也不能复活旧状态。

## 3. 日期与奖励取舍

首次初始化取浏览器解析出的IANA时区并固化为本世代timeZone；无法识别则明确使用UTC并告知。系统时区变化不重桶，P0无改时区入口；浏览器时钟不是可信服务器，无法承诺防改钟作弊。每个事实在可信学习入口产生时固定UTC时间、当地日、同日目标快照，重试不换日期。目标修改仅影响之后尚未开放的日期；今日快照不可改，同日达标至多一奖。

11.1尚未冻结分值，因此先保存唯一奖励权利`pending`，points/policyRef为null；加载有效公共奖励配置后一次性转`posted`，原发生日不变。已posted条目不因配置/内容升版重计；总积分只求和posted，等级由11.3公共阈值派生。夹具里的demo政策和数值只用于模型检查，不是正式积分配置。

## 4. 存储风险与影响

存储以当前origin/浏览器配置为边界；更换域名/端口、其他浏览器、隐私模式和浏览器清网站数据不能自动找回。容量不足不淘汰有效进度/账本/防重键，改为未保存并允许同命令内存重试；不保证队列刷新后仍存在。`estimate()`仅辅助提示，不等于剩余空间保证；P0不自动申请persist权限。[Storage标准](https://storage.spec.whatwg.org/#usage-and-quota)说明配额/使用量是估计及best-effort存储清理规则，用户清除始终可能丢数据。

不设虚构浏览器容量保证或新存档字节上限；累计记录达到实际配额时失败，不剪账本。单命令只有封闭的最少字段，批量迁移以版本化方案检查，不接受任意导入文件。本次不建设备份/恢复上传、账号、云存档、日志或产品遥测。
