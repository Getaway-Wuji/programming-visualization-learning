# 04.3 异常恢复与清除屏障

2026-10-15（Asia/Shanghai），Codex-04.3主窗口。输入：[任务包](../任务包/第04步-完成浏览器本地数据基础.md)、[04.2交接](../交接/04.2-交接.md)、[DEC-006](./02.3-本地存档与一致性决议.md)、[SAVE模型](../契约/02.3-本地数据模型.md)、[事务](../契约/02.3-事务日期与奖励幂等.md)、[恢复规则](../契约/02.3-迁移与恢复规则.md)。所有契约仍1.0.0，DB physical1/九store，无新增持久字段、依赖或数据导入。

## 恢复读取与隔离

正常read/commit/probe继续严格验证全档案及物理键。生产service以recovery选项打开已知布局，额外readRecovery一次事务读取九store的物理键/行，在内存校验并构造合法只读子集。非法行及关系无法确认的依赖行仍留在原DB；不是删除、迁移或自动修复。公开状态仅含store类别/数量、能力和错误码，不复制坏行正文/物理键到日志、新store或广播。

| 情况 | 行为 |
| --- | --- |
| settings/avatar非法 | 显示明确默认外观，暂停普通写；可在本地数据页确认后仅重置对应singleton，保留学习记录与世代 |
| progress/dailyFacts/goals/receipts/aliases非法或关系不明 | 隔离相关行，合法历史只读展示；暂停学习/奖励写，防止把坏去重行当从未发生 |
| ledger非法或账本关联不明 | 标记积分暂不可确认，首页及明细不展示删去坏行后的缩水总分，不猜补奖 |
| meta缺失/非法 | 保留库，snapshot为空，不给旧数据补随机世代；仅精确已知布局且可安全确认时提供全清 |
| 未来/未知语义或物理版本、陌生布局 | 拒绝本版写与清除，说明需匹配版本或浏览器网站数据管理 |
| quota/权限/连接不可用 | 旧数据保留，明确未保存、内存临时使用与重试，不自动淘汰账本/回执 |

隔离投影满足既有结构/关系校验；为避免部分坏行造成虚假完整日目标，无法确认的整日依赖组一起只读隔离。总分是否可确认另用ledgerUncertain表示，不能只看过滤后数组。后台刷新不得用旧保存结果覆盖新发现的readonly或重新宣称已保存。

确认令牌guard仅在StorageClient私有内存，绑定读取时原meta/偏好行，最多保留16份；不进入public facade、DB或广播。损坏meta含Blob等无法在原生事务中同步比较的opaque对象时不提供本版清除；损坏偏好含这类值时不提供局部重置。普通缺失meta/缺失版本/非字符串脏版本可在已知布局中确认清除；任何字符串schemaVersion不等于1.0.0均按未知版本保留。

## 临时使用与重试

应用仍允许浏览/使用工作区；当前正式学习未开放，样例始终不计进度。后续真实可信生产者接入的统一接口在存储失败时可保留内存事实，测试仅用隔离合成可信摘要证明该行为。

已读合法世代的事实保留原token、发生时间、eventId和generation。capture的首次读/开日失败也发布未保存状态，重试重新读取实际冻结日目标，不猜goalVersion；跨午夜仍原发生日。已形成命令的提交失败则保留原命令重试，完整receipt先查确认，奖键/日事实不重复。临时投影每次以最新权威合法行加待保存delta重算，不能拿旧内存整档遮住其他标签的新记录。

首次打开失败或连接关闭后单独的memory-only学习仅在隔离内存世代中展示，没有保存ACK，也不把它加入持久重试队列。真实档案重新读取后该临时上下文失效，不将旧临时事实重新绑定到新/旧真实世代。所有队列只在内存，刷新/关闭不承诺找回。quota/权限检测不假称可识别每种隐私模式，也不自动申请persist权限。

## 清除与局部修复

本地数据页的原生确认对话框说明会移除进度、尝试、账本与防重记录、目标/打卡、形象/设置及当前临时内容，取消默认获焦，Escape和取消不写。局部重置分别说明范围；settings重置包含未来目标模板，已打开目标不变。没有备份/任意导入入口。

确认全清前service同步增加sessionEpoch、撤销临时投影/待保存事实并通知运行消费者，再进入串行队列。页面按epoch重新挂载以丢旧草稿；EngineConnection先清所属检查身份再取消真实Worker/下载，迟到结果不再应用。后续真实执行/播放器/学习生产者必须继续订阅同一失效边界。

clear在含全部九store的readwrite事务内重新核验布局/版本与确认世代，清全部store后写新随机generation、revision0/default singleton，直到transaction.complete并新读核世代后才报告已清除。有效同世代允许先提交写的revision增长，它们随清除一起移除；新世代一律拒绝。坏meta按原始值和物理键比较，不覆盖确认期间变化。任何请求失败/主动abort整体回滚，不用deleteDatabase伪重建。

局部reset只在确认meta revision/世代及目标原值均未变时写该singleton和meta+1，其他store字节/键不变；服务层最终读也核原generation和epoch，不能把别页刚清的新档误认为旧重置已保存。清除失败不显示成功，已失效的旧临时结果也不复活。

## 多标签与后续边界

BroadcastChannel仍只发送闭合合法的generation/revision失效提示，接收只触发重读，不相信消息中的事实或整档。通知禁用/漏消息时，每次写、focus/可见恢复及明确刷新仍核DB meta；原生重叠meta事务合并不同事实并防同业务重奖。versionchange关闭连接并通知，重试可重新打开；未知新版本保持只读。

本轮验收真实浏览器原生事务、双页面、损坏数据原行保留、部分写后abort及确认交互；故障配额/权限由API注入，另验证实际隔离浏览器context关闭后档案消失，不冒称真实满盘或所有隐私配置。OS断电、浏览器驱逐、正式HTTPS/CDN与实际完整教学性能仍留11.4；真实课程/判题/观看/积分政策仍09/11。本次不开始05.1或其他子任务。实际结果见[验收](../验收/04.3-恢复与清除验收.md)及[交接](../交接/04.3-交接.md)。
