契约：**DIAG-01 / JUDGE-OBS-01 1.0.0**；日期：2026-10-14。输入[02.1题目/事件](./02.1-内容格式与引用契约.md)、[DEC-004预算](../架构决策/01.4-资源预算表.md)、[执行契约](./02.2-执行请求与生命周期契约.md)。

## 1. 诊断格式和类别

Diagnostic={code,severity:"error",origin,stage,location,details}。origin为rust/adapter/protocol/judge；stage为preflight/load/lex/parse/semantic/execute/encode/receive/judge。location为source（nodeId、edge或byteRange，二者至少一个）或synthetic（明确reason，可有anchorNodeId）；程序检查前也可直接按byteRange定位。details只允许有界expected/actual/limit/used/attempted/dimension/relatedNodeIds等技术/教学数字，结构见Schema。不能塞源码片段、原始宿主exception/stack或任意JSON。UI本地按code映射通俗文本，安全文本显示；具体GCC风格留14.1。

| code | 阶段/终态 |
|---|---|
| E_LEX_INVALID / E_PARSE_INVALID / E_UNSUPPORTED_SYNTAX | lex/parse/semantic，program-error，无真实执行轨迹 |
| E_NAME_INVALID / E_TYPE_INVALID / E_FORMAT_INVALID | semantic，program-error；未执行分支也静态检查 |
| E_UNINITIALIZED / E_INDEX_BOUNDS / E_DIV_ZERO / E_INT_OVERFLOW | execute，program-error；失败赋值不写、失败printf不输出；可以有已提交prefix |
| E_INPUT_INVALID / E_INPUT_ORDER / E_BINDING_INVALID / E_CONTENT_MISMATCH | preflight/semantic，rejected；逻辑空占位不谎报C越界 |
| E_PROTOCOL_VERSION / E_PROTOCOL_INVALID / E_TRACE_INVALID | preflight/receive，rejected或adapter infrastructure-failure，无假轨迹 |
| E_SOURCE_LIMIT / E_REQUEST_LIMIT / E_DEPTH_LIMIT / E_FUEL_LIMIT / E_STEP_LIMIT / E_MEMORY_LIMIT / E_OUTPUT_LIMIT / E_RESULT_LIMIT / E_DEADLINE | 实际发生阶段，resource-limit；details带维度/limit/used/attempted，位置若无源码则解释原因 |
| E_CANCELLED | adapter，cancelled，synthetic adapter-cancel |
| E_MODULE_LOAD / E_WORKER_FAILURE / E_WASM_TRAP / E_ENCODING_FAILURE | adapter，infrastructure-failure；不能伪装C语法错误 |
| J_STDOUT_MISMATCH / J_EXIT_NONZERO / J_TEACHING_TARGET / J_BINDING_MISMATCH | judge，不改变已真实运行的completed终态，judgeResult=unmet；不是C程序错误 |

同run最多16诊断；completed的terminal.diagnostics必须为空，教学判定未满足放judgeResult及checks.diagnosticCodes，不将C正常运行改成失败。首个程序失败按真实阶段及执行顺序取主码，不通过排序改变首先发生的程序错误。独立协议结构错误先版本、后结构/关系，未知事件不能按“无源码”绕过验证。输入/内容诊断02.1仍按其CONTENT_*格式处理；传入运行边界失配才用本表，不改既有错误码。

## 2. 预算计量

所有上限继承DEC-004，budgetRef固定budget.p0@1.0.0；测试工具的较小预算只能在独立内部测试配置显式标记，正式请求不能抬高/暗改。边界“恰好上限”可用，候选动作将超出时提交前停止；deadline到达即过期。

| 维度 | 固定上限/检查与错误 |
|---|---|
| sourceBytes / requestBytes | UTF-8源码32768、规范完整请求65536；主线程预检和Rust入口复核；E_SOURCE_LIMIT/E_REQUEST_LIMIT |
| inputDomain / inputLength | 元素/普通参数-999..999，逻辑序列0..30，更新题至少1项及合法k，循环n0..30；E_INPUT_INVALID/E_INPUT_ORDER，不限制int32计算结果 |
| syntaxDepth / astDepth | 各≤64；syntax为main根块=1，嵌套块/控制结构/括号每进入一层+1，独立表达式根为1；ast为表达式根1、子表达式+1最长路径，声明/类型不增加表达式层。for内部块按实际语法算一层。词法括号/解析栈/迭代AST遍历均有界；扁平长链也按astDepth检查；E_DEPTH_LIMIT |
| fuel | 每run≤1000000；扫描每UTF-8源码字节1、每token/AST节点构建/检查访问1、每实际read/算术/判断/write/控制转移1、每初始化逻辑槽1、每变化/观测/检查点条目遍历1、键排序每比较1；输入/输出/JSON编码解码每64字节块1（各阶段独立向上取整），内部判题图每节点/边访问1。不得把每大对象操作或整个编码仅算1；E_FUEL_LIMIT |
| steps | ≤20000原子步，追加前检查；失败终止/检查点不计步；E_STEP_LIMIT，不能发第20001个伪终止步 |
| liveBytes | 活int槽总量≤1048576，每槽4字节，包括未初始化及占位；按大小乘加溢出检查，在声明实际分配前拒绝；E_MEMORY_LIMIT。正声明容量可大于30，未执行分支不做分配失败 |
| outputBytes | ≤16384 UTF-8字节；printf完整生成和预算通过再一次提交；E_OUTPUT_LIMIT，不能半次输出 |
| resultBytes | 完整规范结果≤16777216，含nodeMap/逆数据/检查点/诊断/统计/判题观测；65536诊断保留空间也在此内；E_RESULT_LIMIT，不无限构造后裁剪 |
| deadline | 原有效触发至主线程完成验收/呈现<1000ms；每组继承提交剩余时间；E_DEADLINE，不接受迟到success；Rust至少每1024燃料及各原子提交前检查时间 |

JSON容器≤32是编码设施限制，语法64是C结构限制，二者不混报。源码/AST/轨迹不是虚拟对象槽，但都消耗宿主及燃料/编码预算；单Worker WASM最大128MiB，P0一个Worker/一条轨迹/一个只读Module，资源/首屏和首次引擎体积仍按RB-12—17真实构建/测量，非协议数组长度。

在总1000000燃料内保留终包处理能力：已提交步骤/检查点按规范键序增量编码并扣费，候选动作预检须加上预计完整编码的最后缓冲装配费用（每64字节1）及4096单位有界terminal/统计/诊断处理储备。储备不是额外燃料，最终实际处理同样扣费；used+候选动作费用+必要收尾费用将超限时不提交候选，报E_FUEL_LIMIT。整包不能在执行燃料已耗尽后从头无偿重编码；没有可信可送终包时adapter仅失败无轨迹。预留只防必需收尾无资源，截止仍优先，不能延长1秒；06.4须用受控预算真实验证收尾费用与异常。恰好总上限可用，不能把只剩收尾储备的额度再用于新C动作。

燃料不可恢复为“未消耗”以继续Rust执行，播放器回退只恢复教学state/counters；stats.fuelUsed是真实运行总量，不随播放游标改变。取消/时限到期无Rust统计则stats=null。所有周期/排序/扫描实现都须有界，LLVM产物上限/宿主OOM/WASM trap仍需真实验证，不能保证所有故障都变成细粒度Rust诊断。

## 3. 临时判题观测与可信来源

Rust同一运行环境解析AST、识别真实声明/输出位置、记录动态值版本及有效贡献，产生有限judgeResult；前端只核对身份/配置/完整性及聚合。内部依赖图不能作为未计预算的旁路，不自动完整回传；只回传有界结论/关联节点/步骤和必要数组观测，仍仅内存。未知检查/缺证据=not-evaluated或unmet，绝不默认met。

judgeResult={profileRef,caseKey,status,checks,coverage,observations}；status=met/unmet/not-evaluated。checks各{key,status,nodeIds,stepSeqs,diagnosticCodes}，key含input-bindings、stdout-exact、exit-zero、teaching-target，以及EX-04的while-accumulation/for-accumulation。基础四项必须都有且met，EX-04两个子项也必须met；status与所有子项一致。代码非正常/取消/资源失败不能有met整体结果。single-index-increment声称met时必须恰有一个param.values的销毁前观测，长度等实际逻辑输入；缺失/重复证据不能默认通过。请求的profile/rule/所有expected字段必须逐项等当前题目该caseKey冻结配置，不能接受调用方自定答案。

coverage各{siteKey,nodeId,branch,visits}，siteKey对应当前解答结构的稳定生成blockId，由Rust根据source.blockMap解析；控制节点与siteKey必须一对一，选择恰好对应本if/while/for生成块的范围，不得使用包含多个控制节点的main/父容器块充当同一siteKey。缺失/歧义映射为J_BINDING_MISMATCH。branch为then/else/while/for，visits为实际次数。EX-03跨组聚合需要同一siteKey的then与else，节点ID仅在该source内有效，不能跨组按n编号猜同一分支。EX-04两种循环各有真实次数，n=0允许0但须静态结构和0输出成立。

observations当前使用array-before-destroy：{kind,bindingKey,objectId,declarationNodeId,beforeCursor,location,values}；若销毁发生在第k步，beforeCursor=k-1，采样在return求值成功/该绑定scope即将销毁且对象仍活着时，values只含逻辑[0,n)。after销毁的终态无数组也不丢证据；同名后续对象不能取代原绑定。观测不改变state、不新建步、不加读/写计数；与真实对象及采样位置/时序必须相符，最多30项。

## 4. 六种教学检查

| rule | Rust必须检查的实际关系 |
|---|---|
| input-read-output | 当前绑定x声明/真实读取的值沿有效路径到对应%d输出，不用固定答案/死读取替代 |
| multiply-add-output | 输入x有效参与真实乘法及加法到结果，允许交换操作数/临时复制；先计算后覆盖、乘零后输出常量不算目标 |
| if-else-paths | 条件与x相关、两路为同一if/else的有效输出路径；单组记录实际分支，整个提交按coverage补齐then/else |
| while-for-accumulations | 正n时两类循环各实际迭代，各输出来自本循环从0开始的有效累加链，贡献为1..n（可等价调整遍历/操作数顺序）；输出第一/二行分别绑定while/for结果。n=0要求相同结构、0次和两路0；公式覆盖、无关循环、s=s+0均不满足 |
| single-index-increment | 真实读写绑定values[k]，写后值进入stdout；销毁前逻辑数组与expectedArray相等、只有指定元素+1，其他不变；stdout碰巧正确不能替代数组目标 |
| logical-array-accumulation | 真实循环读取全部逻辑[0,n)并作为有效贡献累加到输出；非空各逻辑元素都参与，空没有占位读；无关读取+闭式打印不满足 |

“有效路径/贡献”不得仅用taint祖先集合：`sum*0 + n*(n+1)/2`即使读过sum，也已消除其贡献，必须拒绝。Rust保留声明/动态值版本、迭代/写序和输出参数身份，按受支持的有限累加模式核对贡献。累加检查将源输入槽/实际循环贡献记为独立符号并带整数系数；+合并系数，-减去系数，零系数项删除，单纯赋值覆盖旧值贡献，透明复制保持当前版本，字面常量单独累计。*0清空贡献，*1和/1保持，其他操作只在已登记的精确贡献模式中处理，无法证明则unmet。最终必须与目标贡献集合及每项+1系数一致；因此sum-sum+公式、先累加再被公式覆盖也拒绝。操作数交换/括号及+0/-0可保持贡献；输入元素实际值碰巧为0仍保留该**输入符号**贡献，不能按数值为0删除来源。

本契约不要求通用程序证明器。09.3实现有限贡献检查时可扩展同范围等价模式，但必须给具体规则和正/反真实证据，不把未能证明的结构标met，也不把它说成“不支持该C语法”。复杂等价解若无法满足检查，给J_TEACHING_TARGET及教学要求；不能通过固定源码文本判等。所有24冻结测试/参考解必须满足，并测试装饰循环/公式覆盖、数组错写/占位、部分目标、非0返回等反解。真实AST识别/贡献与字段联调仍是05/06/09.3后续验收。
