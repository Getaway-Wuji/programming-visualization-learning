# 02.3 迁移与恢复规则

契约：**SAVE-MIGRATE-01 1.0.0**，2026-10-14；配合[模型](./02.3-本地数据模型.md)和[事务](./02.3-事务日期与奖励幂等.md)。本目录此前没有产品存档。样例legacy0.9.0是专门构造的前驱资料，不代表曾发布旧产品或真实用户迁移已通过。

## 1. 版本与打开

物理DB版本1与SAVE语义1.0.0分开。仅upgradeneeded的`oldVersion===0`确认新库时创建九store及唯一复合键；初始化meta/default singleton必须同事务。已有库不得因缺meta/解析错误当新库覆盖。打开未来物理版本会失败，未来语义版本转只读不写；不自动deleteDatabase、降级或忽略陌生字段。versionchange关闭连接；blocked等待其他窗口关闭并允许取消，不强删。

未来结构变更只用受控versionchange升级；读取、校验、转换和最终版本标记在同一升级事务。请求成功不发布完成，abort回退旧结构和版本。转换所需公共映射/配置在开事务前准备；事务期间不await网络、定时器、UI确认或crypto异步任务，避免事务自动结束。随机世代也在事务前生成后检查不复用。

当前仅接受首版1.0.0正常数据，**迁移演示0.9.0不授权产品通吃未知旧格式**。若03/04需要实装旧版导入/存档，须正式登记旧物理布局、版本对应、完整recipe和损坏处理；本任务提供可复用迁移机制及确定性参考资料，不新增导入产品功能。

演示前驱字段为schemaVersion=0.9.0、generation/timeZone/createdAt、packageRef、confirmations、passes、rewards、theme。转换只做：保留世代/时间/公共Ref/修订，确认及通过分别转progress；rewards按原source+subject及原points转posted，政策Ref置已声明legacy.fixture@0.9.0；默认缺失偏好/头像、空未来集合、revision=1，schemaVersion=1.0.0。不制造dailyFacts/goals/receipts、小节完成或奖励，不从旧pass猜输出/分值。不合法前驱或失败中断整次不提交，保留原对象/有效行供受控恢复。

## 2. 内容升级与改ID

结构迁移不等于内容更新。当前完成检查同ID、同learningRevision且精确当前version或明确acceptedPriorVersions；纯文案patch可复用，修订变化保留历史但当前须重新满足。小节确认和必修题均检查兼容，不能只看历史completed。内容删除/未知Ref保留历史、标旧内容不可用于当前完成；章节移动不改稳定ID或首次奖键。切包使旧运行失效，但不清旧学习档案。

确须改ID时提供受控公共identity manifest（独立于CONTENT-01实体格式，不修改02.1）：manifestRef、fromPackageRef、toPackageRef、aliases[]；每项fromRef/toRef/fromAcceptedPriorVersions/kind/learningRevision。仅一对一、同种类、同学习修订且已由内容负责人审核等义的重命名；来源/目标必须能在相应不可变公开包查到，fromAcceptedPriorVersions必须等于经审核的来源显式兼容列表。单个来源/目标唯一，无环、最长链32，所有引用/包版本精确；新旧两条记录同时存在时规范身份指向最早旧ID，不以新版ID再发首次奖。

兼容读取的精确算法：历史Ref须与alias.fromRef精确匹配或在fromAcceptedPriorVersions且修订相同，才能变为toRef；逐链重复该检查，最终映射Ref须精确当前或在当前实体acceptedPriorVersions且修订相同。当前ID的未列旧version不得因alias/版本号同形被认可。规范奖励身份可沿反向ID链找最早ID，但这不替代上述进度版本兼容校验。

导入manifest在含meta/aliases/ledger/dailyFacts/progress/receipts的同事务校验关系并保存alias、更新activePackageRef/revision，不产生学习事件/日事实/奖励。历史progress的Ref不改写；当前兼容读取沿有效alias映射，旧奖励的canonicalSubjectId/旧ID不重写。**目标新ID若已存在任何progress、dailyFacts、ledger或receipt引用，首版一律拒绝该alias导入**，包括只有新ID有账而旧ID无账；保留两边等待专用规范化recipe，不能令已有新键失去去重作用。目标也不得已属于其他alias等价类。source已有数据允许，规范身份沿反向alias链取最早旧ID，所有新事实均用该规范身份查唯一奖/日键。拆分/合并/修订改变不作为等义alias；保留旧历史，新规则须重新学习，涉及奖励身份需明确内容/奖励决议后才能开放该新对象领奖，不能默默当新ID刷首次奖。

## 3. 损坏与恢复

| 损坏范围 | 恢复政策 |
|---|---|
| 当前UI缓存/总分/等级/完成百分比 | 丢临时投影，从权威合法行重算，不补奖或删有效行 |
| settings/avatar局部非法 | 保留原行，当前读使用明确标注的默认外观；经用户确认仅重置该singleton，不改进度/账本/世代 |
| 一条进度/每日事实/回执非法 | 该键隔离只读（原字节/行留原DB，不复制日志/新任意JSON袋）；其他合法行仍可展示，但相关学习/奖励写入暂停，不能以少了坏行推导新的首次奖 |
| ledger非法/唯一键冲突/关联不明 | 账本及关联学习写只读，总积分标不可确认，不跳过坏奖显示缩水总分，不从通过记录猜补发 |
| meta坏/世代缺失/未来版本/未知旧格式 | 全业务只读，保留库；不给旧数据补随机世代后回写；明确受控升级/恢复或用户确认清除入口 |
| 实际quota/无法打开 | 旧数据不淘汰，临时学习标未保存；重新可用后原命令核对世代后重试 |

隔离是访问策略，不是先删坏行；未建立自动备份/远程恢复/任意导入。浏览器已删除数据没有可承诺的恢复源；页面仅说明事实。受控修复需展示影响、保留不相关有效数据、事务提交且另有修复recipe，不能自动“修复为全新档”。若用户选择清除，必须明确有效学习数据也将丢失，并走世代屏障。未知未来结构无法安全遍历时不执行本版清除，使用浏览器网站数据管理或匹配新版本，不能伪造清除成功。

## 4. 验证和边界

本轮[模型场景](./02.3-迁移与并发场景.json)检验原子成功/失败/ACK丢失、同题/不同题写入、清除先后与漏通知、午夜重试/DST/回拨、目标冻结、pending入账、内容patch/修订/删除/重命名和无事件迁移。资料检查脚本只在内存计算有限状态，不连接浏览器IndexedDB；这不是04/11真实持久化、断电、quota或竞态证据。
