## 1. 本次决定与范围

1. P0.5采用一份版本化编辑文档管理代码和积木，两侧都是该文档的编辑/显示入口，不建立两个可以各自提交的程序。显示/隐藏积木与当前程序是否可提交分开。
2. 双向所需的新内部编辑契约命名为`EDIT-SYNC-01 1.0.0`；由Rust提供的有界分析投影命名为`AST-MAP-01 1.0.0`。现用EXEC/STEP/DIAG/JUDGE-OBS/JSON-INT的1.0.0消息不因新增编辑入口自动扩字段。本文件冻结接口责任、状态、身份及失败约束，不提前冻结逐节点往返算法。
3. 现有六题沿用原六种JUDGE检查及24组测试。Rust新分析产生当前源码的合法映射后，现有EXEC/JUDGE仍逐次复核；不得用空`blockMap`、伪造ID或省略教学检查让代码作答通过。
4. 原20类积木的逐类反向映射、支持/不支持样例、括号/注释/格式保留和规范输出细则，仍由原**13.1**完整交付并按原验收；Rust分析生产者、浏览器消费者、双向高亮及往返真实行为由原**13.2**交付。本项文档通过不计为13.1或13.2已验收，也不重复计数。
5. 新26题的扩充判题检查使用新`EXEC-01 1.1.0`封套和`JUDGE-OBS-01 1.1.0`，另登记对应CONTENT判题枚举/实体变更。精确组合为`protocolVersion:1.1.0`、`judgeVersion:1.1.0`、`traceVersion:1.0.0`、`diagnosticVersion:1.0.0`、`encodingVersion:1.0.0`；STEP/DIAG/JSON-INT不连带升版。原六题和案例继续使用五版本全1.0.0及原语义。现Schema所有版本共用const1.0.0且judge.rule封闭，支持新检查/版本组合已经改变EXEC接受规则，不能只升judgeVersion。后续新增独立Schema拆分各版本引用并显式登记两套组合，保留旧Schema原字节，禁止任意混搭或旧端猜兼容。
6. 公开静态外观/课程展示偏好可独立注册，不将展示字段塞入封闭的CONTENT-01 1.0.0。浏览器个人偏好与图片的SAVE升版/迁移，以P0.5-01独立存储决议为准，静态配置不是存档旁路。

## 3. EDIT-SYNC-01：单一编辑文档与身份

以下是后续实现必须暴露的内部语义字段；不是往现有EXEC封套追加字段的许可。

| 字段/接口 | 冻结含义 |
| --- | --- |
| `editVersion` | 精确`1.0.0`；浏览器当前会话内协议，未知版本拒收并保留原草稿 |
| `contextId`、`contextRevision` | 复用当前题目/案例会话及EXEC失效身份，不新建竞争的运行会话 |
| `documentRevision` | 当前会话从1单调递增；代码字节、积木逻辑、输入、题目/程序/映射/子集等执行上下文变化递增；与内容version无关 |
| `editId`、`origin` | 一次逻辑编辑的不透明ID及`code`/`blocks`/`input`来源；同一事务的派生投影回写不再次产生用户编辑，禁止源码↔积木回调循环 |
| `authoritativeDraft` | 判别联合：`code`为原始代码文本，`blocks`为当前Blockly草稿及可用IR；同一revision仅一个当前权威草稿。上一次有效投影只能标历史 |
| `syncStatus` | `synced` / `invalid` / `unmapped`，定义见下一节；分析进行中另用`analysisPending`，不把等待伪报为C语法错误 |
| `validatedDocumentRevision` | 最近一次完成分析/映射校验的文档revision；只有等于当前revision且非pending，状态才适用于当前草稿 |
| `lastSynced` | 可为null；保存最后有效代码/IR/映射的会话投影及所属revision，只供恢复/对照，不能自动当成当前程序运行 |
| `codeDraft`、`blockDraft` | 当前会话内分别保存原始文本和完整Blockly草稿，含不完整连接；不得被异步旧分析、显隐切换或父组件初始值覆盖 |
| `inputBindings` | 来自当前Program的精确`bindingKey`、声明身份/类型/名称/顺序和输入约束；不是按名字猜测的自由变量表 |
| `PreparedSource` | 继续使用既有`{text,blockMap,bindingMap}`；属于本组输入实例化后的完整源码，显示与执行必须相同 |
| `sourceRevision` | 继续遵守EXEC原含义：同revision完整源码字节/绑定/映射不变；每组实例化结果获得新递增revision，禁止拿documentRevision直接冒充它 |
| `applyCodeEdit` / `applyBlockEdit` | 同步废弃旧当前运行/判题、递增编辑身份、保留草稿，再启动有界分析；分析结果回写前后均检查完整身份 |
| `setWorkspacePresentation` | 只改变显隐/分栏/缩放/选中等展示状态，不调用逻辑编辑，不递增上述执行revision |
| `prepareForTest` | 对同一冻结编辑版本按该组输入生成并校验完整`PreparedSource`，新sourceRevision绑定该字节/映射；不能以参考程序替换用户解答 |

代码改空白、换行或注释即使语义不变，也改变源码字节及位置，必须废弃旧当前源码映射/执行；这与只移动面板或改变Blockly坐标不同。有效通过已成为历史学习事实后，后续编辑只使它不再代表当前稿，不删除或重复奖励历史。

## 4. 三种同步状态与运行资格

| 状态 | 含义 | 编辑/展示/提交行为 |
| --- | --- | --- |
| `synced` | 当前稿通过Rust语法/语义、课程输入绑定及已登记映射校验，代码与IR表达同一当前程序 | 两侧可编辑；积木隐藏时也可代码运行和提交；提交仍须真实执行全部测试与教学检查 |
| `invalid` | 当前代码暂时非法、输入绑定错误，或积木缺槽/错接等导致当前稿无效 | 原文/草稿保留；显示当前诊断，停用当前运行/提交；最后有效程序标为历史，不能无声执行 |
| `unmapped` | Rust支持该源码语法/语义，但超出已登记双向映射范围，或无法无损表达当前结构 | 保留原代码并说明具体未映射范围；可继续改代码；不生成看似等价的残缺积木。P0.5课程作答只承诺可映射子集，未映射稿不送入课程提交；通用代码能力留17步 |

分析pending期间，`validatedDocumentRevision`必然落后当前revision，所有当前运行/提交入口关闭；最近的状态只能作为上次分析结果标记。异步完成只接受相同context/revision/documentRevision/editId；取消、离题、清除或新编辑后旧结果一律不回写。

用户要求的“不要积木也能写代码”以**synced且积木隐藏**实现，不以“代码模式取消教学检查”实现。源码是否可映射与工作区是否显示是两个独立维度。

## 5. AST-MAP-01：Rust分析与映射责任

### 5.1 接口边界

后续13.1/13.2新增独立`analyzeCodeDraft`分析调用，消费者不得把EXEC结果的有限`nodeMap`误作完整编辑AST。该调用不执行用户程序，不产STEP、判题成功、学习事件或奖励，不建立服务端档案。

| 输入/输出 | 必须有的身份/内容与限制 |
| --- | --- |
| 请求版本与身份 | `analysisVersion:1.0.0`、当前`contextId/contextRevision/documentRevision/editId`；全部回显，无用户内容指纹 |
| 请求课程上下文 | 精确`packageRef/programRef/subsetRef`及经验证的输入/绑定描述；来源是当前静态题目，不能让调用者传自定义答案或抬高预算 |
| 请求文本 | 当前完整`sourceText`及当前输入实例；保留原始UTF-8字节/CRLF，不先格式化再沿用旧坐标 |
| 结果状态 | `valid`/`invalid`及有界诊断；有效结果附`checkedAst`、`bindingMap`、`nodeMap`和候选`blockMap`；无法映射的合法节点由映射消费者产生明确`unmapped`说明 |
| AST身份 | 当前源码范围、节点类别、父子/操作数/语句槽关系、字面值/运算符/声明与引用绑定；使用有界扁平投影、声明判别联合，无任意原始C执行插槽 |
| 映射身份 | Rust基于真实AST/当前草稿结构生成合法ID和范围；输入声明对应精确真实AST；控制节点与siteKey一对一；输出映射仍符合现EXEC字段，无新增执行字段 |
| 体积/资源 | 保持源码32768字节、语法/AST深度64；请求≤65536字节；分析结果≤16777216字节、同1000000燃料/1000ms硬限制/128MiB上限和可取消。不得用分析调用为提交另授运行预算或绕开原deadline |

具体20类节点的投影payload、注释/格式的保留数据和往返映射规则，必须在13.1配套Schema/样例中完整封闭定义后，13.2才实现生产者消费者；不得把本表的约束当作已存在的宽松JSON扩展袋。这里固定**字段职责和允许类型边界**，不是提前交付完整13.1细则。

### 5.2 映射与输入保护

- Rust是唯一C语法/语义权威。前端可编辑有限IR并做连接检查、生成文本、消费Rust投影和转换UI坐标，不能另写C解析器/执行器来证明合法性或教学目标。
- 代码编辑保留课程受控输入前缀；删除、改名、重复、遮蔽改绑或改初值的草稿保留但为invalid，不静默“修复”后提交。实际每组输入仍由同一受限绑定实例化，空数组继续`n=0`/单零占位，逻辑长度规则不变。
- 隐藏/卸载Blockly时先保留完整草稿、原生ID↔协议ID关系及当前IR；重新显示按当前已验证文档恢复，不载入starter覆盖用户代码或编辑。
- 不要求活动画布存在才能生成映射。Rust可为代码起稿产生稳定的合法虚拟积木ID，显示后成为该投影的真实积木ID；这些ID有明确当前AST/范围证据，不能只为满足JUDGE填几个字符串。
- 稳定siteKey属于同一提交的编辑结构；跨测试输入按结构对应保持，不跨组猜`n1/n2`。每个sourceRevision仍重新核对真实AST节点/字节范围。增删控制结构、改变映射或修改输入立即废弃旧提交。
- 原6题对控制siteKey的约束保持：不能用包含多个控制节点的main/父块代替，不能用重复/重叠歧义映射；空映射的条件/循环题不通过，非控制题也必须满足原绑定、输出和真实贡献检查。
- 动态观测继续由真实Rust执行生成。AST分析成功仅证明能映射，不能证明通过；有限贡献无法证明的等价解仍unmet并给教学目标提示，不虚称C语法不支持。

## 6. 显隐、布局、外观与草稿保护

全局积木偏好为`auto`/`show`/`hide`，个人保存字段由SAVE决议定义。`auto`读取当前课程独立展示配置；用户临时展开/收起不改变程序。简单章节可默认代码，复杂控制/数组章节可显示积木，但每题仍使用同一判定规则。

以下行为**不使当前运行失效**：主题/主题色/明暗/背景改变，侧栏收起、面板分栏拖动、切换专注布局、只隐藏/显示积木、辅助面板开合、Blockly画布平移/缩放/选中，以及单纯代码选区变化。它们可以暂停播放器以便重排，但不得取消真实已接受结果、重跑程序或发新学习事实。

以下行为**必须使当前运行失效**：代码字节改变、积木增删改/重连、输入实际值变化，课程程序/题目/判题/子集/映射的执行版本变化，以及退出会话或清除。主题重排造成DOM重挂不能伪造逻辑编辑。

工作台优先采用内嵌外观/积木设置抽屉，或让同题会话继续存活，避免只是改“隐藏积木”却路由离开并清空草稿。会话内切换代码/积木、同题复盘、展开/隐藏和外观设置，合法/非法代码草稿都保留；不能只保存最后有效IR。刷新、真正离题/换题/清除仍按临时会话边界处理，离开前清楚提示未保留草稿；本阶段不暗增原13.4的持久编辑历史。

## 8. 版本、发布登记与质量门槛

### 8.1 每类变化如何触发

| 变化 | 必须新增/保持的版本与授权 |

### 8.2 12份登记源码与新不可变版本

6. 新增执行语义/AST分析或判题时同时运行对应Rust核心、真实WASM及浏览器生产者/消费者验收。外观/宽布局按风险覆盖三浏览器、实际键盘/鼠标及必要性能；性能仍保留原2秒/500ms目标与11.4已登记冷800/暖600ms备注容差，1000ms硬安全截止不变。

## 10. 兼容、回滚与验证要求

静态发布始终成套钉住内容/投影、Blockly登记、学习授权、前端消费者和引擎版本。候选失败保留旧有效组合并明确版本，不混装新课程和旧判题器；未知分析/编辑版本保留原草稿并禁止新执行，不删代码或降级“尝试运行”。回滚到旧单向编辑产品前，当前会话原代码先提示临时性；不能让旧UI读取其不理解的新草稿并覆盖。所有运行态仍为内存，换版本废弃旧上下文。

SAVE升级若已发生，旧应用只能按已冻结迁移决议只读/停写，不能删库、降schemaVersion、覆盖新字段或重建积分来回滚。旧通过、账本、已打开日期目标及别名记录保持；仅外观回滚不发学习事件。外观配置坏包使用内置基础主题并保留个人原记录/图片，不能借“恢复默认”删除学习数据。
