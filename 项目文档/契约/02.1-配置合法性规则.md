# 02.1 配置合法性规则

契约：CONTENT-01 / LEARN-EVENT-01 1.0.0；日期：2026-10-14。  
配套：[格式与引用](./02.1-内容格式与引用契约.md)、[结构Schema](./02.1-内容结构.schema.json)、[合法样例](./02.1-内容样例.json)、[非法样例](./02.1-非法配置样例.json)。

## 1. 校验顺序与拒绝结果

发布时校验整包，加载时在展示/运行/学习事件之前再次验证相关完整依赖。**任一error拒绝整份新包**；不自动修复、跳过坏题、混用缓存版本。可继续保留已验证旧包，必须明确其版本；没有旧包显示内容不可用及重试/返回，不能显示可提交或已完成。构建发布必须先校验再产出清单，正式浏览器实现由03.3负责。

1. 严格解析UTF-8 JSON，拒绝重复对象键和语法错误；普通JSON.parse会覆盖重复键，不能单独作为完整解析验收。
2. 检查contractVersion/packageVersion/purpose/phase及结构Schema；未知字段/枚举拒绝，不把未来版本读成当前版本。Schema阶段可识别的专用失败映射优先于通用CONTENT_SCHEMA_INVALID：contractVersion→CONTENT_CONTRACT_UNSUPPORTED、实体id格式→CONTENT_ID_INVALID、requiredExerciseRefs空→CONTENT_REQUIRED_EMPTY、引用列表uniqueItems失败→CONTENT_LIST_DUPLICATE；其余用通用码。这样CFG-03/06的局部规则无需通过Schema后才报。
3. 建全包ID索引，查重复ID/错误命名/实体版本；再查所有带版本Ref的存在、目标类型、精确版本与语言/子集。
4. 校验归属、顺序/先修无环、必修/案例反向关联、块覆盖、输入/绑定/样例及判题/奖励配置。
5. 对publishable进行正式内容/完整积木资产/模板/来源审核及Rust真实验收，contract-fixture不可发布为产品内容。当前没有这项产品证据。

内容诊断形状为`{code, severity:"error", path, relatedId?, expected?, actual?}`。path是包内JSON Pointer（例如/lessons/0/requiredExerciseRefs/0/version），只记录公开配置的字段位置/版本/ID，不附用户程序/输入；正文提示按错误类别本地映射。输入用户错误仅临时展示，不能写日志。此诊断独立于02.2的C/运行诊断。检查阶段有依赖：结构/ID索引无效则不级联猜测引用；同阶段可聚合，按path再code排序。

## 2. 规则与稳定错误码

| 规则 | 必须检查 | error.code / 明确结果 |
|---|---|---|
| CFG-01 | 非法JSON/编码/重复对象键 | CONTENT_JSON_INVALID / CONTENT_JSON_DUPLICATE_KEY；拒绝解析 |
| CFG-02 | 非当前结构版本、非法实体/包版本、未知字段/枚举、类型/空值错误 | CONTENT_CONTRACT_UNSUPPORTED / CONTENT_SCHEMA_INVALID；拒绝新包 |
| CFG-03 | ID语法或任意集合重复ID（包括跨集合、同ID不同version） | CONTENT_ID_INVALID / CONTENT_ID_DUPLICATE；不得最后一项覆盖 |
| CFG-04 | Ref目标不存在/目标集合类型错误/版本不精确 | CONTENT_REF_MISSING / CONTENT_REF_TYPE / CONTENT_REF_VERSION；不得使用最新版 |
| CFG-05 | reserved语言有subsetRef或被章节/题目/程序/积木执行引用；C子集/能力不存在；跨语言关系 | CONTENT_LANGUAGE_RESERVED / CONTENT_LANGUAGE_MISMATCH / CONTENT_SUBSET_INVALID；标识不等于执行支持 |
| CFG-06 | 章节order连续、3章各2节；共6节/6题/4demo/3algorithm/20块；小节必修至少1且P0恰1；同列表重复Ref | CONTENT_P0_COVERAGE / CONTENT_REQUIRED_EMPTY / CONTENT_LIST_DUPLICATE；缺题不能自动完成 |
| CFG-07 | 章↔节、节↔题/案例归属不一致、题目重复归属、先修自引/环 | CONTENT_RELATION_INVALID / CONTENT_PREREQUISITE_CYCLE；不生成错误目录/学习链 |
| CFG-08 | 学习修订≥1；acceptedPriorVersions唯一、不得含当前/未来版本，必须有同修订语义不变审核 | CONTENT_LEARNING_COMPATIBILITY_INVALID；未声明旧版不作当前通过，历史仍保留 |
| CFG-09 | fields唯一，必填整数/序列；数量/域按DEC-002；派生长度/索引/有序关系指向正确类型 | CONTENT_INPUT_SPEC_INVALID；课程输入域不可扩大；结果不限到-999..999 |
| CFG-10 | 示例和24组测试input恰好字段集合、整数值/域/序列数量，k关系/二分非递减 | CONTENT_INPUT_INVALID；不默认0/截断/静默排序；具体domain/length/index/order原因可临时提示 |
| CFG-11 | 绑定key唯一、inputKey存在、from/targetKind组合合法，数组有派生长度及占位规则；示例n/N/初始化一致 | CONTENT_BINDING_INVALID；删除/改名/重复源、隐藏改值不能执行 |
| CFG-12 | program/exercise/case精确引用同语言/子集；lesson块列表覆盖必修题程序所需块；connectionType按20类映射区分根/语句/表达式，槽/操作符在矩阵中 | CONTENT_BLOCK_MAPPING_INVALID；不生成伪代码或矩阵外C |
| CFG-13 | 每题profile.rule按六题目标；测试caseKey唯一/非空，完整继承24组；expectedExitCode=0、stdout精确、EX-05真实数组预期 | CONTENT_JUDGE_INVALID；EX-04两个目标都必过；不知道规则不能通过 |
| CFG-14 | 4demo/3algorithm的resultRule/程序/输入约束按原清单；二分必须nondecreasing；源码实例符合P0-C | CONTENT_CASE_INVALID；前端不得按rule重算算法 |
| CFG-15 | lesson/exercise/case的rewardRef分别关联对应eventType；daily来源once-per-day/local-day；其他first-only/content-id | CONTENT_REWARD_INVALID；文案版/运行号不能刷新首次奖励 |
| CFG-16 | 教学字段/来源非空，sourceExample完整公开实例；publishable有正式审核/资产/真实执行证据 | CONTENT_PUBLICATION_UNVERIFIED；fixture不能作为已支持课程发布 |

结构Schema只承担字段/枚举/局部数值限制；CFG-03—16的跨对象关系、教学覆盖、C/绑定语义和版本历史审核须另验。02.1用样例结构校验、关系检查、预期独立计算和只读复核验证设计，不冒称已实现线上校验器或Rust检查器。

## 3. 非法样例和可复现方式

非法样例使用一份合法contract-fixture为base，每个scenario独立克隆后按operations顺序修改，**不得串联场景**。每项操作的`op`为set/append/remove，path为JSON Pointer，value仅set/append；append作用于数组，remove移除对象属性或数组索引。它是验收夹具描述，既不是产品运行接口也不是通用脚本。expectedCode表示首要错误，其他同阶段错误可同时返回。

包坏例覆盖缺引用、重复ID、版本不匹配、reserved语言、空必修、归属错误、未知契约、非法输入/索引/二分有序、缺输入绑定、判题/块覆盖/奖励错误和学习兼容；另用原始JSON字符串检查重复键/语法错误。对应机器样例只定义数据/预期，非真实轨迹。

| 行为场景 | 应有明确结果/恢复 |
|---|---|
| 合法包、小节关联题目/案例 | 全图闭合，可找到6题及7案例；不代表产品功能完成 |
| 引用exercise.c.missing | CONTENT_REF_MISSING，拒绝包；修正后重新整包验证 |
| 重复实体ID | CONTENT_ID_DUPLICATE，无覆盖项 |
| 引用正确ID但version=1.0.1 | CONTENT_REF_VERSION，无自动升/降版本 |
| reserved语言请求运行 | CONTENT_LANGUAGE_RESERVED，提示语言标识预留，不能静默按C执行 |
| 学习历史1.0.0遇到新1.0.1 | 只有显式兼容且learningRevision不变才用于当前完成；否则保留旧记录供复习 |
| 新包加载失败/缓存只有旧版 | 保留明确标识的旧有效包或显示不可用；不删除学习数据、不混搭 |
| 真实输入无效或绑定改动 | 提交前及Rust边界拒绝；不发通过/完成/奖励；用户修正后重新实例化运行 |

## 4. 字段归属和增量

本次02.1字段由主窗口冻结为CONTENT-01 / LEARN-EVENT-01 1.0.0，台账登记。02.2只新增执行/DSL/临时判题事实契约，02.3只新增存档/迁移/幂等事务；如需改变本字段，先说明旧/新语义、影响对象/任务及迁移，再由02.1共享负责人合入新版本。02.4统一整个第二步的兼容/样例/双方验证流程，本次不替其验收。

内容修改、教学判据修改、契约修改分别更新实体/learningRevision/contractVersion及包版本；精确Refs一起更新。发布包须原子切换，旧学习记录与当前运行分别处理；代码/输入/包版本变化使相关临时运行失效，不能清空无关历史。03.3/09.1实现静态发布与加载，09.3/10.2验证真实生成和判定，11.1/11.4验证真实奖励和故障。
