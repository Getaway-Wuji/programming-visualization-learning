# 02.2 执行请求与生命周期契约

契约：**EXEC-01 / JSON-INT-01 1.0.0**；日期：2026-10-14；负责人：Codex-02.2 主窗口。  
依据：[DEC-005](../架构决策/02.2-StepDSL可逆与编码决议.md)、[02.1内容](./02.1-内容格式与引用契约.md)、[DEC-001](../架构决策/01.2-执行位置与运行形态决议.md)。配套：[Step状态/定位](./02.2-StepDSL状态与源码映射.md)、[诊断/预算/判题](./02.2-诊断预算与判题观测.md)、[Schema](./02.2-执行与轨迹.schema.json)。

## 1. 身份与上下文

所有运行数据只在浏览器当前临时上下文内存。ID是不含用户内容的不透明标识，匹配`[A-Za-z0-9][A-Za-z0-9._:-]*`，长度1—96；实际可用UUID，不能从源码/输入散列生成或持久日志记录。任何身份字段不匹配均拒收，禁止只比较最后一个runId。

| identity字段 | 唯一性/生命周期 |
|---|---|
| contextId | 当前题目/案例工作区与同题复盘共用；真正退出/清除/刷新后废弃，不跨标签共用 |
| contextRevision | 从1递增；积木、输入、内容包/题目/模板/子集或绑定映射改变时递增，使整个旧提交失效 |
| submissionId | 每次有效提交新建；固定该版本解答结构、subject/program/judge/packageRef和learningRevision；案例同样有提交身份 |
| runId | 每个测试组/案例的一次Worker实例唯一，不复用；重试另建 |
| sourceRevision | context内每份实例化完整源码/绑定/映射的唯一递增版本；同revision的任何字节/映射不变，不是内容version |
| testCaseKey | 练习取题目tests已有caseKey；案例和内部探针为null，不从输入值生成 |

同一练习提交顺序运行各组，P0最多一个Worker/一条当前可播放轨迹。开始下一组不废弃前组已验证的临时最少判题摘要；先释放上一组轨迹再接收下一组。遇首个失败停止，保留该组有效复盘；全过时保留最后组复盘及各组摘要。界面明确所保留caseKey，其他组不可冒用它的源码/轨迹，P0不承诺同时缓存/切换所有组轨迹。可重新提交重建证据；进入复盘不重跑程序。

同题工作区→复盘→返回保留已接受会话，不把正常完成改为取消；运行中离开需要先取消，不能声称已有完整结果。用户再次编辑立即失效旧当前判定/轨迹，02.1历史通过记录仍保留所属内容版本。

## 2. 请求字段

一个请求为`kind:"execute"`、protocolVersion/traceVersion/diagnosticVersion/judgeVersion/encodingVersion均1.0.0；精确字段见Schema。所有Ref复用02.1的`{id,version}`，不接受通配或自动latest。

| 字段 | 含义 |
|---|---|
| identity | 上述6字段，结果原样回显 |
| mode | case / exercise-test / contract-probe；probe仅文档/引擎验收内部入口，无学习事件，产品UI不开放此入口 |
| packageRef、languageRef、subsetRef、programRef、subjectRef、learningRevision | 当前静态包/语言/子集/模板/题目或案例；probe的programRef/subjectRef/learningRevision为null，其余模式必须匹配已验证内容 |
| engineRef | id/version/buildId，对应当前公开引擎发布物；buildId为技术构建标识，不是用户内容指纹 |
| source | text为正在显示/实际执行的完整UTF-8源码；blockMap为blockId及byteRange；bindingMap为bindingKey及声明byteRange，均限同sourceRevision |
| input | specRef、values及random；values是已经校验的实际输入。random为null或{generatorRef,seed}，seed为1—128字符的临时不透明字符串；精确生成算法和种子解释仍由07.2/02.4冻结，Rust不再随机换值 |
| judge | exercise-test必填{profileRef,rule,expectedStdout,expectedExitCode:0,expectedArray?}；case/probe为null；来自同版本公共题目，不带学习档案 |
| budgetRef | 固定budget.p0@1.0.0，对应DEC-004；调用者不能发送抬高预算值 |
| remainingMs | 派发时向下取整的剩余安全时间，1—1000；来自主线程原触发截止，不在Worker重新授予1秒 |

case/练习的inputSpec与program绑定一致，Rust边界再次校验字段/域/数量/有序和source.bindingMap的真实声明/初始化。参数声明位于main受控输入前缀，必须对应原输入源对象；检查声明AST身份、类型/容量和实际初始化，不靠名字/行号猜测。绑定缺失、改名、重复、指向遮蔽声明或声明值不等于输入均拒绝。程序副本、输入、映射随sourceRevision一起改变；不提供scanf/隐藏stdin。

probe为内部合成语义/预算样例，可不依赖正式模板，但仍受相同C子集/资源规则。产品适配只接受case/exercise-test，不因此建设自定义代码工作台。判题不得在前端重新执行或解析C；静态内容读取/实例生成与执行职责分开。

## 3. 响应与终止

结果`kind:"result"`，受支持请求正常回显全部协议版本、identity、engineRef及当前请求的package/program/subject/learningRevision；sourceRevision关联保留的请求源码，响应不重复整段源码。未知请求版本的拒绝响应使用当前受支持的1.0.0封套及主线程可信身份，diagnostic.details.expected/actual记录版本差异，不回显未知版本冒充受支持响应。`producer`为rust/adapter/fixture，fixture只允许离线契约验收工具读取，产品消费端必须拒绝。origin不能自证真实性；接受Rust结果还必须来自该run受控Worker/当前构建，不能把外部对象或预制夹具当Rust结果。

`nodeMap`和`resolvedBindings`由Rust生成，后者为{bindingKey,declarationNodeId}数组；trace为完整/有效前缀或null；terminal给status/exitCode/cursor/location/diagnostics；judgeResult为临时有限结论/覆盖/观测；stats为{fuelUsed,peakVirtualBytes,maxSyntaxDepth,maxAstDepth,rustMicros}或null，rustMicros在合成样例中为null，不能虚构实测时间。结果另回显languageRef/subsetRef/budgetRef。节点表/观测/诊断均计完整结果预算，不能在消息外另带无界图。结果不直接发学习奖励。

| terminal.status | trace / exitCode / 来源 |
|---|---|
| completed | complete，必须最后program.return、控制状态returned；exitCode为实际int32，返回非0仍是正常运行但不通过练习 |
| program-error | execute阶段可有prefix；lex/parse/semantic通常null；exitCode=null，实际语法/运行诊断来自Rust |
| rejected | null；协议/内容/输入/绑定不合法或不支持当前版本；不是运行成功/错误答案 |
| resource-limit | Rust可有prefix，也可解析前null；adapter超期通常null；exitCode=null，诊断指明维度/阶段 |
| cancelled | adapter null；不等待Rust收尾、不伪造前缀或运行统计 |
| infrastructure-failure | adapter null；模块/Worker/编码设施/WASM异常或结果协议无效，不能伪装成C语法错误 |

terminal.cursor为最后一个已提交步骤的K，trace=null时为null；失败位置可以是没有提交的下一表达式，绝不加一条伪失败步骤。终止不会改变已有state；画面在尾游标显示独立故障定位/停止原因，后退仍恢复该有效前缀各步的完整状态。prefix仅表示0..K可完整恢复，不表示程序完成。

## 4. 生命周期与竞争

主线程状态为idle→preparing→running→validating→accepted；尚未accepted时可进入cancelled/expired/invalidated/failed。有效点击/键盘触发即设单调时钟deadline=t0+1000ms，包括生成绑定、下载/Worker、Rust、传递、校验与初始绘制。练习内部后续测试沿用同一提交deadline；每组燃料/内存等run预算独立，但不能为各组重开1秒。500ms完整端到端目标也包含整次题目提交的全部必需检查，分组时间可另报，不能代替整体。

Rust从Worker派发点开始使用remainingMs建立本地相对截止，周期检查；不能直接比较两个上下文未对齐的绝对时钟。主线程在收到、校验完成及提交成功画面前再次检查原deadline，到达即过期。非阻塞前台取消恢复≤100ms继承DEC-004；后台恢复先失效超期run。计时实现留03/06/07，当前不证明实际毫秒时效。

1. 取消/编辑/更换输入/切换内容/清除先改主线程状态和revision，使run/submission不可接受，再终止Worker并废弃尚未完成加载/校验任务。
2. 来消息先核对受控Worker来源、它绑定的当前run、状态/首终态、期限和缓冲长度；再fatal有界解码/唯一键检查，读取并核对完整identity/构建/协议，随后Schema/结构/轨迹/判题校验；异步校验结束再核对身份/状态/期限。ArrayBuffer解码前不能读取其中identity；旧Worker来源可立即丢弃，当前Worker坏包呈协议故障。旧消息不生成学习事件/当前画面。
3. 终态只接受一次。取消早于accepted则排队完成也拒收；accepted已提交的终态不被晚到cancel改写。后续新编辑仍可废弃它作为当前版本的结果，不删除历史学习事实。
4. adapter终态使用主线程已知identity，不信任坏包中的标识。没有Rust终包时trace/statistics/judgeResult为null，location解释no-source；没有可验证前缀则不可复盘。

整题通过要求caseKey集合恰好等于该题tests，无缺/重复/混提交；每组current identity/source有效、正常返回0、stdout-exact/input-bindings/exit-zero/teaching-target均met。EX-04两子目标均met；EX-03同一分支siteKey在整个测试集合至少覆盖then/else，不能跨版本/提交拼接。取消/错误/缺证据均不发exercise.passed，消费只产02.1允许的最少摘要。

## 5. JSON-INT-01与传输

规范编码为无BOM UTF-8、无空白紧凑JSON。对象键限ASCII协议键/合法参数键，按ASCII码点升序；数组按语义顺序保留。键唯一。值只为对象/数组/string/boolean/null或安全范围整数，C值另限int32；十进制最短文本，不用指数、前导零、-0或浮点。字段缺失与null不同，以Schema明确；未知字段拒绝。

字符串必须为合法Unicode标量序列，拒绝孤立UTF-16代理项/非法UTF-8；引号和反斜杠分别编码为\"和\\，退格/制表/换行/换页/回车为\b/\t/\n/\f/\r，其他U+0000—001F为小写十六进制\u00xx；其余字符原样UTF-8，斜杠不转义。不规范字节表示即使能解码也拒绝；源码text的LF/CRLF保持原字节，不归一后沿用原定位。

编码前有界预检，编码过程中有界写入；接收先检查ArrayBuffer长度，再fatal解码、唯一键/深度检查、Schema与关系，最后核对重编码字节完全相等。整个JSON容器深度≤32，与C语法深度64不同；状态/AST采用扁平节点表，不传递无限嵌套AST。先检查线性长度再建对象，不无限解析后才测。单请求≤65536字节、单结果≤16777216字节，当前run消息一次完成，不分消息拼接规避总量。

终止必须有可编码空间：结果中预留65536字节给有界terminal/diagnostics/stats/结束结构，主体追加先核对“现有完整结果估算+候选原子步及可能检查点+保留空间”≤16777216。最多16个诊断，附加字段仅稳定码/位置/有界整数/技术信息，超出时不打印原始异常。预留仍计总16MiB，不是额外预算；最终实际完整编码必须复核。末尾编码/燃料/宿主失败不能把未送出的success当已接受，必要时adapter只能失败无轨迹。

源码/输入/seed/输出/轨迹/诊断及其指纹禁止URL/HTTP/日志/遥测/浏览器持久化。少量技术耗时/字节数/错误码按DEC-001临时处理。学习层不接收原始结果包，P0一条会话引用不复制整轨迹；P1双视图和P2能力另升版/验收。
