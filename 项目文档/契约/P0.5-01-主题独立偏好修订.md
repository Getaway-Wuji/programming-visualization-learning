## 1. 每个主题独立呈现与独立颜色

六个稳定主题ID为`minimal | cute | glass | soft | cool | tech`，名称依次为清爽代码学园、粉晶流体花园、珍珠磨砂书桌、暖光触感工坊、深蓝流光空间、轻雾灵感实验室。`appearance.preset`仅指向当前主题；主题的完整样式来自对应受控静态profile，各自拥有导航、页面外壳、面板材质、控件、图表及动效。切换主题不能只替换主色、圆角或同一套页面CSS变量后宣称重构完成；同一学习功能/判题/保存语义在不同主题中保持一致。

原`appearance.accentColor`删除，替换为固定六键的`appearance.themeOverrides`。每个键都必须存在，值为只有`accentColor`一个字段的封闭对象；`accentColor`只能为null或规范大写`#RRGGBB`。不得存任意主题ID、任意CSS、额外扩展字段或学习者代码。合法小写hex可在写入口规范为大写，入库值必须规范；null表示读取该主题在当前明暗模式下的受控默认色。

**完整默认appearance行：**

```json
{
  "preset": "minimal",
  "themeOverrides": {
    "minimal": { "accentColor": null },
    "cute": { "accentColor": null },
    "glass": { "accentColor": null },
    "soft": { "accentColor": null },
    "cool": { "accentColor": null },
    "tech": { "accentColor": null }
  },
  "blockWorkspace": "auto",
  "layout": {
    "sidebar": "expanded",
    "workbenchMode": "standard",
    "splitRatios": {
      "practice": 50,
      "visualize": 35,
      "review": 35
    }
  },
  "background": {
    "assetId": null,
    "visible": false,
    "fit": "cover",
    "position": "center",
    "overlayOpacity": 75
  }
}
```

新档/全清的`settings.theme="light"`不变；`settings.theme`仍为唯一`system | light | dark`来源，不添加按主题保存的第二套明暗。`avatar.accentColor`仍只属头像，与上述六个主题颜色互不改写。合法SAVE1.0.0迁移保留原settings.theme及头像色。

当前原始强调色精确读取为`appearance.themeOverrides[appearance.preset].accentColor`；为null则取受控配置`themes[preset][resolvedMode].accent`。同一主题在light/dark共用一个用户原选hex，明暗下的前景/底色/焦点可按对比度派生；不得把派生色反写成用户原选色，也不得让自选色覆盖成功/警告/错误语义。静态配置更新不能清空这六项用户覆盖值。

## 2. 切换、保存与重置

| 操作 | 必须修改的值 | 必须保留的值 |
| --- | --- | --- |
| 切换主题 | 仅`appearance.preset`；界面加载对应完整profile | 六项themeOverrides、settings.theme、背景图及配置、用户布局、积木偏好、全部学习数据 |
| 修改某主题颜色 | 仅显式目标`themeOverrides[themeId].accentColor` | 当前preset及另外五套颜色；若同次操作明确选择新preset可在同一事务一并保存 |
| 切换明暗/系统 | 仅settings.theme | 当前preset和六套原选色；实际派生配色重算，不改存档hex |
| 恢复当前主题默认 | 当前preset对应override的accentColor=null；重新呈现该主题受控默认样式 | 当前preset、另外五套颜色、settings.theme、背景、用户分栏/导航折叠/专注和积木偏好 |
| 恢复布局默认 | layout恢复expanded/standard与50/35/35 | 主题选择、六套颜色、明暗、背景和积木偏好 |
| 恢复全部外观默认 | appearance恢复上方完整默认行；settings.theme=light；清空appearance/appearanceAssets两个新store全部行后重建默认appearance | settings其他字段、avatar及全部学习事实/目标/回执/别名/账本；meta按同事务规则+1 |

“恢复当前主题”只恢复该主题可自定义的颜色和受控主题样式；profile本身不可被用户写入，恢复时无需另删profile记录。按钮文案应说明保留背景、布局和其他主题配色。若外观记录损坏，普通单主题恢复不能替代已经冻结的“确认重置全部外观”修复recipe。

切换主题从不顺带改settings.theme。cool主题的暗色建议及tech主题的浅色建议只能通过文字推荐呈现，不能在首次点击、从其他主题返回或刷新时强设dark/light。首次新档默认minimal/light；若用户已选dark/system，切到minimal/cute/glass/soft/tech也保留该选择。

颜色编辑命令必须包含明确`themeId`，不能等颜色选择器或异步预览回调结束后才读取“那时的当前主题”决定写入目标。例：清爽代码学园选`#6D28D9`、粉晶流体花园选`#DB2777`，来回切换后应分别恢复这两个值，glass/soft/cool/tech仍为null；在粉晶流体花园主题中恢复当前主题后，仅cute变null，minimal仍为`#6D28D9`。设置面板可明确编辑非当前主题，但保存时不自动切换preset。

## 3. 事务、并发与失败

数据库、键和store数量不变：原九store加appearance和appearanceAssets，仍只有一个`c-viz-learning` DB。所有新操作经统一service，事务scope包含全部11个store，使用现有`meta.generation/revision`及会话epoch；不得为每套主题另建DB、store、localStorage镜像、颜色revision或第二套明暗源。

切主题、写颜色、恢复当前主题及全外观重置都必须检查expectedRevision CAS。事务内重读当前appearance，仅修改该操作的目标字段，不能用页面缓存的完整themeOverrides覆盖另一个标签的五个其他有效颜色。另一标签改任何主题颜色、同标签学习保存、目标/头像保存均可推进meta.revision，使旧外观草稿返回`S_REVISION_CONFLICT`；保留草稿并明确刷新后重新应用，不静默last-writer-wins或替换revision自动重试。

只有transaction.complete后再读并确认世代/epoch仍匹配才显示已保存。完整相同值可在先通过CAS后返回no-op，不增revision。abort/quota/连接关闭/未知版本时不部分修改preset或某套颜色；先前六套颜色和背景全部保留，临时预览明确标未保存。重置全部外观的确认范围继续包括两个新store的损坏/孤立/异世代/额外资源行；原九store只允许meta与settings.theme按上述操作变化。

themeOverrides缺键、多键、非规范颜色或原单一accentColor等非法外观结构按`S_RECORD_INVALID`处理：保留原行，标`appearanceReadOnly`，临时使用无图默认appearance投影；合法settings.theme仍生效。原九store合法时真实学习继续可保存，普通外观写暂停至用户明确确认全外观重置。未知DB/schema版本依旧完全拒写/拒清除，不把它降级成仅外观故障。广播仍只含generation/revision，不传各主题颜色。

## 4. 已发布DB1到未来DB2的唯一迁移

已有合法physical1/SAVE1.0.0升级时，直接创建本修订的appearance行：preset=minimal，六个override均null，其他默认如上，无图片；不先生成旧单一accentColor或四键设计行再补迁移。原settings.theme、头像、所有学习键值/分值/目标/回执/别名保持；只让meta.dbVersion变2、schemaVersion变2.0.0、revision从r增至r+1。事务失败整体回到完整physical1，未知前驱不自动修复。

旧设计中的`appearance.accentColor`及四键themeOverrides均从未投入产品或发布成用户档案，因此不承诺对“既有DB2单色字段/四键字段”迁移、不猜该颜色应复制给哪套主题，也不凭设计文档虚构2.0.0→2.1.0兼容历史。若隔离开发fixture主动构造旧设计的DB2形状，它属于本修订的非法外观测试输入；保留原行、只限制外观写，允许明确重置全部外观。未来实际发布后再改变该封闭模型，仍须另登记真实前驱版本和迁移recipe。

## 5. APPEARANCE-CONFIG的版本和profile/layout边界

独立静态资源继续为**APPEARANCE-CONFIG-01 1.0.0**；它尚未发布，本文直接明确首次正式格式。正式配置根必须含`contractVersion:"1.0.0"`、`schemaVersion:"1.0.0"`、不可变`configRef:{id,version}`，两个版本字段都须精确匹配，不推测相邻版本兼容。configRef.version是具体资源版本，与两项格式版本职责不同；manifest登记同源路径、字节数、SHA及用途。设计预览文件中的`purpose/runtimePublished`等声明不把它自动变成正式生产配置。

`themes`严格具有minimal/cute/glass/soft/cool/tech六个条目。每条含名称、light/dark受控token及必填`profile`，profile含shell/navigation/panel/control/chart/motion六个字段，均为下表白名单变体ID；它们选择预先实现的组件表现，不接脚本、HTML、任意CSS文本或URL。同一主题须使用其对应整行组合，不允许公共配置任意拼接出未验收的混合主题。

| 主题 | shell | navigation | panel | control | chart | motion |
| --- | --- | --- | --- | --- | --- | --- |
| minimal | paper | sidebar-text | academy-sheet | flat | ink | quiet |
| cute | jelly | top-capsule | liquid-glass | elastic-capsule | crystal | soft-spring |
| glass | ambient | floating-rail | frosted-pane | frosted-pill | clear | float-feedback |
| soft | tactile | bottom-dock | soft-relief | pressed-key | relief | gentle-press |
| cool | theater | tool-rail | sharp-stage | sharp-key | stage | crisp |
| tech | mist | soft-rail | airy-relief | soft-key | airy | soft-shift |

其表现责任分别为：清爽代码学园的左侧文字导航与清晰课程纸面；粉晶流体花园的顶部胶囊导航、粉色流体/晶冻窗口及底部悬浮操作坞；珍珠磨砂书桌的环境式外壳、浮动导航轨、珍珠磨砂窗片及通透图表；暖光触感工坊的暖黄触感外壳、底部操作坞、柔和浮雕与按压控件；深蓝流光空间的194px完整文字侧栏（紧凑时64px）、标签带、深蓝流光及锐利剧场面板；轻雾灵感实验室的浅雾拟物外壳、柔和导航轨、轻盈浮雕面板和软质控件，推荐浅色表现。profile下需要的尺寸/材质/阴影/透光/曲线值由同一主题的受控设计token提供，都是静态配置或实现，不复制进个人存档。玻璃失效/低性能时必须有主题内可读的实色回退；代码与可视化数据仍保持清晰对比。

预设页面背景只允许纯色或同色系低幅渐变，不加入照片、风景、室内场景或其他场景图片，也不为预设写入appearanceAssets资源行。流光、粉色流体、磨砂与拟物效果由受控颜色/材质/渐变表达，不能通过自动附加场景图实现。未来P0.5-03的用户主动本地导入能力仍保留；该能力继续遵守原单张格式/5MiB/4096预算及同事务保存规则。切主题不会删除或替换用户已主动导入的图片。

motion变体仅定义反馈表达，不代表可启动持续背景动画。tech的soft-shift只允许用户触发操作后不超过600ms的轻柔反馈；cool的stage不得启动持续剧场动画。`settings.reducedMotion`及系统减少动态偏好优先，启用减少动态时停止弹性位移和非必要动态。算法/播放器的真实执行步与速度不由主题motion控制。旧tech技术ID及旧minimal.panel仅为未发布设计，本次静态变体修订不需要用户存档迁移，不改变DB2/SAVE2目标。

| 数据位置 | 可放内容 | 禁止放入 |
| --- | --- | --- |
| 静态根layout | 可用宽度、阅读上限、断点、安全最小面板尺寸、分栏30..70范围及50/35/35默认等共用可达性约束 | 用一个强制导航宽度/面板外壳覆盖六种不同主题 |
| 静态themes[id].profile及该主题token | 该主题导航形态、课程纸面/粉色流体/珍珠磨砂/暖黄浮雕/深蓝锐边/浅雾拟物材质、对应尺寸/控件/图表/反馈的受控组件变体 | 用户偏好、学习结果、执行语义、任意可执行文本或外部资源URL |
| SAVE appearance.layout | 用户expanded/collapsed、standard/focus、practice/visualize/review三比例 | 静态profile、副本shell/navigation、推导坐标、CSS像素、临时窄屏标签 |
| SAVE appearance.themeOverrides | 六套独立用户accentColor | light/dark色板副本、生成的对比色、静态profile、第二个theme字段 |

`layout.sidebar`保留为跨主题的“导航完整/收起”用户偏好，不强制所有主题都有左侧栏：paper对应完整文字侧栏/收起栏，jelly对应完整顶部胶囊/紧凑导航，ambient对应浮动轨完整标签/紧凑图标，tactile对应底部坞完整标签/紧凑图标，theater对应轨道辅助文字/仅图标，mist对应柔和导航轨完整标签/紧凑图标。每种表现都须保持相同页面入口、键盘可达和当前页标记。`workbenchMode`与分栏比例也是跨主题用户选择；不同profile可重构其导航与壳体，但不得在切主题时重置这些选择或压缩关键工作区域。

静态配置未知版本/坏profile/缺主题时拒绝整个配置并使用受控内置minimal可读回退，明确外观资源加载失败；保留已保存preset、六套颜色、背景与布局，不将临时回退写入DB。课程编辑推荐仍由TEACHING-PRESENTATION-01负责，不能塞进APPEARANCE或profile，也不能授予新语法/学习事件权限。

## 6. 修订验收与实施边界

本次设计检查须核对完整默认JSON、固定六键、版本一致性及profile边界。P0.5-02/10的真实验收至少补充：

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| AT-01 | 六主题分别修改为不同颜色、反复切换及刷新 | 每个主题独立记忆；所有页面呈现对应完整profile，不只是同壳换色 |
| AT-02 | 主题切换×light/dark/system | 切preset始终不改settings.theme；明暗改变不改六套原选hex |
| AT-03 | 恢复当前主题/恢复全部外观/取消 | 当前主题仅清自己颜色；全外观恢复minimal/light及六null并删图；其余五套或学习数据的保留符合操作范围 |
| AT-04 | 颜色编辑回调晚到、两标签改不同主题、学习同时保存 | 明确themeId不串色；旧revision冲突且保留草稿，无整张themeOverrides覆盖 |
| AT-05 | DB1→新DB2、升级abort、手工旧DB2单色/四键坏fixture | 直接生成六null；旧九store保留；失败完整回滚；坏fixture不被猜测迁移或全局阻断学习 |
| AT-06 | 配置缺schemaVersion、未知版本、缺profile/非法ID、坏包回退 | 严格拒绝坏配置；内置可读回退但不覆盖用户记录 |
| AT-07 | 六profile桌面/窄屏/键盘/专注/布局保存 | 导航与材质可辨识，功能同等可达；用户比例不因主题切换丢失 |
| AT-08 | 流光/玻璃/拟物/弹性/轻柔反馈及减少动态、预设背景检查 | 可读且主题内有回退；soft-shift≤600ms，减少动态生效，无持续装饰动画；预设仅纯色/低幅渐变，无场景图，不自动写图片store |

本文件仅更新未实现的修订设计，不改产品、旧存储设计、现用Schema、中央台账或历史验收。原设计需由协调窗口添加supersede入口并同步总决议/设计变量/预览/影响登记后使用；正式实施仍须单独领取P0.5-02，不以此文冒称完成主题、迁移或运行验收。
