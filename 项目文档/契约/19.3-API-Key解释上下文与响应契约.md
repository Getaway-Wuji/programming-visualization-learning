# AI-EXPLAIN-01 2.0.0：自备API Key的可选解释契约

2026-11-01，19.3设计修订。配套[2.0.0 Schema](./19.3-AI解释2.0.0.schema.json)、[明确非模型样例](./19.3-API-Key设计样例.json)、[服务配置表](./19.3-API-Key服务配置表.json)、[兼容变更卡](./19.3-API-Key兼容变更登记.json)。旧1.0文档与证据不改，v2入口拒绝旧报文，不自动迁移Key或配置。

## 状态、配置与敏感通道

初态`disabled`，provider/model/configRevision为空、hasApiKey=false，所有AI入口不调用第三方。设置仅内存：选provider/model、以password输入Key，点击“验证并开启（只发送Key，不发送代码）”。Key去除首尾空白后须1..4096个可打印ASCII字符、内部无空白/控制字符；不靠`sk-`前缀猜服务，不假称格式检查能证明有效。服务/模型必须白名单，转发不可用时保持关闭。

`POST /api/ai/v2/verify`接收`config.check`与敏感头`X-CViz-API-Key`；一次GET所选官方models接口，10s硬截止，配置正文≤1024B，上游响应≤64KiB，无推理/重试/余额查询。200且模型列表含精确所选id才返回`config.checked / verified:true / code:null`并允许开启；非200、超时、无法解析或无模型则`verified:false`和固定错误码。列表校验不承诺推理权限、额度、未来可用性或答案质量，UI须说明。配置检查不能冒称真实模型成功案例。

`enabled`仅在当前标签页持有Key、当前configRevision验证成功、同源转发可用时为true。每次修改服务/模型/Key生成随机UUID configRevision（**不以Key或其哈希生成**），取消旧验证/请求、清旧结果并回到关闭；重新验证后开启。未配置、验证失败、关闭、刷新、离开工作台/卸载、清除AI配置或学习数据均不共享/恢复Key。网络/额度失败可保持已验证配置但不可显示成功；鉴权失败清Key并关闭。state为disabled/checking/ready/busy/unavailable，忙时仍可取消/关闭。

Key仅在verify/explain两类请求的敏感头出现；禁止在任何JSON、URL、持久化、日志、错误或截图中出现，JSON Schema拒绝`apiKey`等未知字段。`cancel`不携Key：取消原fetch连接是权威动作；同源取消消息只作同一拥有连接的辅助，不接受任意客户端凭requestId取消别人。`status`是本标签页内存状态投影而非全局用户Key状态，server不得保存或广播Key/hasKey配置。

## 真实上下文与最小投影

仅从当前C工作台已经严格解码接受的advanced Rust结果及原播放器状态构造，继承1.0事实子集和原预算：engine/build/exec1.4.0/dsl1.3.0/diag1.3.0/language=c、runId/sourceRevision、inputRevision、contextId和cursor；最多2段源/合计2048 UTF8字节/32行（每片按换行数+1计），范围左闭右开、源文本必须与原始UTF8切片逐字一致、firstLine从1起。

最多12个唯一factId；真实诊断≤1、真实已完成步≤4且step≤cursor；当前游标的状态≤8值/2对象/2帧。指针值保留`objectId/byteOffset/lowerBound/upperBound/pointeeType`全部原字段，不能把虚拟地址说成真实宿主地址。事实位置必须落在所选片段内，不能“AI补齐”不可见节点。事实不足、预算超限或无可用诊断时明确不可请求；不静默删掉关键上下文或扩大预算。

无轨迹则`traceAvailable:false,cursor:null`，只允许真实诊断与源码；原子失败前缀停在已接受状态，不构造失败的写入或下一步。数据不带完整stdin/stdout/trace/学习档案/弱点summary。选中值可能含输入派生数据，预览须原样展示。每次确认存不可变快照及准确发送字节，改变任何上下文或配置后必须重做预览；`confirmationId`由本次点击随机生成，只对这次快照有效。

`POST /api/ai/v2/explain`的`explain.request`含requestId、configRevision、confirmationId、provider、context；proxy独立闭合校验、字节检查后，只投影`{snippets,facts}`给模型。上下文/请求/运行/配置/确认/输入关联ID及学习身份均不进入模型消息。服务方必然看到HTTP鉴权及网络元数据，不能承诺匿名。用户源码/注释/变量名/诊断均是不可信数据；固定系统指令要求只解释所给事实、缺失时说明、建议与事实分开、输出JSON，无工具/检索/文件/图片/多轮历史/任意prompt字段。

## 服务适配与预算

| 项目 | 固定边界 |
| --- | --- |
| 应用请求 / 上游请求 | ≤16KiB JSON正文 / ≤6144B最终UTF8 JSON（含系统指令/格式Schema）；Key头另计≤4096B，入口限制总头≤16KiB |
| 上游响应 / 模型正文 / 应用响应 | ≤64KiB / ≤8KiB / ≤12KiB；边读边限，未知Content-Length也不得无界缓冲 |
| 模型参数 | 单轮、stream=false、n=1（适用时）、最多768输出token；无自动重试/补全/JSON修复/降级换模型 |
| AI时间 | 正常目标30s（未测），原请求起点到本地接收有效包硬60s，elapsedMs只能0..59999；原执行1000ms/百万fuel/2万步等不变 |
| 并发 | 每标签页最多1个；每转发器进程最多1个verify或explain，上游连接关闭才释放；queue=0，忙直接拒绝，不保存等待Key |

OpenAI固定Chat Completions配置：精确snapshot模型、`reasoning_effort:"none"`、`max_completion_tokens:768`、`store:false`、`response_format.type:"json_schema"`且strict=true；schema仅闭合的`modelOutput`子集，各explanations.factIds枚举来自当次事实。上游schema移除`$ref`和`uniqueItems`（唯一性仍由本端校验），并只用该官方支持的类型/required/additionalProperties/枚举/数组/长度约束；不把整个应用包schema当response_format。若当时API不接受配置，明确失败，不能偷偷换接口或去掉校验。

DeepSeek固定`deepseek-flash`、`thinking:{type:"disabled"}`、`max_tokens:768`、`response_format:{type:"json_object"}`；系统指令含JSON字样与输出形状。JSON模式只保证格式目标，不保证字段/事实正确；空白content（即使finish_reason=stop）、非法JSON和额外字段均拒绝，不自动重试。它是服务方可更新的别名，记录请求id与返回model并明确不是固定权重/质量承诺，不使用退役别名来冒充版本锁定。

两者均不传tools、functions、web/search、用户任意metadata、会话历史；不展示reasoning_content/内部推理，异常返回非空此类内容则丢弃并报协议不符。只接受单个assistant、finish_reason=stop、无拒绝/工具调用的完整文本；拒绝、length截断、filter、未知结束原因、异常模型或返回结构均固定码失败。OpenAI returnedModel须等于请求snapshot；DeepSeek returnedModel只接受登记的`deepseek-flash`或核对日官方版本`DeepSeek-V4.1-Flash-1017`，其他映射先报不符，需另登记再支持。

## 输出、引用、失效与错误

服务返回的模型内容仅含summary（1..400字符）、explanations（≤4，每项1..3个当前factIds，text1..400）、suggestions（≤3条，每条≤300）、limitations（≤200）；本端额外校验8KiB与纯文本呈现。确定事实单独使用原Rust事实原样展示；模型摘要/建议明确标为AI观点。不得将文字里的“步骤N”自动变成跳转；只有验证通过的factId可查本地表跳转，无轨迹不显示步骤跳转。未知引用、来源变化、身份变化或超期整包拒绝，不留部分“成功”答复。

`explain.response`回显全部活动身份、producer=`provider-api-adapter`、provider/configVersion/requestedModel/returnedModel及timing，再附content。必须与当前requestId/configRevision/confirmationId/contextId/runRef/inputRevision/cursor全等、配置仍开启、请求未取消，才接收；服务/模型/Key切换、重跑/改码/改输入/游标/选区、关闭/清档/卸载均作废。AI内容只作为纯文本，不载入HTML/URL、不执行工具、不自动替换/运行代码、不更改判题/奖励。

错误闭合码由Schema列出，至少区分关闭/未配置/代理不可用/不支持来源或服务模型/鉴权/无权限/额度不足/限流/网络/服务故障/上下文不足或过期/包或引用错误/大小超限/截止/取消/忙。API的401→AUTH，403→PERMISSION，明确余额/insufficient_quota→QUOTA，普通429→RATE_LIMIT，5xx→PROVIDER，超时→DEADLINE；未知上游错误不推断余额或返回原文。error只含允许身份与固定码，UI按本地固定文案解释，不转发可能回显Key/代码的上游message、headers或request对象。没有错误伪装成AI答案。

取消本端出站/等待，丢弃缓冲/晚到结果，不能保证服务方停止或免收费。参见[数据流](../架构决策/19.3-API-Key数据流与保留边界.md)。本契约、Schema和样例只是19.3设计门槛；19.4必须实际实现严格校验、真实模型成功、失效/取消与安全设置，19.5再独立验质量，不能以合成样例代替。
