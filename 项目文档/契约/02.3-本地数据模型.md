# 02.3 本地数据模型

契约：**SAVE-01 1.0.0**，DEC-006 V1.0，2026-10-14。与[事务规则](./02.3-事务日期与奖励幂等.md)、[迁移规则](./02.3-迁移与恢复规则.md)、[Schema](./02.3-存档结构.schema.json)共同生效。JSON样例为contract-fixture，是九个store的一致只读投影，不是实际数据库文件、导入/备份接口或已保存的用户档案。

## 1. 数据分层

| 类别 | P0存储与寿命 | 禁止混淆 |
|---|---|---|
| 业务事实/进度/账本/目标/打卡 | IndexedDB至用户清除或浏览器移除 | 与当前程序是否通过/保存状态分开 |
| 头像/显示偏好 | 同DB singleton，经过统一事务 | 不另存localStorage镜像；不上传图片 |
| 当前积木/源码/输入/seed/提交与观看覆盖 | 当前上下文内存；真正退出/刷新/关闭丢弃 | P0不自动保存草稿或观看覆盖 |
| 执行检查点/Step DSL/虚拟对象/输出 | 02.2当前有效会话内存 | 不是持久编辑历史或学习记录 |
| P1逻辑编辑历史/断点/复习/徽章、P2笔记/薄弱点 | 此版本没有字段/store | 13/15/19/20显式增量；不建空功能表或通用JSON袋 |

## 2. 字段和键

DB物理版本是正整数1，语义schemaVersion是精确1.0.0；未来版本只读阻止写回。九store采用out-of-line key、不启用autoIncrement；meta/settings/avatar单体键均`"current"`，集合键用下表IndexedDB复合数组，不能用未转义分隔字符串。snapshot集合行的generation由meta唯一指定，真实集合物理键包含它；查询必须限定本世代。公共Ref `{id,version}`沿用CONTENT-01；local-goal Ref的version专用正整数十进制字符串（如`"1"`）对应goalVersion，不套三段内容version。UTC时间固定`YYYY-MM-DDTHH:mm:ss.sssZ`，日`YYYY-MM-DD`必须是有效公历日，数值为有限安全整数（偏好playbackRate为封闭枚举）。禁止未知字段、重复JSON键、孤立代理字符或任意对象正文。

| store/投影 | 键及字段 |
|---|---|
| meta | singleton `"current"`；schemaVersion、dbVersion、generation、revision、timeZone、createdAt、activePackageRef。revision从0，每次有效变更+1；清除新世代从0；耗尽安全整数则只读不回绕 |
| settings | singleton；theme=system/light/dark、reducedMotion=system/on/off、playbackRate=0.25/0.5/1/1.5/2/4、goalTemplate=null或`{revision,targets}`。默认system/system/1/null；targets有exercise/lesson/case三项0..100且合计>=1；推荐数量留11.2 |
| avatar | singleton；presetId（受控公共资源ID）、accentColor（规范大写`#RRGGBB`）；默认avatar.basic.01、#168A72，仅基座选择/强调色，不存URL/Base64/自由HTML；完整资产/选项留11.3 |
| progress | `[generation,eventType,subjectRef.id,subjectRef.version,learningRevision]`；eventType/result沿用02.1，禁止daily-goal.achieved；subjectRef、packageRef、learningRevision、firstAt、lastAt；attempt另有resultCategory及可空failedCaseKey，其他行禁止这两字段 |
| dailyFacts | `[generation,localDate,eventType,canonicalSubjectId]`；只exercise.passed/lesson.completed/case.view-confirmed，subjectRef、canonicalSubjectId、occurredAt、localDate；同日同类型同稳定主体1行，跨日须新有效事实 |
| goals | `[generation,localDate]`；localDate、goalVersion（正整数）、targets或null、achievedAt或null。opened日快照不可改；null表示尚未配置，不自动达成/打卡；achievedAt才是打卡依据 |
| ledger | `[generation,sourceId,canonicalSubjectId]`首次来源，或`[generation,sourceId,localDate]`日来源；sourceId、subjectId、localDate、occurredAt、status=pending/posted、points、policyRef。subjectId是规范身份或local-goal.<日>；pending两项null，posted安全非负整数points+公共policyRef |
| receipts | `[generation,eventId]`；eventId、eventType、subjectRef、packageRef、learningRevision、result、goalVersion、occurredAt、localDate、committedRevision；attempt另有resultCategory/failedCaseKey。内容事件Ref/修订非null；日事件subjectRef为local-goal Ref、packageRef/learningRevision为null。完整白名单摘要逐字段相等才是原重试，没有原始执行证据或内容哈希 |
| aliases | `[generation,fromRef.id]`；fromRef、toRef、fromAcceptedPriorVersions、kind=lesson/exercise/case、learningRevision、manifestRef。保留精确迁移端点及来源显式兼容版本，不凭ID相等接受所有旧版本；历史Ref不改写；见迁移规则 |

进度行firstAt取最早、lastAt取最晚有效事实，失败只留该题该版本最新一行，较早迟到失败不覆盖较新失败。行存在表达历史事实，不在本模型持久化`currentPassed`、总积分、等级、完成百分比、知识图谱或解锁位。当前小节完成以兼容确认+全部必修题兼容历史通过派生；保存completed行只是历史，不能盖过当前内容谓词。

## 3. 白名单和关系

允许最少标识/版本/修订/时间、公开结果枚举、账本数量和偏好。禁止runId/submissionId/sourceRevision、源码/积木、输入/seed、stdout/诊断正文、AST/轨迹/原始观测、内容哈希；不以“摘要”改名保存这些值。resultCategory仅02.1六类，failedCaseKey若非null必须是对应公开题目测试之一。

started/confirmed/completed分别属lesson，passed/attempt属exercise，view属case；subject/package版本必须来自已验证包。缺失旧公共条目保留历史，不强迫删除；它不能用于当前完成。dailyFacts身份经过合法alias规范化；目标计数按三类行数，不按attempt/浏览/播放帧/测试组。daily-goal.achieved是统一学习层派生，只进入receipt和对应ledger/goals，不放内容progress。

ledger四个sourceId固定02.1四项，source和主体类别一致，首次奖励不含entity version/learningRevision/run。日奖励subjectId固定`local-goal.<YYYY-MM-DD>`、goalVersion只决定配置不决定奖键。政策引用是11.1受控公共积分配置，不伪装成CONTENT-01已存在实体；posted一经入账不重算，积分=posted points总和，pending不计。**聚合使用BigInt或等价精确整数，不能让多行安全整数之和静默失精度；该派生大整数以十进制文本展示，不作为JSON数值缓存入库。**头像/偏好更新须expectedRevision CAS，冲突需刷新并明确重新提交，不覆盖其他标签旧值。

根投影只包含meta/settings/avatar及六个集合；没有extensions字段。Schema表达结构，关系校验另负责唯一复合键、日期/时区、版本/来源、内容兼容、账本关系和派生谓词；不能仅通过Schema就认为真实奖励合法。[存档样例](./02.3-存档样例.json)和[场景](./02.3-迁移与并发场景.json)均使用合成数据。
