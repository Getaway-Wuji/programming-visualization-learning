# 02.1 学习事件与奖励边界

契约：**LEARN-EVENT-01 1.0.0**；日期：2026-10-14；负责人：Codex-02.1 主窗口。  
依据：[01.1 完成判定](../架构决策/01.1-一期范围与用户路径.md)、[内容契约](./02.1-内容格式与引用契约.md)、[DEC-001 数据规则](../架构决策/01.2-日志与数据保留规则.md)。这是业务事件语义，不是Step DSL、已建账本或02.3存档事务。

## 1. 事件字段与最少数据

统一学习层是唯一接受事件并更新进度/奖励的入口；页面/播放器/Worker不得各自增分。事件带`eventContractVersion: "1.0.0"`、`eventType`、`subjectRef`（精确id/version）、`learningRevision`（仅内容事件）、`packageRef`（内容包id/version，仅内容事件）、`result`（表内枚举）。仅exercise.attempt-evaluated另带必填`resultCategory`（下文枚举）及可选`failedCaseKey`（只能引用该题tests中已有caseKey，不接收正文）；其他事件禁止这些字段。不接受任意payload。发送端到学习层的事件ID/本地清除世代/发生时间/日期/事务与幂等键由02.3冻结，当前文档不定义存储行格式。

事件接收前在临时内存验证当前run/submission/source及题目测试/观测，02.2定义这些证据对象；验证后仅留下本表允许的最少摘要。持久学习记录只保留必要标识、版本、判定修订、类别/通过摘要、日期及02.3规定的幂等信息。不得保存源码、积木、实际输入/seed、输出、诊断正文、轨迹/AST/原始观测或它们的内容哈希指纹，不发送学习档案给Rust。公共内容引用允许，不相当于记录用户程序指纹。

| eventType（稳定标识） | subjectRef类型 / result | 接受前提及进度效果 | 奖励来源 |
|---|---|---|---|
| lesson.started | lesson / started | 用户进入有效小节或启动其练习；无学习活动时为未开始 | 无 |
| lesson.study-confirmed | lesson / confirmed | 用户主动确认该版本目标/讲解已学；不能由滚动/计时/播放自动触发 | 无，等待小节完成 |
| exercise.attempt-evaluated | exercise / failed | 当前提交得到有效不通过结论；保存至多必要结果类别和测试caseKey，不保存失败内容 | 无；不抹掉兼容历史通过 |
| exercise.passed | exercise / passed | 该题全部测试及教学目标满足、每组Rust正常结束返回0、版本/当前提交有效；记录历史通过 | reward.exercise.first-pass |
| lesson.completed | lesson / completed | 当前学习确认+全部必修题兼容有效通过，由学习层派生；不是UI随意上报true | reward.lesson.first-completion |
| case.view-confirmed | case / confirmed | 独立案例模式的真实成功运行，按下节完整观看且主动确认；不算题目通过/小节完成 | reward.case.first-view |
| daily-goal.achieved | local-goal / achieved | 由11.2根据去重学习事实满足当天已定目标；日期/subjectRef本地ID由02.3定义 | reward.daily-goal.once |

事件中`subjectRef`为local-goal时不使用内容entityRef，不携带packageRef/learningRevision。local-goal的稳定ID/配置版本由02.3定义，本次只预留事件类型和业务效果。`exercise.attempt-evaluated`的允许结果类别为wrong-answer、teaching-goal-unmet、program-error、cancelled、resource-limit、infrastructure-failure，区别保留。取消/无有效结果时不伪造“已判定错误答案”，只记对应尝试终止类别；检查阶段的输入非法不发通过或小节完成。若无需保留失败摘要，可不保存该事件，不能影响通过的判定或将错误视作成功。

## 2. 小节和当前提交

小节完成谓词：当前有效内容的学习确认存在，且requiredExerciseRefs非空、引用均合法、每题存在兼容历史通过。选做题不阻塞。required列表缺失/无效是内容缺陷，不自动完成。兼容判断为同ID/同learningRevision且版本精确当前或显式acceptedPriorVersions；02.3迁移不得静默清空有效学习记录。

当前程序变动后旧运行/判定立即失效；旧成功记录保留为带版本的历史，不能将当前修改的程序标为通过。晚到结果必须先检查身份，不发新事件。已经接受的真实通过不会被后来错误尝试撤销；不要求强制播放完整题目复盘才认可通过。完成状态与保存状态分开：写入失败只能显示临时完成/本次未保存，允许幂等重试。

EX-04是同题的while/for两个必过目标，全部通过只发一次exercise.passed，不分成两题/两次奖励。EX-05的真实返回前数组观测只在内存验证，不进入学习记录。测试多个run合成一个提交结果，只有全部成功才发一次题目通过；某组失败/取消/超限，不能用其他组成功发部分通过奖励。

## 3. 案例观看判据

适用于4个语法演示和3个算法案例。case.view-confirmed须同时满足：

1. 已验证case/program/subset/input引用和当前运行身份，运行使用该版本公共模板与合法输入，Rust正常结束且返回0，结果符合该案例规则；不能用静态代码/预制轨迹。
2. 从游标0开始，在同一次有效运行中实际呈现每个原子教学步骤的执行后状态，前向相邻步骤形成0至终点的完整覆盖。播放和手动前进均可；暂停/后退不清除已看覆盖，但跳转/直接设终点不能补齐未看步骤。原子步骤及零步终点由02.2定义，零步时须实际呈现已验证的初始/终态。
3. 在满足上述条件后用户主动确认已观看；不设停留时长。更换输入/程序/案例使本次临时覆盖和确认失效；刷新不能持久化覆盖/轨迹补成已看。

播放器只上报临时“哪些真实状态已经呈现”的事实，统一学习层检查谓词。播放速度/动画帧数不是教学步数；不得跳过契约步骤后算看完。exercise-review模式不发案例观看事件，教师独立演示可按明确确认获得案例首次奖励，但不会完成关联课题。界面控制与判据由08/11.1落实，当前只是已定业务规则。

## 4. 奖励来源、重复和目标计数

| 稳定奖励来源ID | 允许事件 | 业务去重范围 | 重复政策 |
|---|---|---|---|
| reward.exercise.first-pass | exercise.passed | 来源ID + 稳定exercise.id；不含run/source/version/测试组 | 首次一次；兼容复习/重提/内容升版不自动重奖 |
| reward.lesson.first-completion | lesson.completed | 来源ID + 稳定lesson.id | 首次一次；题目奖励与小节奖励为不同来源 |
| reward.case.first-view | case.view-confirmed | 来源ID + 稳定case.id | 首次一次；重新输入/播放/确认也不再发首次奖励 |
| reward.daily-goal.once | daily-goal.achieved | 来源ID + 02.3本地日期 | 每日一次；同日改目标/重复达成不重复 |

这些是业务等价范围，不是已冻结的数据库幂等字符串。分值、等级阈值由11.1/11.3冻结，不在JSON里填虚构数值。P0重复学习/重复通过/重复观看不给额外积分；P1闯关与挑战加扣分另增事件版本/来源，不把它们提前作为可用奖励。

每日目标可统计exercise.passed、lesson.completed、case.view-confirmed三类去重学习事实，每类只按当天该稳定主体首次有效发生计一次，不计浏览/滚动/回退/重播/输出/每测试组。既有内容在另一日期再次完成有效学习，可计该日复习事实，但不重发终身首次内容奖励；必须有新的主动确认或真实通过事实，不能每天刷新自动复用旧事件。目标推荐/自定义组合、日期/时区/修改后的目标生效方式和本地事务由02.3/11.2承接，不能利用目标修改刷同日奖励。

进度确认、历史通过、奖励入账和每日计数是相关但不同的状态；统一事务/持久化成功、重试、多标签冲突与清除防复活均留02.3/04/11.1真实实现。首次事件的业务范围已定，存储实现不能以新的随机eventId绕开来源去重。

## 5. 可核对场景与后续责任

| 场景 | 必须结果 |
|---|---|
| 只确认小节，必修题未过 | 学习已确认，未完成，无小节完成奖励 |
| 题过但未确认小节 | 题目可有一次首次奖励，小节仍未完成 |
| 题目三组只过两组、EX-04只做一种循环 | 整题不通过，不发首次通过奖励 |
| 题目过后改错，再收到旧成功 | 当前解不标通过，历史保持，旧消息不发事件 |
| 成功案例直接跳尾或取消后用有效前缀 | 观看谓词不满足，不发观看确认/奖励 |
| 正常观看逐步覆盖+主动确认，再后退/重播/刷新 | 首次来源至多一次；刷新不能自行产生新学习事实 |
| 两标签同题通过、保存失败重试、同日改目标 | 02.3必须以来源范围幂等处理，不多发奖励；失败不显示已保存 |
| 旧文案版本显式兼容，或判定修订已变化 | 前者可复用历史进度；后者历史保留但新规则须重新满足，不自动重奖 |

02.2定义临时运行/判题/播放事实，02.3定义时间/存档/幂等/迁移；09.3/09.4/11.1/11.2实施事件消费，11.4验真实故障/多标签/重复行为。事件不放进Step DSL、不由Rust持久化、不在URL/网络/持久日志中传播。
