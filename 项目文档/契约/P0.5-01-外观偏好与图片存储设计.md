## 1. 版本、存储与职责

继续使用唯一数据库`c-viz-learning`和统一学习/存储入口，不新增外观DB、localStorage/sessionStorage镜像或第三方存储依赖。物理版本由1升2，语义版本由1.0.0升2.0.0；这是旧严格客户端不能安全写回的存档变更，不能伪装成1.0.0的任意附加字段。

| store | 物理键/结构 | 本次变化 |
| --- | --- | --- |
| meta | out-of-line单体键`"current"` | 字段集合保持；`dbVersion=2`、`schemaVersion="2.0.0"` |
| settings | 单体键`"current"` | 字段集合及枚举保持；新档/全清默认`theme="light"`，迁移不改旧值 |
| avatar | 单体键`"current"` | 字段/默认/现有形象和头像强调色不变 |
| progress、dailyFacts、goals、ledger、receipts、aliases | 原复合键和封闭行结构 | 所有原事实/身份/分值/目标/回执/别名保留 |
| appearance | 新增，out-of-line单体键`"current"` | 第2节的封闭外观行 |
| appearanceAssets | 新增，out-of-line复合键`[generation,"background"]` | 第3节的单张背景Blob行，最多1行 |

共11个store，无autoIncrement、无新增index。所有写事务包含meta；学习事务、外观事务和全清事务均以全部11个store为scope，继续在事务内重读合法世代/版本/当前行，写逐行delta。只读外观可读取meta/settings/appearance/appearanceAssets组成一致投影；正式学习快照须严格验证原九store的完整物理键、封闭字段与业务关系。新两store单独验证并区分`appearanceReadOnly`，不能把外观故障扩散为学习保存不可用；学习事务不修复或覆盖坏外观行。所有偏好均不进入Rust执行请求、日志、分析或广播。

`settings.theme`仍是唯一明暗设置，枚举`system | light | dark`；系统媒体查询结果仅在内存派生。`appearance.preset`决定设计风格；它不能另设`darkMode`或存第二份theme。`avatar.accentColor`仅控制学习形象，与平台自选主题色分开，选主题不重写头像。外观/布局改变不重跑Rust、不改变sourceRevision、不产生学习事件/奖励、不使已保存进度失效。

## 2. appearance封闭模型

以下JSON是完整默认行，不是额外嵌套在settings里的对象。所有字段必填、禁止未知字段；数值必须为有限安全整数，不接受数字字符串、NaN或浮点近似。公开设计资源表由P0.5-01设计规范固定，存档只保存其受控枚举。

```json
{
  "preset": "minimal",
  "accentColor": null,
  "blockWorkspace": "auto",
  "layout": {
    "sidebar": "expanded",
    "workbenchMode": "standard",
    "splitRatios": {
      "practice": 50,
      "visualize": 35,
      "review": 35
    }
  },
  "background": {
    "assetId": null,
    "visible": false,
    "fit": "cover",
    "position": "center",
    "overlayOpacity": 75
  }
}
```

| 字段 | 范围与确定含义 | 默认/行为 |
| --- | --- | --- |
| preset | `minimal | cute | cool | tech`，分别为简约、可爱、炫酷、科技 | `minimal`；四者均支持settings中的明暗/系统，不因选预设暗改theme |
| accentColor | `null`或规范大写`#RRGGBB`；写入口可将用户合法小写hex规范为大写，入库只收规范值 | `null`使用预设受控默认强调色；自选色不覆盖语义成功/危险颜色 |
| blockWorkspace | `auto | show | hide` | `auto`；根据当前课程/练习的明确推荐派生是否显示，未配置推荐时显示；show/hide为用户优先选择 |
| layout.sidebar | `expanded | collapsed` | `expanded`；正式尺寸216/60px由UI规范消费，数字不存档 |
| layout.workbenchMode | `standard | focus` | `standard`；focus隐藏非必要导航/说明以扩大工作区，退出后恢复同一已保存分栏比例 |
| layout.splitRatios.practice | 30..70整数，左侧编辑区域占可用双栏宽度百分比 | 50，即50:50 |
| layout.splitRatios.visualize | 30..70整数，左侧代码区域占比 | 35，即35:65 |
| layout.splitRatios.review | 30..70整数，左侧代码区域占比 | 35，即35:65；复盘比例独立，不借用算法页比例 |
| background.assetId | `null | "background"`，内部资源槽标识，不是原文件名、URL或用户内容哈希 | `null`；非null必须有本世代唯一合法asset行 |
| background.visible | boolean | false；assetId为null时必须false；已有图片可暂时隐藏而保留唯一Blob |
| background.fit | `cover | contain | tile` | `cover`；cover填满裁切、contain完整呈现、tile平铺 |
| background.position | `center | top | bottom` | `center`；横向居中，纵向按选择对齐；tile时为平铺起点 |
| background.overlayOpacity | 0..90整数，主题背景遮罩不透明百分比 | 75；遮罩色由实际明暗主题派生，不存第二份颜色 |

自选主题色的合法性不等于所有组合可直接用于文字。组件前景、焦点、状态和背景须由设计token按实际对比度选择，保留数字/文字/图形提示；不得为保持用户色值而放弃可读性。保存用户hex后，运行时派生可读配色，不把派生色反写为用户原选值。

sidebar/focus/三页分栏是全站外观偏好。窄屏下当前显示哪个区域、一次临时展开、帮助面板/逐块键盘编辑展开状态、拖拽中的分栏位置、Blockly缩放和平移、对象URL与媒体查询结果仅在会话内；不得塞进本行。逐块编辑与键盘连接面板每次进入工作区默认折叠，保留可发现的键盘入口。

`auto`不能根据用户积分猜基础水平，也不能直接授予后续语法权限；显示设置不等于积木解锁。课程推荐具体资源字段由内容设计契约定义，但其结果仅为`blocks | code`两种：blocks显示、code隐藏；用户show/hide优先。隐藏积木后必须仍有代码作答、运行和提交能力，由P0.5-08及原13.1/13.2真实验收，不在此冒称已实现。

## 3. 图片资源、预算与生命周期

### 3.1 唯一资源行

appearanceAssets唯一行字段为：`assetId:"background"`、`mimeType:"image/png" | "image/jpeg" | "image/webp"`、`byteLength`、`width`、`height`和`blob:Blob`。无其他字段，不保存原文件名/本地路径、File.lastModified、外部URL、data URL/Base64、HTML/SVG、用户内容摘要或缩略图副本。`blob.type`必须等于规范mimeType，`blob.size === byteLength`。规范MIME可通过以相同字节重新包装Blob设置，不改图片像素。

边界固定为：**单张、原始文件1..5,242,880字节（5MiB，含上限）、宽和高均1..4096像素（含上限）**；总持久图片负载最多5MiB，描述字段另占少量空间。只接受静态PNG、JPEG、WebP；SVG、GIF、AVIF、BMP及APNG/动画WebP均拒绝。多文件一次选择拒绝该次操作，不悄悄只取第一张。无远程URL入口、上传、网络探测、图片代理或自动下载。

文件后缀、浏览器File.type均不作为真实格式证明。导入先检查原始字节预算，再读取格式签名/完整容器及尺寸信息；PNG须排除acTL，WebP须排除ANIM/ANMF，并检查容器结构。先确认声明尺寸在预算内，再由浏览器完整解码成功，核对实际格式与解码尺寸；截断/畸形/尺寸不符/解码失败均不提交。JPEG的EXIF方向由解码显示方向应用，行中宽高为最终显示尺寸；横纵上限对旋转前后均成立。不能只凭成功创建Blob或文件名报导入成功。

有效图片不自动裁剪、压缩、上传或建立永久缩略图；cover等布局仅为显示处理。最多一份待保存图片草稿；不为四种主题各存一张背景。图片草稿及预览URL只在当前会话，替换草稿/取消/页面卸载/全清/世代变更时释放；解码后的临时ImageBitmap、canvas等验证资源用毕关闭，不缓存多个全分辨率副本。旧URL在新预览就绪后释放，避免空白闪烁；移除后不得继续持有旧资源URL。4096图的实际解码/纹理内存须在P0.5-03实测，不把5MiB文件预算等同内存预算，也不改既有Rust资源/性能门槛。

### 3.2 资源与偏好关系

assetId=null时appearanceAssets必须为空且visible=false。assetId="background"时必须恰好存在键`[当前generation,"background"]`，行内assetId一致；visible=false仍保留这张图。任何异世代行、孤立行、第二行、错键或缺引用都属于损坏，不自动挑一张或删除另一张。

导入/预览阶段不写DB。用户执行保存后，在同一11-store事务中检查expectedRevision/generation/版本、替换唯一Blob、更新appearance引用并meta.revision+1；事务完成前UI仅显示“预览，尚未保存”。替换的删除旧图/add或put新图/新appearance/meta必须一起提交，quota或任一步abort后旧图和旧偏好仍完整有效。移除同样原子删除Blob并设assetId=null、visible=false；保留本人的fit/position/overlayOpacity，后续导入沿用。仅隐藏把visible设false，不删除Blob。新图保存后visible=true。

P0.5-02必须识别完整2.0.0布局及图片行，即使导入UI尚未开放，也不得把合法图片视为未知字段并清空。P0.5-03不再单独增加DB版本；其权限只开启本节已经冻结的资源操作。Blob是浏览器IndexedDB原生结构化克隆值，不假扮JSON；后续新Schema需同时定义可JSON化元数据和原生Blob关系验证，不能拿JSON fixture占位串冒充已保存图片。

## 4. 保存命令、CAS与多标签

所有外观命令经统一service进入，页面不能直接put存储。封闭输入至少含操作类型、当前generation、`expectedRevision`、会话epoch，以及该操作所需的合法新值/已校验图片草稿；这些命令只在内存，不形成学习receipt或奖励。只允许下列操作：

| 操作 | 原子修改范围 |
| --- | --- |
| 保存主题/外观 | appearance单体；若该次同时修改明暗则settings.theme；其他settings字段逐字段保留；可附本次唯一图片替换 |
| 保存布局/积木偏好 | appearance相应字段+meta；完整行由事务内当前值构造，不携带整份学习快照 |
| 隐藏/显示背景 | appearance.background.visible+meta，资源不动 |
| 移除背景 | appearance对应引用/可见性、appearanceAssets删除和meta |
| 恢复布局默认 | 仅layout三种比例/sidebar/focus+meta |
| 恢复全部外观默认 | 默认appearance、settings.theme="light"、清空appearanceAssets和meta；保留settings其他字段、avatar及全部学习集合 |
| 既有settings局部恢复 | 仍按04.3确认影响；恢复该settings单体，含未来目标模板，明暗默认改为light；appearance/图片不变；已打开日快照不变 |

每个有效变更在同一事务内重读meta并严格比较generation/版本/expectedRevision，检查修订可加1后更新；安全整数耗尽只读，不回绕。新值与当前完整目标值完全相同时可作为no-op返回当前权威状态，不增加revision、不广播；no-op也必须先通过世代和CAS检查。请求成功不能显示已保存，只有transaction.complete后重新读DB核对仍为同世代/当前epoch才发布成功；清除后的迟到成功一律丢弃。

预览开始时捕获expectedRevision；期间别页学习保存或改头像也会推进同一meta.revision，外观保存返回`S_REVISION_CONFLICT`。保留本页内存草稿，明确显示冲突，读取最新已保存设置后由用户重新应用；不得自动last-writer-wins或悄悄用新revision重试覆盖。拖动分栏仅在拖动结束/键盘一次调整确认后提交，不在每个pointermove写DB；改色/遮罩滑动也先预览，确认保存时提交。普通学习事实继续沿既有合并/幂等规则，不强加偏好的CAS重试方式。

BroadcastChannel继续为`c-viz-learning.invalidate`，仅发送`{generation,revision}`；不发送预设、色值、布局、图片字节、资源描述或URL。消息仅触发重读，不充当锁/事实源。漏通知、后台挂起、重新focus/visible和每次写前仍核对meta；世代变化撤销全部图片/外观草稿与待提交命令。DB versionchange立即停止写并关闭连接，提示重新载入；升级blocked保留旧库，允许取消/关闭其他标签后重新打开，不强删。

保存/替换失败时保留原持久图与偏好；当前临时预览可继续查看但必须明确“未保存”，允许在当前世代重试或丢弃。quota不淘汰任何学习账本/回执/进度，也不自动删旧图来腾空间。storage.estimate仅可作提示，不能当作成功保证；不新增persist权限申请。

## 5. physical 1 → 2迁移recipe

只支持精确已发布前驱：physical1、semantic1.0.0、原九store/no-index/out-of-line布局及完整合法SAVE 1.0.0数据。合成legacy0.9.0、未知字符串语义版本、额外store/index或其他陌生布局均拒绝，不提供任意存档导入。

1. 在开升级事务前准备纯验证器、默认appearance和新档所需随机世代/时区；不得在versionchange事务里await图片解码、网络、crypto、定时器或用户确认。
2. `oldVersion===0`才按新档初始化11个store、physical2/semantic2.0.0 meta、默认appearance、无图；settings.theme=light，reducedMotion=system、playbackRate=1，avatar仍为既有正式默认。goalTemplate初始规则及首次goal.open前装载正式推荐配置沿11.2，不伪造当日目标/打卡。
3. `oldVersion===1`时，在同一原生升级事务严格读取/验证原九store所有物理键、封闭行和关系；创建两个新store并放默认appearance，无图片。旧坏行不在迁移时静默重置，任一失败主动abort。
4. **保留**generation、timeZone、createdAt、activePackageRef、全部settings原值（包括原theme、reducedMotion、playbackRate、goalTemplate）、avatar、六个集合的每个物理键和行值。仅meta.dbVersion变2、schemaVersion变2.0.0、revision从r变r+1；r已耗尽则拒绝迁移并保持旧库。
5. 升级事务完整校验新11-store布局/关系后提交。迁移不新建receipt、学习事实、积分、日事实/目标/小节完成，不改历史posted政策/分值，不从旧进度猜当前通过。当前包切换仍走独立内容规则，不捆在外观升级中。
6. complete之后重新读取确认版本/世代再对UI报告升级成功；任何创建store/读写/验证/配额/中断失败回滚到physical1原九store/原meta及全部原键值，不能留下“版本已变但新store缺失”。ACK丢失后重新打开：若已是合法2.0.0按已迁移读取，不再+1；若仍1.0.0重新执行同一recipe。

迁移前后旧九store比较按物理键与结构值（不依赖游标插入顺序）；meta仅允许上述3字段差异。旧settings.theme=system/dark/light分别原样保留，不能因默认简约浅色而把现有用户强制调亮。旧avatar.accentColor也不被外观颜色迁移吸收。migration无图，因此不存在升级事务内异步解码Blob的需要。

前驱损坏导致升级失败后，新版保留旧库并提供只读说明，不把失败当无档新建、不以默认外观冒称已恢复，也不由新版本临时写旧模型修复。用户可用匹配1.0.0的旧发布执行原04.3已冻结的明确修复/清除，或使用浏览器网站数据管理；修复后的合法旧库才能重试该recipe。该路径和新版对自身2.0.0的局部外观恢复必须在使用说明中区分。

## 6. 2.0.0损坏、全清与发布回滚

| 情形 | 已冻结处理 |
| --- | --- |
| appearance缺失/非法、资源孤立/缺失/错世代、图片元数据/Blob格式/解码非法 | 保留原行，设`appearanceReadOnly=true`，禁用背景；当前仅用标明“外观未恢复”的默认appearance投影，明暗仍读合法settings.theme；仅普通外观写暂停，已验证原九store的学习读写照常；允许明确重置全部外观 |
| 图片恢复解码尚未完成 | 先显示无图主题，标背景读取中；在事务外完成签名/尺寸/解码验证后再启用。不得为显示图片阻塞首屏或先报背景恢复成功 |
| settings/avatar及旧集合损坏 | 原04.3分类继续：局部确认重置、相关只读隔离/全局普通写暂停、账本不确定则总分不可确认；不因UI改版降低门槛 |
| meta坏/未来semantic/未来physical/未知布局 | 拒绝本版写与局部恢复；原版本已明确支持的已知损坏meta全清能力按第7节确认，未知布局绝不遍历清除 |
| Blob合法但当前浏览器解码资源不足 | 归类背景暂不可用，保留行；允许重试读取或明确移除，不删除学习事实，不冒称资源已丢失 |

新外观恢复操作的确认文案必须明确：**重置当前全部外观偏好并删除全部本地背景资源；保留课程进度、积分、每日目标和形象。** 用户确认的对象是两个新store的全部当前内容，包括其中损坏、孤立、异世代或额外资源行，不要求把坏Blob复制到日志或与任意opaque对象逐字节同步比较。恢复guard只在私有内存，绑定合法meta的generation/revision、精确2.0.0布局及当前sessionEpoch；恢复事务重核该屏障，清空appearance/appearanceAssets两个store全部行，再写默认appearance并将settings.theme设light，revision+1。若settings自身不合法，则该外观操作拒绝，先使用对应settings恢复，不顺便覆盖未来目标模板。原九store中仅meta与settings.theme按该操作改变，所有学习事实、目标、回执、别名、账本与头像的物理键和值保留；期间任何合法保存都会改revision并使guard冲突。该受控全外观重置是新store的明确recipe，不扩张旧任意opaque损坏记录的修复权，也不授权对未知DB/schema版本执行清除。

外观降级是独立能力标记，不将整个service状态伪装为已恢复，也不撤销已有真实通过/保存。学习写入继续推进meta.revision，因此外观草稿或恢复guard可因学习保存冲突；明确刷新、重新确认后再操作，不为减少冲突把两个revision源拆开，也不静默覆盖。外观读出合成默认投影永不回写原库。

资产内容验证发生在读取事务外，且结果绑定原generation/revision/epoch和资源槽。验证期间观察到revision变化必须丢弃旧结果并重读，不能将旧图晚到解码结果应用到替换/清除后的界面；不通过await维持IDB事务生命。格式与解码失败仅给稳定码/阶段，不持久化原图、异常正文或文件名。

全清沿04.3先同步推进sessionEpoch、失效旧草稿/待保存事实/运行检查身份并取消Worker，再在一个11-store事务清全部store、rotate generation、写physical2/semantic2.0.0新meta revision0及默认settings/avatar/appearance，无图片。旧命令不得自动建库或绑定新世代；清除事务失败则旧持久图和所有学习数据完整保留，但已失效运行不复活。成功仍须complete后新读核世代，其他标签漏通知也在写前/恢复时失效。已知physical2/11store布局中缺失或非opaque损坏meta可沿04.3私有原值guard确认全清；未知字符串schemaVersion、陌生布局或无法同步安全比较的opaque坏meta不提供本版全清，转匹配版本/浏览器网站数据管理。

发布回滚采用**前向兼容保护**：physical2不降回1，不改meta骗旧客户端，不复制出“缩水九store库”供旧版继续写。已升级的origin回退旧产品时，旧客户端的versionchange/version mismatch须保持拒写并提示需要新版；修复优先发布能读取2.0.0的前向修正版。未升级physical1的档案可继续旧版。若用户明确选择浏览器清网站数据，丢失范围按原说明告知；这不是自动回滚或数据恢复方案。
