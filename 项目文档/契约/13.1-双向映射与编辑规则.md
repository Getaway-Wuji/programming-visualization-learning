## 1. 固定范围与单一来源

- 仅现有P0-C V1.0与20类可见积木，不加入函数、递归、指针、字符串变量、`i++`、复合赋值或通用源码工作台；`input`是原声明积木的受控角色，不是第21类可拖入块。
- Rust唯一负责C词法、语法、名字/类型/作用域检查；前端消费有界checked AST并构造有限IR、生成C与渲染。前端不得另写C解析器或执行器。分析不执行、不产Step、不判通过、不发学习事件。
- 唯一权威是当前版本的编辑文档；`authoritativeDraft`指向当前代码原文或完整Blockly草稿。AST、IR、映射都是该版本的派生投影，不能各自成为可提交的第二份程序。代码起稿无需活动画布即可得到有真实AST证据的积木ID。
- 逻辑状态、AST节点、源码与映射只在会话内；不新增SAVE字段或持久编辑历史。13.3解锁、13.4快照、13.5拆积木仍未实施。显隐/两种作答入口由13.2能力和P0.5-08分别集成。
- 源码≤32768 UTF-8字节；语法与表达式AST深度各≤64；IR节点≤32768。分析请求≤65536字节、结果≤16777216字节、同1000000燃料/1000ms硬截止/128MiB和取消规则。字符数限制不能代替UTF-8字节检查。一次完整提交仍共享原1000ms预算；编辑分析不能替提交预支预算或延长提交截止。

## 2. 20类积木的双向规则

IR字段严格沿用`web/src/blocks/model.ts`；每节点都有唯一协议`id`，下表不重复列。`Expr`为7类表达式联合，`Stmt[]`保留语句顺序和作用域，所有额外字段拒绝。声明、引用及运算顺序不做代数化简、不重命名、不改变短路顺序。

| 可见kind / IR字段 | C → IR：真实checked AST | IR → C与拒绝边界 |
| --- | --- | --- |
| main / body | 唯一Function的body Block → body列表 | `int main(void) {…}`；一个main，控制体容器不多造scope块 |
| integer / value | Integer，规范非负十进制文本0…2147483647 | 负数由unary表达，`-2147483648`单字面量非法；最低值可写`(-2147483647 - 1)` |
| declare / name,initial | 标量Declaration，None→null、Scalar→Expr | `int name;`或`int name = Expr;`；null不等于0，不把未初始化自动补0 |
| variable / name | Name，resolvedDeclarationId必须指向可见标量声明 | 名称原样保留；名称规则见下文，不将数组名当标量读 |
| assign / name,value | Assignment的target为标量Name | `name = Expr;`，禁止把array target静默改写为变量赋值 |
| unary / operator,operand | Unary +、-、! | `(+ Expr)`、`(- Expr)`、`(! Expr)`，符号次序不折叠 |
| arithmetic / operator,left,right | Binary +、-、*、/、% | 按树加括号；除零/溢出仍是运行错误，不因分析成功承诺可正常执行 |
| compare / operator,left,right | Binary <、<=、>、>=、==、!= | 保留树/左右顺序；结果沿Rust int32的0/1语义 |
| logic / operator,left,right | Binary &&、\|\| | 保持左到右短路，不排序/提前计算右值 |
| if / condition,then,else | If的Condition.expression及两个Block列表 | `else:null`无else，`else:[]`显式空else；不互换，所有控制体必须有大括号 |
| while / condition,body | While+Condition.expression+body列表 | `while (Expr) {…}`；空body合法，是否终止由真实执行/预算决定 |
| for / init,condition,update,body | For；init为null/标量Declaration/标量Name Assignment，condition为null/Condition.expression，update为null/标量Name Assignment | 三槽可全null；init含分号而update不含；头部数组写虽Rust合法但unmapped，不能降为普通assign |
| break / 无 | Break且真实循环上下文合法 | `break;`；循环外invalid，不作为unmapped |
| continue / 无 | Continue且真实循环上下文合法 | `continue;`；保留for更新/while测试的真实控制语义 |
| array_declare / name,length,values | 正固定长度Declaration；None→null，Array→单一可选符号和字面量列表 | length为规范正十进制，values可短于length但不可空列表/超量；缺省零由Rust补，不扩写用户列表；`null`保留未初始化 |
| array_read / name,index | Index的array为已解析数组Name | `name[Expr]`；数组名辅助AST不是额外变量积木 |
| array_write / name,index,value | Assignment的target为Index(array Name,index) | `name[Expr] = Expr;`；下标表达式与值表达式顺序不交换 |
| print / format,args | Output，format为已解码语义文本，arguments按原顺序 | 只%d/%%；参数数量相符；转义反斜杠、双引号、LF；无任意原始C插槽 |
| return / value | 显式Return的value | `return Expr;`；保留显式用户return，即使值为0或不可达 |
| scope / body | 独立Block语句；排除main/控制体容器 | `{…}`保留声明寿命/遮蔽；空scope不删除 |

名字沿现IR：`[A-Za-z][A-Za-z0-9_]*`且非保留词；Rust合法的`_x`/`_`不能映射，标unmapped并保留原名。同一作用域重声明、未定义引用、标量/数组误用是invalid；可见普通局部遮蔽由Rust决定，不泛禁同名。数组values规范成有符号十进制文本（去多余+与负零），绝对值≤2147483647；数组字面初值不能直接装最低int32，亦不能用表达式冒充单一字面量。普通数组长度受真实分配预算约束，不套课程输入n≤30。

print允许Unicode可打印文本和LF，拒绝其他C0控制符及DEL；Rust合法的原始tab因此unmapped，`\t`这个不支持的C转义则invalid。保留UTF-8/CRLF/中文/补充字符，不把JS UTF-16下标当字节坐标。

## 3. AST-MAP-01封闭投影与映射

请求为`analysisRequest`：精确analysisVersion、contextId/contextRevision/documentRevision/editId/operationId、静态精确packageRef/programRef/subsetRef、当前完整sourceText和InputInstance。上下文Ref在13.2生产端必须与已验证静态注册匹配，不接受调用方自定新语法/答案/预算。输入形状复用现EXEC InputInstance，不能从分析请求生成学习授权。

结果为`analysisResult`：原身份完整回显。`valid`提供checkedAst、bindingMap、nodeMap、候选blockMap和trivia；`invalid`只提供有界诊断，不携带部分成功AST/旧映射。模块/传输/取消/超限为独立`analysisFailure`，不伪称C非法。未知版本/未知字段/不闭合引用/越界或非UTF-8边界的结果拒收；保留当前草稿，置analysisError，禁止运行。

checkedAst使用扁平先序nodes，每项有nodeId、parentId、byteRange及封闭payload；18个kind为function/block/declaration/assignment/if/while/for/condition/output/return/break/continue/empty/integer/name/index/unary/binary。声明initializer区分none/scalar/array；name额外带resolvedDeclarationId；arrayLength与integer使用规范十进制string。所有子引用唯一有父、无环、由root可达，parent和有序槽一致；每个范围非空、父包含子且在当前源码内。nodeMap逐项投影为STEP原kind（表达式各类统一expression），不能冒充完整AST。headerRange独立，不伪造header块；无隐式return的源码不伪造AST节点。

Condition、main/控制体Block、赋值target Name/Index、数组initializer节点等都是辅助节点，不要求各有可见积木；`blockMap`只映射真实IR节点的主AST范围，一块可包含辅助节点。新映射取**精确AST范围**，包括parser为分组扩大后的表达式范围；不得包含外围注释。for init范围含分号，update范围不含。输入块指向精确Declaration，print指向Output，scope指向独立Block。协议ID沿EXEC `[A-Za-z0-9][A-Za-z0-9._:-]{0,95}`，原生非法ID继续沿既有UTF-8十六进制转换，碰撞/超长拒绝，不悄悄截断。

每个if/while/for有唯一blockId和siteKey；siteKey继续由现JUDGE使用blockId形成，EXEC封套不新增siteKey字段。Rust无编辑会话状态，响应候选blockMap只用当前AST生成`block.analysis.<先序号>`和真实范围，不承诺跨稿稳定。浏览器消费者依真实AST构建IR，再为代码起稿分配`block.code.<会话单调号>`或恢复当前可信积木事务的原ID；仅在已记录编辑区间变换/补丁能证明字节片段未变、节点kind/父槽/声明绑定均相同时保留未改ID，不能证明则分配新号，不按文本猜C结构。代码选择而无编辑不重新分配。`n1/n2`为当前源码先序节点号，不跨sourceRevision复用。一次提交冻结IR和blockId集合，各组替换输入后重新Rust解析/语义/精确映射，控制节点按同一IR有序槽对应；任何缺失/歧义/结构变化拒绝整提交，不能按旧偏移猜测。

说明现状：旧judge可接受控制范围外仅空白的单个包围项；13.2新生产者统一提供精确范围，是更严的生成要求，不修改EXEC/JUDGE旧接受语义。空blockMap、父main代控制、重复或歧义候选不能满足原控制教学目标。合法但unmapped的分析结果可有空候选map，消费者必须诊断未映射，不能据此提交。

## 4. 格式、注释、规范输出与合成来源

1. **语义等价不是文本一致。** 这里指按本契约归一后的IR结构等价，保持声明绑定、求值/短路顺序、作用域、输入绑定、输出和终止行为；允许数组signed literal去+或负零、可核验合成尾return及header/main形式的规定差异。不承诺通用C等价证明，也不承诺AST/Step数量或燃料完全相同；因此仍必须新建sourceRevision、重验映射，不能沿用旧轨迹或重发奖励。规范输出可改变缩进、括号、十进制拼写与header/main写法，不承诺原文一致。相同测试输出也不能单独证明结构等价。
2. 代码编辑或只切换显示时保留sourceText每个字节，包括注释、空白、换行、`main()`与可选教学header；反推积木不得立即用规范C覆盖原文。Rust lexer丢弃trivia，现checked AST并无注释；13.2必须由Rust产生有界`trivia`旁表（line-comment/block-comment/whitespace的原字节范围），前端仅复制片段，不自行解析C。
3. 从代码投影的积木做逻辑编辑：替换最小完整受影响语句/独立作用域（for任一头槽替换整个for）。新插入语句沿原文件主换行风格（首个换行，缺失时LF）、4空格缩进。未受影响原字节不变；替换后的整个源码必须重新分析，旧位置全作废。若不能构造无歧义非交叉补丁或新语法深度超预算，拒绝该块编辑并保留两侧草稿，提示改代码，不静默全篇重排。
4. 替换范围内的原注释按原序移至该范围新语句之前独立行；`//`后必须补同风格换行。删除语句时注释留在原父块对应位置；跨父块移动时与被移动语句一起带走。边界外（包括同行尾注释）原样保留。这样保留注释文字和次序，但明确不保证精确附着位置或可执行教学指令含义。注释不是语义判据。每次迁移应显示“本次积木编辑调整了注释位置”，便于用户检查；不丢弃注释。
5. 纯积木起稿继续规范生成：可选stdio教学header、main(void)、4空格、LF、表达式括号、输入声明原字节及既有转义。即使已有显式return，现生成器也会追加默认`return 0;`；新provenance记录`synthetic-tail-return`的精确范围与nodeId以及所属documentRevision，只供同一来源逆推剔除这一个合成节点。代码原有显式return始终是用户块；从外部粘贴/失去provenance后不得按文本猜删。原样保留合成段的字节补丁可以平移来源范围，重新分析验证；直接代码编辑覆盖该段则取消合成标记，把它作为用户return。不得每次往返新增尾句。
6. 代码来源使用局部补丁，不额外追加默认尾return；原有显式return或Rust main的隐式0正常保留。全新积木来源才使用规范生成。后续若用户主动选择整篇格式化，应独立声明为逻辑代码编辑并按字节使旧运行失效，本阶段不新增格式化按钮。

provenance只包含有界trivia与synthetic片段的类型/range/nodeId，原文本保留在sourceText，不能把任意C文本当可执行插槽。`generationMode`为canonical（纯积木规范生成）或preserve（代码原文/局部补丁），直接代码编辑后进入preserve。注释长度已计源码上限；旁表条数≤32768且总结果预算仍生效。Rust分析只返回真实trivia，不推断合成来源；会话消费者仅从自己捕获的可信生成/补丁事务恢复syntheticSegments，再与本次真实AST核对范围/节点/尾部return值。原始代码请求没有这种证明时列表必为空，不允许调用方自证“这一用户return是合成的”。

## 5. 输入绑定与跨测试实例化

输入声明是main前bindings.length个语句，按原静态Program声明顺序；bindingKey、名称、标量/数组/逻辑长度角色、数组物理容量、字面初值与当前InputInstance一一匹配。每个bindingMap精确指向当前Declaration，不能按同名变量猜测。允许声明内部格式/注释变化，但删除/改名/重复/重排/改类型/改容量/改初值均invalid并保留原文。改绑采用可机械核验的规则：每个拼写等于受控targetName的Name AST节点（含赋值目标和数组名）必须解析到对应输入声明；解析到局部同名声明即invalid。未被读写/引用的普通同名局部声明仍可保留，因为声明名token本身不是Name表达式。不依赖“用户原本想引用谁”的猜测；无受控名的普通局部遮蔽沿Rust原语义。改绑保护为13.2的新增分析责任，不冒称现input.rs已全面实现。

普通scalar/array绑定可以被程序后续赋值；loop-count的n和派生logical-length不得赋值，包括不可达路径。不要把受控前缀的编辑保护误作所有输入运行时只读。空sequence仍物理`[1]={0}`，logical-length为0；输入域仍沿原内容规则与n≤30。

`prepareForTest`冻结documentRevision、结构ID和当前原文，仅用真实Rust校验后的声明槽替换该组输入值/容量，不能把参考解全文替代用户代码。每次重新parse/semantic/binding/map，产生新的PreparedSource `{text,blockMap,bindingMap}`和sourceRevision，显示/执行必须相同。首组到末组输入导致的长度变化不能沿用字节坐标或n序号。构建期prepare模板仅用于已登记静态源码的既有优化；任意代码稿没有该豁免。

## 6. EDIT-SYNC-01状态与版本去重

EditDocument的封闭字段见Schema。blockDraft使用会话内`workspaceSnapshotId`指向完整Blockly13.4.0序列化草稿（含未连接块/字段/原生ID），并有nullable program；句柄不进Worker、不持久化、不接受跨context引用。Schema不扩展Blockly私有对象；13.2在捕获时验证固定版本格式，snapshot≤1048576 UTF-8字节、块≤32768、逻辑连接深度≤64；超限拒绝该次编辑并恢复编辑前完整草稿、给容量提示，不截断或丢弃脱离块。这是编辑内存保护，不提升源/执行/SAVE预算。缺槽、脱离块、多main在限额内保留完整snapshot并invalid。`program`只能是该snapshot的当前完整结构，最后有效结构仅放lastSynced。会话内嵌套IR不经过旧JSON-INT消息的深度32限制；Worker只收源码/扁平AST，不借编码深度悄悄缩减C/IR深度64。

| 字段 | 固定责任 |
| --- | --- |
| contextId/contextRevision | 复用现EXEC会话；contextRevision失效旧操作。PracticeSession原revision仍对应它，不再创造另一执行上下文 |
| documentRevision | 会话内从1单调增的逻辑文档版本；代码字节/块逻辑/实际输入/静态执行上下文或答题模式切换各增一次 |
| editId / origin | 一次用户逻辑事务唯一ID；origin为code/blocks/input。同事务的分析/IR/画布回写沿用editId，不二次增加revision |
| operationId | 每次分析/重试/取消屏障独立ID；同文档重复分析也不能接收旧请求结果 |
| sourceRevision | 每组最终完整源码的EXEC版本，沿当前context单调递增；文档revision不能替代它。仅新contextId可重置 |
| validatedDocumentRevision | 当前成功完成分析并验证的revision；pending/analysisError时不代表当前可提交 |
| codeDraft / blockDraft / authoritativeDraft | 原文、完整草稿句柄与唯一权威来源；投影不得覆盖另一份当前非法内容 |
| input / inputBindings / diagnostics / issues | input是唯一当前InputInstance，分析/测试从文档冻结它；静态绑定描述规范为显式emptyStorage:null或占位枚举。diagnostics沿原DIAG呈现语法/语义诊断，issues为封闭映射/绑定问题，均归当前validated版本 |
| lastSynced | nullable，只是历史代码/IR/映射/provenance及所属revision；禁止自动回退运行它 |

| 状态 | 判据与运行资格 |
| --- | --- |
| synced | Rust静态、输入绑定和全部映射校验完成；validatedRevision=current、非pending、无analysisError才可运行/提交 |
| invalid | 当前代码语法/语义/绑定错误或块不完整；保留原文/草稿、显示当前诊断、不能运行/提交 |
| unmapped | Rust合法但超出上述IR范围，例如空语句、for头数组写、下划线开头名、print原始tab；保留原文并定位未映射节点，不部分转换或提交 |
| analysisPending / analysisError | 与三种syncStatus正交：等待或模块/传输/取消/预算/无效响应错误；最后status仅为历史分析。失败不可伪装invalid/synced，禁止运行/提交；重试保留相同稿和新operationId |
